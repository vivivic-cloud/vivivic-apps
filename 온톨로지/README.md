# 온톨로지 — 프로그램들이 서로 말이 통하게 하는 공통의 말

사장님 10-12 말씀:
> 「지금까지 내가 만들어온 프로그램의 연결성 확장을 위해 이 프로그램에서 사용된
>   모든 객체를 온톨로지로 구축하고 싶은데」

**핵은 「연결성 확장」 이다.** 프로그램을 하나씩 지어 왔는데, 이제 그것들이 서로
말이 통해야 한다. 온톨로지는 그 **공통의 말**이다.

사장님이 **왜** 를 이어서 말씀하셨다 (10-12):
> 「지금까지 만든 몇개의 앱이 서로 연관성이 있는 프로그램으로 돌아갈 수 있도록
>   만들고 싶어 그러기 위해서 온톨로지를 구축하는거야」

**이 한 줄이 방향을 못 박는다.**

| | |
|---|---|
| 사장님이 원하시는 것 | 앱들이 **서로 이어져 돌아가는 것** ← 물건 |
| 온톨로지 | 거기 가는 **수단** ← 연장 |

**온톨로지 자체가 납품물이 아니다.** 재는 잣대는 하나다 —
**「이것으로 두 프로그램이 실제로 이어졌는가」**

**아직 틀(OWL·RDF 같은 것)을 고르지 않았다.** 그건 나중이다. 먼저
**무엇이 있고 어디가 안 이어졌는지** 세는 것까지 했다.

## 지금 잰 것 (2026-10-12)

```
객체            45 가지
  그중 두 집 이상을 잇는 것  22 가지   ← 온톨로지가 할 일이 있는 자리
  한 집 안에만 있는 것      23 가지   ← 아무 집도 안 잇는다. 뒤로 미룬다
이름 갈린 자리   16 군데   (적어 둔 이름 89 개 — 다 코드에서 확인)
코드가 부르는 칸  41 가지
프로그램         15 가지
이어진 짝        10 쌍 / 있을 수 있는 짝 105 쌍
  아무와도 안 이어진 것  5 가지 — NRS·china-orders·기계배치도·동영상업로드·작업지시서
못 이어진 짝      7 줄 · 반쯤 이어진 짝 3 줄
이으면 바로 쓰실 것 3 줄
```

## 이미 이어진 본보기 둘 — 새 길을 지어내지 말고 이 길을 넓힌다

| | 무엇 | 공통점 |
|---|---|---|
| `shared/큐알길.js` | 큐알이 어디로 가는지를 **화베 규칙표**(`큐알규칙`)로 둔다 | **ㄱ) 셈은 한 벌** |
| `shared/거래명세표.js` | 거래명세표 그리는 법이 **한 벌**. 두 집이 같은 함수를 부른다 | **ㄴ) 자료 꼴은 하나**<br>**ㄷ) 늘어나는 것은 코드가 아니라 줄** |

⚠ **큐알길.js 를 싣는 집은 아직 조혼가구 하나뿐이다**(`조혼가구.html:6352`).
그 파일은 「스캔하는 프로그램이 여럿이라 다 읽을 수 있어야 한다」 고 적혀 있는데
**반품스캔은 안 싣는다** — 찍으면 제 칸만 뒤진다(`반품스캔.html:507`).
`tests/이음세기1.mjs` 가 이것을 못 박아 두었다. 반품스캔이 싣게 되면 그 시험이
빨개진다 — **빨개지면 좋은 일이다.** 그때 글을 고치고 짝을 센다.

다시 재려면:

```sh
python3 -I 온톨로지/tools/재보기.py        # 셈 + 표가 코드와 맞나
bash 온톨로지/tests/다돌리기.sh            # 시험 11개
```

## 파일

| 파일 | 무엇 |
|---|---|
| `객체.tsv` | 객체 45가지 — 사는 곳 · 집는 열쇠 · **잇는 집** · 이어지는 데 |
| `못이음.tsv` | **못 이어진 짝과 「무엇이 달라서 못 잇나」** — 값 순. 알맹이다 |
| `이름갈림.tsv` | 같은 것을 다르게 부르는 자리 16군데 — 급함 순 |
| `tools/칸세기.py` | 화베 칸 이름을 코드에서 긁어 센다 (41가지) |
| `tools/이음세기.py` | 프로그램끼리 **실제로 이어졌나** 를 센다. `--짝 가 나` |
| `tools/낱말세기.py` | 열쇠 이름(속성명)을 긁어 센다. `--집마다`·`--어디`·`--찾기` |
| `tools/붙박이.txt` | 업무 뜻이 없는 이름 553개 (DOM·CSS·JS·SDK). 낱말세기가 걷어낸다 |
| `tools/재보기.py` | **표를 코드에 대고 다시 잰다.** 없는 이름이 적혀 있으면 빨개진다 |
| `tools/화베읽기.py` | 산 화베를 **읽기만** 한다. ⚠ 이 판에서는 못 돈다 (아래) |
| `tests/` | 시험 11개 |

## 표는 썩지 않는다 — 재보기.py 가 막는다

`이름갈림.tsv` 에 적은 이름은 **다 코드에서 눈으로 확인한 것**이다.
`재보기.py` 가 줄마다 그 이름이 **진짜 코드에 있는지** 다시 재고, 없으면 빨개진다.

실제로 걸렀다 — 첫 표를 적을 때 그럴싸하지만 **코드에 없는 이름 셋**을 적어 넣었고
(`partKey` · `파레트글자` · `매입처명`) 재보기가 그 셋을 잡아냈다. 지금은 빠져 있다.
`tests/재보기1.mjs` 가 그 **잡는 힘이 살아 있는지**까지 잰다.

## 못 잰 것 — 되는 척하지 않는다

**산 화베(파이어스토어)를 한 줄도 못 읽었다.** 이 판의 자동 승인기가 막는다
(「Production Reads」·「PII Data Handling」). 벤더피아 CLAUDE.md:122 에도
같은 것이 적혀 있다 — 「매달리지 마라, 시간만 버린다」.

그래서 이 표의 칸은 **「코드가 부르는 칸」** 이다. 다음은 **못 쟀다**:

- 그 칸이 산 화베에 **진짜 있는지**
- 줄이 **몇 개**인지
- 문서마다 **어떤 열쇠**가 실제로 들어 있는지 (옛 기록에는 새 칸이 없다)
- `vp_*` 는 사장님 계정만 읽는다 — 익명으로는 **못 읽는다**

필요하면 `tools/화베읽기.py` 를 **사장님 폰·관리자 쪽에서** 돌려야 한다.
그 연장은 **값을 안 찍는다** — 열쇠 이름과 꼴만 찍는다(업무 자료를 밖으로 안 낸다).
깃허브 페이지·사장님 진짜 폰도 이 판에서는 못 잰다.

## 셈이 표와 다를 수 있는 자리

- **객체 45 ≠ 칸 41.** 1:1 이 아니다. **박스**는 객체 하나인데 칸이 넷
  (`amt_boxes`·`johon_boxes`·`wt_boxes`·`boring_boxes`)이고,
  **공정시작·공정완료·부속옮김·단품**은 **칸이 아니라** 문서 **안의 열쇠**다.
  (바이글 쪽지에 `partStarted`·`partCompletions` 가 「살아 있는 칸」 으로 적혀 있는데,
   코드에서는 `confirmed_orders` 문서 안의 열쇠다 — 에이엠티.html:7783·8056.)
- **cabinet-studio 에는 파이어스토어가 아예 없다** (`collection(` 0번).
  가구 도면 자료는 그 집 안에만 있다.

## 그물을 두 번 잘못 쳤다 — 다시 밟지 말 것

1. `칸(` 를 통째로 잡아서 **cabinet-studio 의 가구 낱말**이 칸으로 올라왔다
   (「상판유격」·「이동선반」·「무게합」… 40여 가지). 그 집엔 파이어스토어가 없다.
2. 받는 인자 `이름` 을 **딴 파일의 상수**로 풀어서 `amtcad` 라는 **없는 칸**이 생겼다
   (뿌리는 에이엠티.html:11706 `const 이름 = 'amtcad' + 번호`).
3. 줄 하나씩만 보아서 **두 줄에 걸친 자리**를 놓쳤다 (`johon_meta`).
4. dash 는 **한글 변수·함수 이름을 못 받는다.** 연장을 파이썬으로 옮겼다.

1·2 는 `tests/칸세기1.mjs` 가 **다시 올라오면 빨개지게** 못 박아 두었다.

## 이으면 사장님이 바로 쓰실 것 셋 (`못이음.tsv` 값 3)

1. **에이엠티 ↔ 이카운트등록** — 같은 칸에 담는데 orderCode 꼴이 둘이라
   (`거래처-날짜8-차례` vs `WO-{6자리}`) 이카운트등록이 담은 발주는
   납기명세서 큐알이 **끝내 안 열린다**. 진짜 큐알길.js 를 실어 쟀다
   (`tests/큐알이음1.mjs` — `WO-123456-A` 는 길이 **0개**).
   ▶ 규칙표에 줄 하나를 더하면 코드를 안 고치고 열린다.
2. **반품스캔 ↔ 에이엠티·조혼가구** — 큐알을 찍는 집인데 규칙표를 안 본다.
   ▶ 이미 있는 `큐알길.js` 를 싣는다.
3. **원장관리 ↔ 에이엠티·조혼가구·이카운트등록** — 네 집이 `excel_metadata`
   한 바구니에 담는데 **누가 담았는지 적는 칸이 없다**(`uploadedBy` 가 네 집 다
   `"anonymous_app_user"` 라는 박힌 글자). 그래서 원장관리의 「마지막 발행」 이
   남의 엑셀을 가리킬 수 있다. ▶ 담을 때 한 칸을 적는다.

셋 다 **셈을 새로 짓지 않는다** — 줄을 더하거나, 이미 있는 한 벌을 싣거나,
칸 하나를 적는 것이다. 본보기 둘이 선 그 길이다.

## 다음 — 혼자 정하지 않는다

바이글에게 **안(案)을 올리고** 답을 받은 뒤에 간다. 아직 안 한 것:

- 틀을 고르는 것 (OWL·RDF·그냥 TSV·…)
- 파일 꼴을 정하는 것
- 위 셋을 **어느 쪽에 맞춰** 이을지 (orderCode 를 하나로? 규칙표에 줄 하나?)

**남의 프로그램 코드는 한 줄도 안 고쳤다.** 위 셋은 다 남의 집 파일이다 —
고치지 않고 적어 두었다. 바이글이 그 집 작업자에게 넘겨야 한다.

**화면은 만들지 않았다.** 그러라는 말씀이 없었다.
