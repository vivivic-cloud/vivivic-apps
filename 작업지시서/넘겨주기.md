## 0. 먼저 — 합치면 깨질 것 (위험한 순서)

### ① 저장 자리가 브라우저 안(localStorage)이다. 사장님이 만든 지시서가 전부 거기 있다
- 칸 이름은 `vv.workorder.` 로 시작한다(아래 2장). **이 이름을 바꾸면 그 순간
  지금까지 만든 지시서가 화면에서 사라진다.** 파일이 지워지는 건 아니지만
  사장님에게는 사라진 것과 같다. 옮길 때 이름을 그대로 들고 가라.
- 다행인 것: `vivivic-apps` 와 `vivivic-docs` 는 주소가 같은 집
  (`vivivic-cloud.github.io`)이라 **localStorage 는 두 앱이 이미 한 통을 쓴다.**
  주소가 `/vivivic-docs/...` 로 바뀌어도 칸 이름만 그대로면 지시서는 그대로 열린다.
- 위험한 것도 같은 이유다: **5MB 한 통을 서류관리와 함께 쓴다.** 지금도 사진을
  몇 장 넣으면 찬다(저장 멈춤 띠가 뜬다). 서류관리가 쓰는 양이 늘면 작업지시서가
  먼저 죽는다. 합치기 전에 사진을 IndexedDB 나 드라이브로 옮기는 것을 정해 두는
  편이 낫다. 지금 앱은 IndexedDB 를 안 쓴다.

### ② 클래스 이름과 인쇄 CSS 가 남의 화면까지 건드린다
- 작업지시서는 한 파일 안에 제 CSS 를 다 담고 있고, 이름이 짧다 —
  `.top .b .card .sheet .it .tools .hint .warn .zone .grip .tray .card`.
  서류관리 `index.html` 에도 **`.card` 가 있다**(`#fff`, 반지름 16px). 그대로
  한 화면에 합치면 서로 덮어쓴다. 작업지시서 쪽은 `.wo-` 같은 앞가지를 붙여
  가두는 것이 가장 안전하다.
- 인쇄 CSS 는 더 세다. `@media print` 안에서 `.top,.tools,.hint,...{display:none}`
  을 하고, 자바스크립트가 `<style>` 을 새로 만들어 `@page{size:A4;margin:0}` 을
  박는다(1620줄 근처 `인쇄스타일`·`적용된인쇄방향()`). **서류관리에는 지금
  `@media print` 도 `@page` 도 없다.** 합치면 서류관리 화면을 인쇄할 때도 이
  규칙이 걸린다. 인쇄가 필요한 쪽만 켜지게 감싸라.
- 서류관리는 Tailwind 를 빌드해 쓴다(`css/app.css`). Tailwind 의 기본 되돌림
  (preflight)이 작업지시서의 단추·글꼴을 함께 건드릴 수 있다. 붙여 보고 눈으로 봐야 한다.

### ③ 만드는 방식이 아주 다르다 — 한 파일 전역 스크립트 대 ESM 모듈 + 번들
- 작업지시서는 94KB 한 파일, 평범한 `<script>` 하나에 전역 이름이 한글로 잔뜩
  있다(`문서 그리기 고른것 배율 저장 끌기 만들기 …`). 서류관리는 `type="module"`
  ESM 여러 벌 + `build-single.py` 로 `docs/index.html` 을 만든다.
  **모듈 안으로 그냥 넣으면 전역이 아니게 되어 서로 못 찾고, 전역으로 두면
  이름이 부딪힐 자리가 많다.**
- 가장 덜 위험한 길: **합치되 섞지 않는다.** 서류관리 안의 한 자리(탭·라우트)에서
  작업지시서를 `<iframe>` 이나 별도 쪽(`/작업지시서/`)으로 띄우고, 오가는 것만
  약속한다. 한 화면에 코드까지 녹이는 것은 그다음 일이다. (내 생각이다. 정하는
  것은 서류관리 쪽이다.)
- 빌드에 관해 내가 모르는 것: `build-single.py` 가 남의 `<script src>`(CDN)나
  긴 인라인 CSS 를 어떻게 다루는지 안 읽어 봤다. **모른다.**

### 그 밖에 잃을 수 있는 것
- 바깥 파일 두 개를 상대 경로로 부른다: `../shared/svg.min.js`, `../shared/viggle.js`.
  서류관리 쪽으로 옮기면 그 경로가 깨진다. 서류관리는 이미 손잡이를
  `/vivivic-apps/shared/viggle.js` 로 절대 경로로 부르고 있으니 같은 식으로
  `/vivivic-apps/shared/svg.min.js` 로 바꾸면 된다. **대신 `vivivic-apps` 저장소를
  나중에 지우면 둘 다 죽는다.** 지우려면 `shared/` 를 먼저 옮겨야 한다.
- pdf.js 는 cdnjs 에서 받는다(본체와 worker 둘 다, 7줄·949줄). 막히면 PDF 불러오기가
  조용히 죽고 "이 PDF 를 읽지 못했습니다" 만 뜬다.

## 1. 이 프로그램이 무엇을 하는가 — 누르는 차례대로

A4 흰 종이에 사진·PDF 를 올려 놓고 손으로 배치해서, 인쇄하거나 PDF 로 내보내는
것이다. 서버가 없다. 자료는 이 기계 안에만 있다.

**머리(위)**
1. `작업지시서` 글자 — 이름표다.
2. **지시서 이름** 칸(`#docname`) — 이름을 바꾸면 그 이름으로 새로 저장되고,
   옛 이름 자리는 지운다(`onchange`, 1700줄 근처). 한 글자 칠 때마다 저장하지 않는다.
3. **인쇄 · PDF**(`#print`) — 이것이 이 앱의 결과물이다. 3장과 5장을 보라.
4. 둘째 줄에 **파일**(PDF) · **사진** 둘만 있다. 다른 기능 단추는 09-15 지시로 뺐다
   (글상자·구분선·방향 고르기는 만들 수 없다. 이미 저장된 문서의 것은 그대로 보인다).

**왼쪽 쪽 목록(`.tray`, 92px)**
5. 불러온 PDF 쪽·사진이 여기 쌓인다. 캔버스에 자동으로 안 올린다.
6. 목록에서 **톡** 누르면 골라지고(여럿 고를 수 있다), **끌어다** 원하는 종이에 놓는다.
   놓아도 목록에 남는다 — 같은 사진을 여러 장에 쓸 수 있다.
7. 쌓인 것이 있으면 저절로 펼쳐지고, 비면 접힌다. 여닫는 단추는 없다.

**무대(가운데) — A4 장들**
8. 종이를 톡 누르면 그 장이 '지금 장' 이 된다. 빈 자리를 누르면 고름이 풀린다.
9. 자료를 톡 눌러 고르고, 끌어 옮긴다. 다른 장으로 끌면 그 장으로 넘어간다.
10. 오른쪽 아래 **손잡이**로 크기를 바꾼다. 옆 자료의 가로·세로에 한 번씩 걸리고,
    걸릴 때 어느 줄끼리 맞는지 줄 둘을 긋는다.
11. 왼쪽 위 **×** 로 지운다(여럿 고르면 다 지운다).
12. 장마다 아래에 **정렬**(그 장의 것들을 여백 10mm 로 줄 맞춰 다시 앉힌다)과
    **삭제 ×**(그 장을 없앤다)가 있다.

**아래 연장 줄(`.tools`, 한 줄, 옆으로 밀린다)**
13. 축소 / 확대 — 화면 배율만 바꾼다. 종이 크기는 안 바뀐다.
14. 맨 앞으로 / 맨 뒤로 / 폭 맞춤 / ◀▲▼▶(미세이동) / `1mm`(걸음: 1→5→10mm)
15. **여러 개** — 켜면 톡 칠 때마다 고른 것에 더해진다(폰에는 Ctrl 이 없다).
16. **자르기** — 사진 위에 판을 덮고 손가락으로 네모를 그린다. 그러면 띠가 바뀌고
    `이 부분만 / 복사 / 복제 / 잘라내기 / 삭제 / 그만` 이 뜬다.
17. **표시 도구** — 자료 위에 화살표·네모·동그라미·자유선을 그린다(색 3, 굵기 3).
18. 크게 / 작게(10%씩) · 자르기 되돌리기 · 모두 지우기.

**손잡이(`?viggle=1`)** — 사장님이 화면을 **길게 눌러** 그 자리에 지시를 적는 길.
앱 코드가 아니라 `shared/viggle.js` 가 한다. 4장을 보라.

## 2. 어떤 자료를 읽고 쓰는가

### 쓰는 것 — localStorage 뿐이다 (앞가지 `vv.workorder.`)

| 칸 | 무엇 | 언제 쓴다 |
|---|---|---|
| `vv.workorder.문서.<이름>` | 문서 한 벌 통째로(JSON) | 저장() — 600ms 미룬 뒤 한 번 |
| `vv.workorder.지금이름` | 마지막으로 열었던 이름 | 저장() 마다 |
| `vv.workorder.목록` | `{이름: {잰때}}` 목록 | 저장() 마다 |
| `vv.workorder.지금` | **옛 방식.** 시작할 때 읽어 보고 지운다 | 지우기만 한다 |

문서 모양:

```js
문서 = { 이름, 방향: 'p'|'l', 잰때, 쪽함: [{id, src, 이름, 비}],
         장들: [ [자료…], [자료…] ] }        // 장들[n] = n+1 번째 A4
자료 = { id, 종류: 'img'|'text'|'line', x, y, w, h,   // 전부 mm 다. px 아니다
         z,                                  // 앞뒤 차례
         쪽 | src,                           // 쪽함을 가리키거나 제 안에 담는다
         잘라: {x,y,w,h},                    // 자른 조각 — 원본 그림에 대한 비 0~1
         구멍: [{x,y,w,h}],                  // 지운 자리 — 같은 0~1 비
         그림들: [{종류,색,굵기,점들:[{x,y}]}], // 얹은 도형 — 자료 상자에 대한 비 0~1
         글, 크기, 굵게, 정렬, 이름 }         // 글상자·캡션
```

**mm 로 두는 것이 이 앱의 뼈대다.** 화면에서는 `transform: scale(배율)` 로 줄여
보여 주고 인쇄할 때만 1:1 이 된다. px 로 담으면 종이에서 어긋난다.
자른 자리·구멍·얹은 그림을 **0~1 비**로 담는 것도 같은 이유다 — 크기를 바꿔도
따라온다.

### 파이어스토어 — 앱 자체는 하나도 읽지 않고 쓰지도 않는다
쓰는 것은 손잡이(`shared/viggle.js`)뿐이고, **주소에 `?viggle=1` 이 있을 때만** 돈다.

- 프로젝트 `vivivic-4b7ef` (서류관리와 같은 계정)
- 쓰기: `artifacts/vivivic-4b7ef/public/data/wt_dev/<자리>` 에 PATCH.
  `<자리>` 는 `box:workorder`(주소의 `box=` 값) 또는 `모든박스`.
  `msgs` 배열에 `{who:'나', text, at, sent}` 를 하나 밀어 넣고 `잰때` 를 찍는다.
- 읽기: 같은 문서(「지난 지시」 볼 때).
- 들어가기: 화면에 `window.fbAuth` 가 있으면 그 자격을 쓰고, 없으면
  `identitytoolkit accounts:signUp` 으로 **익명**으로 들어가 토큰을
  `localStorage['vg.tok']` 에 한 시간 둔다.
  서류관리는 `window.fbAuth` 를 안 내놓는다 — 합친 뒤에도 지시는 로그인한
  사람 이름이 아니라 익명으로 올라간다. 그게 싫으면 서류관리가 `window.fbAuth` 를
  내주면 된다(손잡이 코드는 안 고쳐도 된다).
- `docs_files` · `docs_overlay` · `docs_rules` · `docs_config` 는 **건드리지 않는다.**

### 구글 드라이브 — 안 쓴다
작업지시서는 드라이브를 읽지도 쓰지도 않는다. 파일은 사장님이 `<input type=file>`
로 고른 것만 본다. (서류관리의 `appsscript/sync.gs` 쪽과는 아무 관계가 없다.)

## 3. 다른 프로그램과 닿는 자리

| 상대 | 무엇으로 닿나 |
|---|---|
| **작업대(viggle)** | 박스 목록에서 이 주소를 열어 준다. `box:workorder` 라는 자리 이름은 **주소의 `box=` 값이고, 앱 코드 안에는 없다**(`viggle.js` 108줄 `표.get('box')`). 그래서 "박스를 없앤다" 는 작업대·서류관리 쪽 일이고, 이 HTML 은 고칠 것이 없다. |

| **에이엠티 · 이카운트등록 · 원장관리 · 조혼가구** | **내가 아는 한 주고받는 것이 없다.** 자료도 코드도 공유하지 않는다. |
| **바깥** | cdnjs 의 pdf.js 3.11.174 (본체 + worker). |

## 4. 다시 밟지 말 것

새로 옮기는 사람이 같은 자리에서 넘어지지 않게 적는다. 대부분 사장님이 한 번씩
겪고 나서 고친 것들이다.

**손가락**
1. HTML5 `draggable`/`dragstart`/`drop` 은 **아이폰 손가락으로 아예 시작되지 않는다.**
   이 앱의 모든 끌기는 `pointerdown/move/up/cancel` 로만 되어 있다. 되돌리지 마라.
2. **길게 누르기는 쓰지 마라.** 그건 손잡이(지시 보내기)가 쓰고 있다. 우클릭·
   contextmenu 를 유일한 길로 두어도 안 된다(폰에 없다).
3. 두 손가락 확대에 지시창이 튀어나오던 것을 `viggle.js` 에서 막아 두었다
   (`e.touches.length > 1` 이면 그만둔다). 손잡이를 고칠 일이 있으면 이걸 지우지 마라.
4. 화면이 0.44배로 줄어 있어 종이 안의 손잡이(20px)는 9px 로 보인다. 그래서
   `--되키움`(1/배율)으로 되키운다(880줄). **부작용을 알아 둬라 — 되키운 ×는 자료
   왼쪽 위에서 60px 쯤 차지한다.** 그 근처를 누르면 지우기가 눌린다. 시험 코드를
   쓸 때 여기서 여러 번 헛짚었다.
5. 글상자(`.tx`)는 손가락으로 끌어 옮길 수 없다 — 상자 전체가 편집칸이라
   `끌기` 가 `.tx` 를 만나면 비켜선다. **글상자는 미세이동(◀▲▼▶)으로 옮긴다.**
   고칠 생각이면 이 자리를 먼저 보라(712줄 근처).
6. 글상자를 누르면 `focus` 가 따라오는데, 그것이 고르기를 한 번 더 불러 방금
   Ctrl 로 더한 것을 도로 뺐다. `방금누름` 으로 막아 두었다. 지우면 다시 그 버그다.
7. 여럿 고른 채 그 가운데 하나를 누를 때 고름을 흩지 않는다(함께 끌어야 하니까).
   끌지 않고 톡 떼면 그때 셈한다. 이 두 가지를 한 군데서 한다(584줄 근처).
8. 겹친 것은 같은 자리를 톡톡 눌러 한 겹씩 내려간다(6px·400ms 안의 '톡' 일 때만).
   고른 것이 잠깐 `z-index:900` 으로 올라오고, 걸림 가이드는 `1000` 이다 —
   안 그러면 고른 자료가 제 가이드를 덮는다.
9. 「여러 개」 가 켜졌거나 Ctrl·⌘·Shift 를 누른 동안은 **한 겹 내려가기를 쉰다.**
   `더누름(e) = 키누름(e) || 여럿모드` 한 줄이 그것까지 본다. 끌기를 막는 자리는
   `키누름(e)` 만 본다(켜 둔 채로도 끌어야 하니까). 이 둘을 헷갈리면 폰에서
   자료가 안 움직인다.

**자르기 · 지우기 · 그리기 (자료가 불어나는 자리)**
10. 자를 때 그림을 **다시 굽지 마라.** `it.잘라` 에 원본에 대한 비만 적고, 상자를
    그 조각 자리로 옮긴다. 그래서 자르기 전후 배율이 똑같다(사장님이 "자르면
    확대되는 게 말이 되냐" 고 한 그 일이다).
11. 지우기·잘라내기도 **굽지 마라.** 예전에 `canvas.toDataURL('image/png')` 로
    다시 구웠더니 1200×800 JPEG 719KB 가 3687KB(5.1배)가 됐다. localStorage 5MB 면
    사진 한 장에 저장이 끊긴다. 지금은 `it.구멍` 에 적고 SVG `clipPath` 의
    `clip-rule="evenodd"` 로 오려 낸다(인쇄 PDF 에도 벡터로 들어간다).
12. 구멍을 낼 때 `delete it.쪽` 을 하지 마라. 그러면 쪽 목록의 한 벌 쓰기가 깨져
    같은 그림이 문서 안에 여러 벌 쌓인다.
13. 얹은 도형도 자료 상자에 대한 비로 담는다(`it.그림들`). SVG `viewBox` 를 자료의
    mm 크기로 잡으므로 선 굵기도 mm 다 — 그래서 인쇄가 선명하다. 캔버스로 바꾸면
    A4 에서 계단이 진다.
14. 붙여 오는 그림(`복사함`)은 원본 주소를 그대로 들고 온다. 크기를 다시 재지 마라 —
    붙일 때 배율이 바뀌면 안 된다.

**저장**
15. 글자 하나마다 저장하면 사본이 그만큼 쌓인다(지울 방법도 없었다). 600ms 미뤘다
    한 번 쓴다. 이름은 `onchange` 에서만 바꾼다.
16. 본문은 **한 곳에만** 둔다. 예전에 `지금` 에도 한 벌 더 써서 담을 수 있는 쪽 수가
    정확히 절반이었고, 둘 중 하나만 성공하면 다음에 열 때 말없이 옛 판으로 돌아갔다.
17. 자리가 모자라 저장이 멈추면 머리에 붉은 띠를 띄워 **고쳐질 때까지 둔다.**
    한 번 알리고 마는 알림창으로 바꾸지 마라 — 모르고 닫으면 다 사라진다.
18. PDF 는 쪽마다 긴 변 2000px 로 줄여 JPEG 0.85 로 담는다. 쪽 수는 자르지 않는다
    (예전에 10쪽에서 끊어 뒤가 통째로 사라졌다). 한 쪽이 30초를 넘으면 그 쪽만
    건너뛰고 나머지는 살린다.

**시험하는 법(내 쪽 이야기지만 적어 둔다)**
19. 손가락은 CDP `Input.dispatchTouchEvent` 로만 제대로 흉내 난다. Playwright 의
    `setInputFiles` 는 경로로 주면 아무것도 안 붙을 때가 있다 — `{name,mimeType,buffer}` 로 줘라.
20. `addInitScript` 는 새로고침할 때 localStorage 를 다시 덮는다. 저장이 남는지 보려면
    **같은 칸의 새 창**으로 열어 봐라.
21. 좌표 없는 합성 `PointerEvent('pointerdown')` 으로 고르면 끌기가 시작된 채로
    남아, 다음 터치가 엉뚱한 곳으로 튄다. 고를 때도 진짜 터치를 쓰거나
    `pointerup` 을 같이 보내라.

## 5. 인쇄 · PDF — 그리고 09-10 질문 자리

사장님 09-10 질문: **「인쇄 저장시 왜 편집된모습이 적요되지않나요」**
원인과 고친 자리를 적는다. (작업대 라인에는 이 질문에 대한 답이 아직 안 달려
있다. 고친 것은 09-11 에 나갔다.)

- **원인**: 예전에는 인쇄 직전에 `그리기()` 로 화면을 통째로 다시 그렸다. 고른
  표시를 지우려는 것뿐이었는데, 글상자는 `input` 이 올 때만 모형에 적히고
  아이폰은 자판이 내려가며 마지막 `input` 을 늦게 주거나 아예 안 준다. 그래서
  **방금 친 글자가 없는 채로 다시 그려져 그대로 인쇄됐다.**
- **고친 자리**: `글걷기()` (1657줄 근처) — 화면에 보이는 글을 먼저 걷어 모형에
  담고(조합 중인 글자는 `blur()` 로 끝맺는다), 다시 그리지 않고 `고름지우기()` 로
  표시만 뺀다. 그다음 `그림기다리기()` 로 그림이 다 펴질 때까지 기다린 뒤
  `window.print()` 를 부른다. 이 순서를 바꾸면 그 버그가 돌아온다.
- 인쇄 단추는 누르는 동안 잠기고 글이 '내보내는 중…' 으로 바뀐다.

**아이폰 용지 문제(같이 알아 둘 것)**
- 아이폰 사파리는 `@page{size:A4}` 를 **무시하고** 제 용지를 쓴다. 여백도 제멋대로다.
  그러면 210×297 이 용지에 안 들어가 오른쪽이 잘리거나 한 장이 두 장으로 갈린다.
- 자바스크립트로는 인쇄 매체를 못 읽으므로, `용지사다리()` 가
  `@media print and (max-width:…mm){.아이폰 .sheet{zoom:…}}` 를 100%→50% 까지 한 줄씩
  깔아 둔다. 맞는 줄이 스스로 잡힌다. `인쇄여유 = 12.7mm`(0.5인치)는 사파리가
  제멋대로 두는 한쪽 여백 어림값이다.
- **크롬은 이 사다리에 걸리면 안 된다.** 인쇄 매체의 width/height 는 `@page` 가 아니라
  **프린터 용지**를 알려 주므로 크롬도 조건에 걸릴 수 있다. 그래서 첫 칸을 99% 로
  낮춰 두었고, `.아이폰` 클래스가 붙은 화면에만 건다.
- `.sheet{margin:0 auto}` 는 **`.아이폰` 에만** 건다. 크롬에 걸면 글자가 0.156px 씩
  밀려 인쇄 결과가 달라진다(PDF 를 뜯어 비교해서 찾았다).
- 인쇄에서 숨기는 것: `.top .tools .hint .sheetpad .grip .del .pageno .pagedel
  .pagefit .zone .warn .guide` 와 `.vg-hint .vg-toast .vg-sheet .cropbar .croplayer
  .tray .ghost .drawbar .그림판`. **손잡이 띠를 안 숨기면 종이마다 '길게 눌러
  짚어서 지시' 가 박힌다**(사장님이 실제로 겪었다).
- 고칠 때마다 나는 크로미움으로 인쇄 PDF 를 떠서 **옛 판과 한 줄씩 비교**했다
  (내용 스트림을 풀어서 `re`/`Tj`/`cm` 줄만 견준다). 0줄 차이가 아니면 뭔가
  건드린 것이다. 이 습관은 물려받을 만하다.

## 6. 375px · 손가락 크기 · 길게 누르기가 걸린 자리

- 화면은 **폰 375px** 기준으로 맞췄다. 768·1280 도 본다.
- 띠 단추는 `min-height:40px` 다(**44px 이 아니라 40px** 이다. 44 로 올리면 아래 줄이
  더 밀린다). 아래 연장 줄은 375px 에서 **한 줄 57px**, 옆으로 **766px** 밀린다
  (단추 17개 — 옆으로 미는 줄이다).
- 표시 도구 띠(`.drawbar`)는 **두 줄 96px**, 단추 40px. **「그만」 은 줄 밖에
  붙박아** 두었다 — 줄이 옆으로 밀려도 나가는 길이 늘 보여야 한다. 둘째 줄은
  209px 밀린다.
- 쪽 목록은 92px 이고, 열리면 무대가 그만큼 오른쪽으로 간다(`body.쪽함`).
- 종이 안의 손잡이·×는 20px 인데 배율만큼 작아지므로 `--되키움` 으로 되키운다.
- 걸림 폭은 화면에서 늘 같아야 한다 — `걸림px = 6` 을 mm 로 바꿔 쓴다
  (배율 1.0 이면 1.59mm, 0.44 면 3.60mm).
- **길게 누르기가 걸린 자리**
  - 실제 동작은 전부 `shared/viggle.js` 에 있다. 앱은 두 가지만 거든다:
    ① 종이를 세로 4 × 가로 3 으로 나눈 보이지 않는 칸(`.zone`)을 깔아 두고 거기에
    `1장 위 왼쪽 35,37mm` 같은 이름을 적어 둔다(`칸나누기()`, 427줄 근처).
    손잡이가 짚은 것의 글자를 그대로 읽어 가므로 **지시에 어디를 짚었는지가 실린다.**
    ② 짚은 칸에 손잡이가 `vg-mark` 를 붙이면 `.sheet.짚기 .zone.vg-mark::after` 로
    그 이름을 옅게 보여 준다. 인쇄에서는 `.zone` 을 숨긴다.
  - 그래서 **자료 위에서 길게 눌러도 지시창이 떠야 한다.** 새 기능을 넣을 때마다
    이걸 확인했다(자르는 판·그림판은 그리는 동안만 덮고, 그만 누르면 걷는다).

## 7. 내가 모르는 것 (아는 척하지 않는다)

- **사파리·아이폰 실물에서 못 해 봤다.** 이 방에 웹킷이 없고 내려받는 길도 막혀 있다.
  전부 크로미움에 손가락 신호를 넣어 쟀다. 특히 `clipPath`(구멍)와
  `zoom` 사다리(인쇄)는 사파리에서 한 번 봐야 한다.
- 배포된 주소를 이 방에서 열어보지 못한다(github.io 가 막혀 있다). 배포는 GitHub
  Actions 의 성공 여부로만 확인했다.
- `build-single.py` 가 CDN `<script>` 와 큰 인라인 CSS 를 어떻게 다루는지 안 봤다.
- 서류관리의 로그인(이메일·비밀번호)과 작업지시서를 어떻게 이을지 정해진 것이
  없다. 지금 작업지시서는 로그인이 없고, 누가 쓰든 그 기계 안에 저장한다.
- 사장님 폰에 이미 구워진(옛 방식의 PNG) 자료가 있을 수 있다. 그건 그냥 그림으로
  남는다 — 되돌리지 않았다.
