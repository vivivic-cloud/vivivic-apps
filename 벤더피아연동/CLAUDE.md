# 벤더피아연동 — 이 집에서 지킬 것

벤더피아(`https://vendorpia.com`, ASP.NET WebForms ERP) 위에 덧씌우는 **크롬 확장 프로그램**이다.
웹 앱이 아니다. 벤더피아의 **진짜 아이디·비밀번호로 그 사이트 로그인을 그대로** 쓴다
(집 이메일 로그인을 쓰는 「배송관리업로드」 와는 다른 것이다). 크롬이 깔린 컴퓨터에서만 돈다 — 폰에서는 안 된다.
설치 안내는 이 폴더의 `index.html` (https://vivivic-cloud.github.io/vivivic-apps/벤더피아연동/) 이다.
확장 이름(manifest)은 「벤더피아 보기」, 사장님 컴퓨터에 깔린 폴더는 **`~/Downloads/벤더피아보기 31`** 이다 (unpacked, 크롬이 거기서 읽는다 — 바탕화면 `~/Desktop/벤더피아보기` 가 아니다. 10-25 바이글이 사장님 크롬에서 확인).

## 목록 화면이 하는 일 (`goods.js`)

⚠ 10-21 부터 **표**다 (사장님: 「단품관리와 상품관리 재고조회의 각 버튼이 메인이 되는 표형식으로 나열해줘」).
- **첫 칸 = 이름 버튼**(누르면 오른쪽에 상세 창). 나머지 칸은 `vp-data.js` 의 `PAGES[…].cols`:
  단품관리 `단품분류·현위치(매입처명)·재고유형·발주유형·판매상태` / 상품관리 `매출처·매입처명·배송사명·판매상태·옵션상품유무·상품정보(링크)` /
  재고조회 `분류명·현위치·양품수(합)`. **금액 칸은 표에도 안 꺼낸다.**
- **이름 하나에 표 줄 하나.** 같은 단품·상품의 줄이 여럿(창고별·매입처별·매출처별)이어도 한 줄이고, 칸에는 값들을 **중복 없이 모아**
  적는다(셋 넘으면 「… 외 N」, 마우스를 올리면 전부). 줄은 `groups`(이름 → `{b, items, tr, tds, i}`)가 하나씩 들고 있다.
- **거르개 알약**(검색칸·선택칸 **아래** `.vp-pillbar`): `PAGES[…].pill` — 단품관리 **현위치 = 매입처명**(0.34.65 부터 알약 대신 **고르는칸 하나** `select.vp-fsel`, `pill.drop`; 예전 [전체보기][현위치별 보기] 탭을 없앴다),
  상품관리 **매출처명**, 재고조회 **현위치 = 창고, 창고가 0.본사면 매입처**(상세의 현위치 탭과 같은 논리, `placeIn`).
  알약을 고르면 그 값이 든 줄을 하나라도 가진 이름만 남고(`matches` 의 `pillPick`), 줄은 그대로 한 줄이다. 칸도 **고른 값의 줄만** 모아 적는다
  (재고조회 양품수 = 고른 현위치 것만의 합). 알약에는 그 값이 든 이름 수가 붙는다. 상세 창도 고른 값부터 연다(상품 상세의 매출처 알약·재고 상세의 현위치 탭).
  상품관리의 선택칸 「매출처」·단품관리의 「매입처」 선택칸은 알약과 겹쳐 **없앴다**.
- 표 줄 차례: 첫 화면은 **최근 3개월 많이 나간 순 50개**(「더보기」·「전체보기」·「접기」 그대로). 표 줄에는 CSS `order` 가 안 먹어
  `reorder()` 가 줄을 **실제로 옮긴다**(이미 그 차례면 안 건드림).
- **이름은 버튼이 아니라 누르는 글자 + 아래 점 넷**(10-22 `[새 지시 연동 점]`). 글자 꼴은 서류관리의 누르는 글자(`text-info` `#337ea9`·평소 밑줄 없음·올리면 밑줄)를 따르고 표 안에서는 첫 칸 꼴(14px·700, 10-23)(상세 칩 12px), 누른 것은 굵게+밑줄. 버튼은 그대로 `td > div.vp-goods-list > button`(클래스 이름·시험 열쇠 유지).
  점은 글자 아래(`span.vp-점` 안 `i.g/.r/.o/.b` 넷, **클래스만 보고 CSS 가 켠다**): 🟢 초록 = 재고조회 목록에 있음(`vp-instock`, 양품 0 이어도) · 🔴 빨강 = 조혼가구와 일치(`vp-johon`, `markJohon`) · 🟠 주황 = 카탈로그 inghome 와 맞음(`vp-ing`, `ing맞춰보기`, 상품관리). 🔵 파랑 = 서류관리 연결(`vp-서류`, `서류연결` 판단 그대로, 색은 아래 팔레트, 10-22 `[새 지시 파란 점]`) · 해당하는 것만 나란히. 양품 딱지는 글자 곁에 그대로. 판단 논리는 안 바꿨다. 세 화면 머리(`h1` 아래 `.vp-legend`)에 점 설명 넷(● 서류관리 연결 포함).
  **점 색 = 사장님 팔레트**(10-22 `[새 지시 점 색]`, 사장님 말씀 「각 점을 이색상들로 사용해줘」): `#06AED5` Turquoise Surf · `#086788` Cerulean · `#F0C808` Bright Amber · `#FFF1D0` Papaya Whip · `#DD1C1A` Primary Scarlet. 짝(바이글이 정함) — 재고조회 🟢→`#06AED5`(`--점-재고`) · 조혼가구 🔴→`#DD1C1A`(`--점-조혼`) · 카탈로그 🟠→`#F0C808`(`--점-카탈로그`) · 서류관리 🔵→`#086788`(`--점-서류`). 네 CSS 변수는 `goods.css` 의 `#vp-root { … }` 한 줄에 모여 있다(점과 머리 설명이 같이 따라옴) — 바꾸려면 거기만. Papaya Whip 은 흰 바탕에서 점으로 안 보여 안 썼다. 점 크기·자리·기준은 그대로. ⚠ `#F0C808` 은 밝아 6px 점이 흰 바탕에서 옅다.
  ⚠ 서류관리 연결(`vp-서류`, `서류연결`, 수입정보 차수 박스)은 판단·기능 그대로, **주황 칠은 뺐고 파란 점으로 보인다**(단품 글자·상세 칩 어디서나) — 주황은 이제 카탈로그다. (10-24 에 배송관리·CS등록 상품명/단품명 단추도 같은 꼴로 바뀜 — 아래 「알아낸 것」 0.34.50. 옛 알약 꼴·서류 주황 칠 CSS 는 지움.)
- 속성은 **상세 창 안에서만**(전과 같다): 빈 값은 「전체속성 보기」, 금액 칸은 「금액속성 보기」(누르면 「금액 속성은 승인된 아이디만 볼 수 있습니다.」 팝업),
  조혼가구 단품은 「부속보기」(에이엠티 부속카드). **승인된 아이디는 아직 하나도 없다.**
- 표 꼴은 **서류관리 제품관리 박스의 표**(`vivivic-docs/index.html` `#docs-prod .dpr-t`)를 따른다(10-23, 아래 「표 꼴 = 서류관리 제품관리 표」 숫자 표). 좁은 창은 표 통만 옆으로 밀린다(쪽은 안 밀림). 첫 칸은 밀어도 왼쪽에 붙는다.
- 버튼에 코드를 작게 함께 적는다. 단품명에 `(사용안함)` 이 든 단품은 줄을 만들지 않는다.
- **재고는 단품으로만 관리한다** (상품은 판매명일 뿐). 재고조회에 있는 단품은 초록 점 + 양품수 딱지.
- 조혼가구 단품(모든 거래처 탭의 ING단품명)과 같은 단품은 이름 밑에 **빨간 점**. 붉은 줄 단품은 「부속보기」 →
  에이엠티 발주확정 부속카드 모양. AMT 부속은 붉게. 카드를 누르면 엣지 도면(초록선=엣지면, 붉은선=우라홈)과
  재단도면(조각마다 치수, 「+전도방지」).
- 상품 상세에는 연결된 단품 버튼, 단품 상세에는 연결된 상품 버튼. 상품정보(inghome) 링크는 표의 「상품정보」 칸과 상세 둘 다에 있다.

  · 언제 지우나: **F5 에도, 새 로그인에도 안 지운다**(`clearCache` 는 `vpCache:` 만). 7일 처음부터 다시 모으기·새 등록 더하기는 **없다**(전체를 모으지 않으니 필요 없다).
  · 열 때: 저장에서 읽기만 하고(요청 0) 바로 단추를 붙인다(F5 두 번째 0.3초 안 — 지키는 것). 모음에 없는 이름은 목록에 나온 칸 차례대로(위 줄부터) `VP_DATA.하나찾기`(코드 먼저 → 이름, 조회만)로 하나씩 찾아 모음에 더하고, **찾는 대로 120ms 모아** 단추를 붙이고 끝에 저장한다. 일꾼 3(상품·단품 각각) — ⚠ 0.34.71 부터 벤더피아로는 공용 줄이 **한 번에 하나만** 보낸다(아래 「이동느림근본」), 한 번에 1,500가지까지. 못 찾은 이름은 같은 날 다시 안 찾는다(`없음`).
  · 이름이 바뀐 것 거르기: 단추를 누르면 그 이름으로 상세 줄을 받는데(`줄받기`) 못 찾으면 **모음에서 뺀다**(`모음에서빼기`) — 다음 조회에서 목록의 새 이름으로 다시 찾는다. 안 누른 낡은 이름은 화면에 안 나오니 해가 없다.
  · 큰 HTML 읽기(DOMParser)는 한 쪽씩, 쪽 사이에 쉰다. search.js 는 칸을 25ms 씩 쪼개 채운다(`칸채우기예약`). `VP_DATA.이름받기` 는 없앴다.
- **열 때 뒤에서 요청하지 않는다 — 누를 때 받는다 (10-26, 0.34.60)** — 배송관리·CS등록을 열거나 F5 하고 아무것도 안 누르면 벤더피아로 가는 요청은 **페이지 자신 1번뿐**이다(조회 전엔 곁다리도 0). 규칙:
  · 열 때 해도 되는 것: 저장 읽기(요청 0)와 벤더피아 아닌 점 자료 — 서류관리 차수(Firestore `수량받기`)·카탈로그 목록(깃허브 `ing맞춰보기`)·조혼가구(저장). 수입정보(Firestore, 상세에만 씀)는 조회가 끝나고 한가해진 뒤(`조용해지면` — `window.VP조회중`(search.js `status`)이 꺼져야).
  · **재고조회 전체(StockList 5~6번·7MB)·연결 목록(상품↔단품 전체)·상품관리 상세는 열 때 받지 않는다.** 연결 목록은 단추를 처음 누를 때(`연결받기`, 1.5초 뒤, 뒤에서). 재고조회는 아래 「한번에」 — **조회 목록이 다 온 뒤**.
- **점·수량·단추는 한번에 붙는다 (10-26 [새 지시 한번에], 0.34.61)** — 사장님 「되도록 불러온 정보의 상태과 그 작동은 한번에 되게 해줘」. 0.34.60 은 초록 점·양품 수량이 처음 단추를 누른 뒤에야 붙었다 — 그것을 걷었다. 규칙(`goods.js` 맨 위 `한번에`, 두 벌이 함께 쓰는 한 벌):
  · 곁다리 이름 단추(`곁다리단추`)는 **`한번에.s.다됨` 전엔 만들지 않는다**(칸은 글자 그대로). 다됨 = 상품 벌 준비(카탈로그) + 단품 벌 준비(조혼가구·차수) + 재고(받음/저장/못받음). 다되면 두 벌이 알려(`vp상품단추준비`·`vp단품단추준비`) search.js 가 칸을 한꺼번에 채운다 → 단추 · 네 점 · 양품 수량이 같은 순간에 붙는다. **단추만 먼저 붙이지 마라.**
  · 재고 받기 시작 = 첫 `곁다리단추` 부름(= 조회 목록이 그려짐) 뒤 `VP조회중` 이 꺼지면. 열 때(조회 전)는 요청 0 그대로. 받는 동안 이름 찾기(`곁다리찾기`)는 쉰다(`비켜서기` — 벤더피아는 요청을 하나씩 처리한다). 누른 단추의 상세(`줄받기`, `누름중`)도 찾기보다 먼저 간다. 30초 넘게 답이 없으면 초록 점 없이 붙이고 재고가 오면 그때 칠한다. 벤더피아 아닌 점 자료(차수·카탈로그)도 8초 넘게 안 오면 준비로 치고, 늦게 오면 그때 칠한다(흉내 화면에서 Firestore 다리가 없어 단추가 영영 안 붙던 것을 시험통 `확장길.cjs` 가 잡았다).
  · **재고 저장 `vpStock`** = `{v:1, at, 쌍:[단품코드열쇠, 양품수, …]}` — 두 칸뿐(금액·사람 칸 없음). **10분** 안이면 F5·다시 열기에 그대로 쓴다(요청 0, 줄 보임과 같은 순간에 다 붙음). 10분 넘으면 다시 받는다 — 수량이 10분보다 오래된 값으로는 안 보인다. ⚠ `vpCache:` 가 아니라 F5 에 안 지워지는 것은 **일부러**다: 집 규칙 「F5 = 목록 화면 자료 새로」 는 단품·상품·재고조회 **목록 화면**(`vpCache:`)에 그대로 걸린다. `vpStock` 은 배송관리·CS등록 단추 점·수량만, 10분만. 더 길게 늘리지 마라.
  · 카탈로그(주황)는 받은 목록(`ing표`)을 들고 있어 나중에 찾아 더한 이름에도 붙는다(`ing한이름`, 같은 잣대).
  · 이름 단추 찾기(`곁다리찾기`)는 **맞는 줄 하나면 되니 10줄만 받는다**(`하나찾기(가볍게)`: 10줄에 없고 더 있으면 700줄로 다시). 10줄만 받은 답은 상세용 줄 캐시에 넣지 않는다(`전부:false`).
  · 찾는 대로 단추를 붙이는 알림(`곧알림`)은 **700ms 모아서** — 120ms 마다 하면 600줄×30칸 표를 계속 다시 배치해 한 번 멈춤은 없어도 화면이 내내 버벅이고 찾기도 1.5배 느려졌다(재서 확인: 36초 ↔ 53초).
  · 조회 응답(1.3MB↑)은 `표뽑기` 가 DOMParser 전에 숨은 입력칸·스크립트·스타일을 문자열에서 덜어 내고, 600줄은 80줄씩 그리고 쉰다(search.js `take`). 한 번 멈춤 0.2초 아래가 목표.
- 지금 화면에 필요한 것을 먼저 받고, 다른 메뉴 목록은 그 뒤 조용히 받는다 (지금 화면이 받는 중이면 기다린다).
- 단품코드는 앞뒤 빈칸을 지우고 소문자로 맞춰 비교한다 (그래야 99.9% 맞는다).

## 무엇보다 먼저

- **벤더피아에서는 조회만 한다.** 저장·등록·삭제는 하지 않는다.
  ⚠ **예외는 둘뿐** — ① (10-26 사장님 허락 「만들어. 시험 등록할 주문은 내가 정해줄게」): CS 상담 판 메시지 → 벤더피아 **고객문의 등록**(`search.js` `벤더피아올리기`). ② **벤더피아 쓰기 예외 두 번째: 고객주문변경 저장**(10-28 [새 지시 고객주문변경], `search.js` `주문변경올리기` — CS등록 종류·단품·출고 메시지). **이 둘만**이다 — 다른 기능에 쓰기를 넓히지 마라.
- **비밀번호를 대신 넣지 않는다.** 로그인은 사장님이 하신다.
- **배송관리는 저장해 두지 않는다** — 늘 벤더피아와 같아야 한다.
- 조혼가구 화면이 빈 자료(에이엠티처럼 `pageToSupplierMap` 이 빈 화면)를 넘기면 저장된 목록을 **덮어쓰지 않는다**
  (예전에 그래서 붉은 줄이 다 사라졌다).
- 에이엠티 그리기 코드(`amt-draw.js`)를 따로 고치지 않는다. 에이엠티가 바뀌면 거기서 다시 옮겨 온다.

## ⚠⚠ 벤더피아 메인은 **틀(frameset)** 이다 (10-13)

사장님: 「메인화면에서는 **영역만 짚어지고** 지시내용을 보내는 부분이 안나타난다」 ·
「본 메뉴에 들어가서도 안된다」.

까닭 둘 —
1. 틀 문서에는 몸(`body`) 자리에 `<frameset>` 이 있다. **거기에 붙인 것은 안 그려진다.**
   붉은 테만 남아 「영역만 짚어진다」 로 보였다.
2. 확장 글은 기본으로 **맨 위 문서에서만** 돈다(`all_frames` 없음). 진짜 화면은 **틀 안쪽**이라
   거기엔 손잡이가 아예 없었다.

→ `불러오기.js`·`짚개.js` 둘 다 **`all_frames: true`**, 그리고 **틀 문서(`FRAMESET`)에서는 돌지 않는다.**
→ `짚개.js` 는 `불러오기.js` 에서 떼어 **제 content_script** 로 두었다(틀 안쪽까지 가야 한다).
⚠ 새 글을 붙일 때 이 둘을 꼭 지켜라. 안 그러면 또 「영역만 짚어진다」 가 난다.

## ⚠⚠ 화면 글은 **깃허브에서 바로** 간다 — 덮어쓸 일이 거의 없다 (10-13)

사장님: 「확장파일을 계속 수정시마다 덮어 써야되는거야?」 → 「**1**」(얇은 껍데기로 하라).

벤더피아 화면에서 도는 글은 이제 확장이 **깃허브에서 받아** 넣는다(`불러오기.js`).
```
깃허브에서 바로 가는 것 (커밋·푸시만 하면 끝 — 사장님은 새로고침만)
   vp-data.js · login.js · menu.js · search.js · johon.js · amt-draw.js · goods.js · 짚개.js
   login.css · menu.css · search.css · goods.css
확장 안에 있어야 하는 것 (고치면 판 올리고 zip 다시 묶고 **사장님이 덮어써야** 한다)
   manifest.json · 불러오기.js · 저장다리.js · johon-read.js · johon-save.js · 깔렸다표시.js
```
⚠ 못 받으면 **확장 안의 것**으로 돈다(같은 파일이 zip 에도 들어 있다). 둘 다 안 되면 **붉은 줄**을 띄운다.
그래서 **zip 에는 늘 최신 화면 글도 같이 넣는다** — 뒷길이 묵으면 안 된다.
⚠ 화면 글은 이제 **페이지 쪽(MAIN)** 에서 돈다. `chrome.storage` 에 바로 못 닿으니 **`window.VP저장`**
(저장다리.js) 을 쓴다. 새 글에서 확장 저장소가 필요하면 그 다리를 쓰고, 다리를 늘릴 일이 생기면
`불러오기.js` 와 `저장다리.js` 를 **같이** 고쳐야 한다(이때는 덮어쓰기가 필요하다).

    확장 안의 글이 바뀌어 **정말로 덮어쓰셔야 할 때만** `꼭판` 을 올린다 — 안 그러면 고칠 때마다
    사장님께 쓸데없는 덮어쓰기가 뜬다.)
1-나. ⚠⚠ **`login.js` 의 `VP_화면글판` 을 `manifest.json` 의 version 과 **같은 값**으로 올린다.**
