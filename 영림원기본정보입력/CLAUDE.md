# 영림원 기본정보 입력 — 이 집에서 지킬 것

실제 등록할 제품·반제품(부속)·자재를 **한 행 = 한 품목**으로 보고 고치는 프로그램. 고친 행을 「넘기기」로 영림원외주입력 폼 1~11단계·구매단가 **대기** 문서로 보낸다.
주소: https://vivivic-cloud.github.io/vivivic-apps/영림원기본정보입력/영림원기본정보입력.html

> 영림원외주입력 폼의 규칙(맨 위 ⚠ 덩어리)을 모두 따른다 — 칸 이름 영림원 글자 그대로 · 설명 글 금지 · 드롭다운 목록 밖 입력 허용(「미등록」 표시만) · 양식 다운로드·일괄 업로드(엑셀·구글시트) · 대기 삭제 · 복사등록.
> ⚠ **공개 저장소.** 실제 제품 목록·단가·거래처 값은 커밋하지 않는다. 자료는 파이어스토어 `erp_basic` 과 드라이브(「영림원외주입력 양식」 폴더와 그 하위)에만.

## 사장님 말씀 (글자 그대로, 2026-11-10)
「이 파일은 확정된 제품의 테스트가 아닌 실제 등록이 시작될 제품 입니다. 테스트로 돌렸던 네가지 제품의 확정판이라고 생각하면 됩니다. 이파일을 기준으로 네가지 테스트 제품의 영림원 입력정보를 응용하여 한행입력 시트를 만들어야 합니다. 이를 편집할 수 있는 정보가 포함된 영림원 기본정보 입력 프로그램을 만들어 봅시다 프로그램의 디자인은 비비빅 디자인과 일관성이 있게 만들어져야 합니다. 일단 만든후 실제 사용하면서 코드를 수정 합니다」

## 파일
- `영림원기본정보입력.html` — 한 장짜리. 판 번호 = 맨 위 주석 + 머리띠 배지(같이 올림). 지금 **v1**.
- `칸.json` — 칸 정의(시트 「품목」·「자재」, 묶음 → 칸, 반복 묶음 `rep`·`n`·`pre`). 화면·양식·올리기·아래 도구가 모두 이것 하나를 쓴다. 칸을 고치면 여기만.
- `도구/기준파일-한행만들기.py` — 기준 파일 xlsx + 폼 저장소 erp_ JSON → 한행 입력표 xlsx. 자료 값 없음(실행 때 읽음). 테스트 꼴 응용 규칙이 이 안에 있다(`item_analog`·`mat_analog`).

## 저장소
- 파이어스토어 `vivivic-4b7ef`, 컬렉션 **`erp_basic`** 하나. 문서 id = `i_<품번>`(품목) · `m_<자재번호>`(자재), `/` 는 `∕` 로.
- 문서: `kind`(품목|자재) + 칸.json 의 칸 키 + 반복 묶음 배열 `bom`(7 BOM 줄) · `procs`(10 공정순서 워크센터 + 11 외주품번·외주단가, 같은 배열) · `pp`(구매단가 1·2) + `test`(테스트값 칸 키 목록) · `tpl`(테스트 기준 품번) · `parents`(이 부속을 쓰는 제품) · `status`(대기|넘김) · `passedAt` · `createdAt`·`updatedAt`·`by`.
- 로그인 = 영림원외주입력 v115 담당자 로그인 그대로(같은 식). 화면 권한 = `admin` 또는 `erp_staff.cols.erp_basic.{w,d}`.
  권한 메뉴 = 폼 v165 「담당자 관리」 의 「영림원 기본정보 입력」 줄(`erp_basic`). 사장님이 그 줄에 권한을 주셔야 담당자·입력 작업자(터미널 R0G2)가 저장한다(11-10 기준 R0G2 쓰기 403, 읽기는 됨).
  저장소 규칙은 고칠 것 없음(erp_ 일반 덩어리).

## 화면
- 왼쪽 목록 = 제품 · 반제품 · 자재. 카드 = 품명 · 품번 · 공정흐름유형 · 상태 칩(대기/넘김) · 「테스트값 N」 · 「확인 N」.
- 펼치면 단계별 칸 묶음: 4 품목등록 · 3 품목 대중소분류 · 품목등록업로드(기준 파일의 그 밖 칸) · 8 공정흐름유형 · 7 BOM(줄 표, 줄 더하기·빼기) · 9 공정차수·BOM차수 · 10 시간단위·표준작업시간 + 공정순서 표(워크센터 우선순위 1~3) · 11 사업단위·통화·정산기준·부가세·적용시작일 + 공정순서별 외주품번·외주단가. 자재 = 5 자재등록 + 구매단가등록 1·2.
- 테스트값 칸 = 노란 칸 + 「테스트값」 표. 고치면 표시가 빠진다(저장 때 `test` 에서 빠짐).
- 공정흐름유형을 바꾸면 공정순서의 공정이 그 흐름대로 바뀐다(워크센터·단가는 그대로).
- 「확인」(막지 않음): 품번 없음 · BOM 공정이 공정순서에 없음(표 칸 빨강) · 하위품번 미등록 · 공정흐름유형 없음. 목록 밖 공정·워크센터·흐름·거래처 = 칸 주황 테두리 / 「미등록」.
- 단추: 양식 다운로드(엑셀 / 구글 스프레드시트 — 저장된 행 전부가 들어간 한행 입력표, 구글은 v113 웹앱 `GS_MAKER`, 파일 이름 `외주입력_기본정보_한행입력표`) · 일괄 업로드(엑셀 파일 / 구글시트 링크 — `export?format=xlsx` 로 두 탭 함께, 링크 공유 필요) · 입력폼에서 불러오기(폼 erp_ 완료 문서 → 한 행) · 새 품목/새 자재 · 행마다 저장·복사등록·넘기기·삭제 · 목록 「넘기기 N건」·「선택 삭제 N건」·「대기 모두 삭제」.
- 편집 중에는 저장소 변경으로 화면을 다시 그리지 않는다(`dirty`) — 저장·닫으면 그린다.

## 한행 입력표 (구글시트)
- 드라이브 「영림원외주입력 양식」 › 「품목 한행 입력표」 › 「실제 등록 품목 한행 입력표 (품목등록test서버용1101 기준)」(11-10 만듦). 1행 = 묶음 이름(병합) · 2행 = 칸 이름 · 3행부터 자료. 노란 칸 = 테스트값. 맨 끝 「테스트 기준 품번」·「테스트값 칸」.
- 기준 파일 = 드라이브 「관리프로그램/품목등록test서버용1101」(읽기만, 안 고침). 시트 넷 중 **1-1.품목등록확정 · 2-1.BOM등록확정** 만 쓴다(후보 시트는 안 씀).
- 만든 법: 기준 파일 xlsx 받기 → 입력 작업자 터미널 로그인(`작업자표.py`)으로 erp_ 읽기 → `도구/기준파일-한행만들기.py` → 드라이브 업로드(구글시트로 바뀜).
- ⚠ 저장소 `erp_basic` 에는 아직 안 넣었다(입력 작업자 계정 403 — 폼 v165 담당자 관리에서 R0G2 에 「영림원 기본정보 입력」 권한을 주시면 작업자가 넣을 수 있다). 사장님이 프로그램에서 「일괄 업로드 → 구글 스프레드시트」에 이 시트 링크를 넣거나(링크 공유 필요), 시트를 엑셀로 받아 「일괄 업로드 → 엑셀」 하면 들어간다. 권한이 열리면 작업자가 넣어도 된다.

## 테스트 꼴 응용 (기준 파일에 없는 칸만, 지어낸 값 없음)
- 짝(`item_analog`): 제품 = 이름의 너비·「더 높은」 → T-al12h·T-al12mh·T-al80h·T-al8mh(400 은 800 짝). 반제품 = 품번 가운데 글자 + 규격: tp·bt → p07(너비 ≥1000)/p08 · siL·siR → p05/p03 · is → p10/p09 · doL·doR·do → p06/p04 · mrL → p01 · mrS → p02 · mr → p01(≥700)/p02 · b27 → p11·p12·p13·p14(너비·높이). 자재(`mat_analog`): pb_18 → T-pb18-wt · md_27 → T-md27-wt · ed_001 → T-ted1-wt(수입 외자).
- 가져온 칸: 중요도 · 대표품목 · 공정흐름유형 · 공정차수 · BOM차수 · 시간단위 · 표준작업시간 · 공정순서별 공정·워크센터(우선순위 1~3) · 사업단위·통화·정산기준·부가세포함여부·적용시작일 · 외주품번(꼴 = 품번_공정순서, 마지막 공정 = 품번) · 외주단가(우선순위1 업체 계약, 없으면 아무 업체) · BOM 원장 줄 결방향 있음 · 자재 품목자산분류·자재상태·내외자구분·중요도·자재소분류·구매단가(거래처·내외자구분·통화·단가·단위·적용시작일·특이사항).
- 기준 파일 값 그대로: 품명·품번·규격·품목자산분류·기준단위·대중소분류·품목상태·내외자구분·세트/Lot/Serial·Loss율·기본구매처·품목설명 · BOM 전부(공정 「조립」·「가공」 포함). 하위유무 = 하위품번이 품목 시트에 있으면 O(계산).
- ⚠ 그래서 모든 행에 「확인」이 뜬다: 기준 파일 BOM 공정(조립·가공) ≠ 테스트 흐름 공정(T조립·T재단·T엣지·T보링). 사장님이 공정흐름 또는 BOM 공정을 정해야 한다.
- 기준 파일 안에서 다른 값: 도어 14품번 — 품목 시트 규격(785*397·1147*397)과 BOM 하위규격(784*396·1146*396)이 다름. 그대로 옮겼다.

## 넘기기 (v1)
- 한 행 → 폼 대기 문서(`status 대기`, `fromBasic true`, route = `../영림원외주입력/erp-spec.json` 의 단계): 자재 → `erp_materials` · `erp_purprices`(거래처마다) / 품목 → `erp_items`(품목소분류 = 대 > 중 > 소) · `erp_itemflows` · `erp_boms` · `erp_itemmats`(procs = 공정순서, mats = BOM 줄, 하위유무면 제작·srev 차수, 아니면 구매) · `erp_itemwcs`(공정순서 × 워크센터) · `erp_contracts`(워크센터의 외주거래처별로 한 문서, 업체 모두 같은 단가).
- 폼에 같은 품번 문서가 있으면(오류 빼고) 그 부분은 건너뛴다. 넘기기 전에 표·건너뜀·확인 목록을 보이고 확인창.
- **못 하는 것**: 3 분류(없으면 「미등록」만) · 1 거래처 · 2 워크센터 · 6 공정흐름 새로 만들기 · 9단계 재공품 줄(`wips`)·5 재공품 자재(폼 9단계가 만든다 — 외주품명이 비면 「재공품 미등록」) · 넘긴 뒤 고친 것을 폼 문서에 다시 반영(지금은 건너뜀).

## 함정
- `procs` 하나를 10·11 두 묶음이 같이 쓴다. 줄 더하기·빼기는 10 표에서만.
- 칸.json 의 반복 칸 이름은 `줄1 공정`·`공정순서1 외주단가`·`구매1 단가` 꼴 — 올리기는 이 이름으로 칸을 찾는다(앞뒤 `*` 무시). 이름을 바꾸면 옛 양식이 안 맞는다.
- 「테스트값 칸」 열 = 칸 이름을 ` · ` 로 이은 것. 올리기가 이름 → 키로 되돌린다.

## 시험
- 가짜 저장소 사본: `connectDb` 를 메모리 껍데기로 바꾼 복사본을 로컬 서버로 열어 확인(실제 저장소 안 씀). 11-10: 제품·반제품·자재 목록, 편집, 넘기기(제품 1행 → 대기 8건), 엑셀 받기 → 다시 올리기(84건 같음), 375 폭 넘침 없음(375/375).
- 실제 로그인·실제 저장은 안 해 봤다(비밀번호 없음).

## 알아낸 것
- 입력 작업자 터미널 계정은 erp_ 읽기는 되나 새 컬렉션 쓰기는 담당자 관리 권한(cols)이 있어야 한다 — cols 는 폼 `erpMenus()` 가 만든다.
