# 시스템클라우드보기 — 이 집에서 지킬 것

SystemCloud(영림원 K-System Ace, `https://inghometest.ksystemace.com`, 테스트 회사 「아이앤지퍼니처(TEST)」)
위에 덧씌우는 **크롬 확장 프로그램**이다. 웹 앱이 아니다 — 사장님 크롬에 「압축해제된 확장 프로그램」 으로
깔려서 SystemCloud 를 열면 돈다. 설치 안내는 이 폴더의 `index.html`
(https://vivivic-cloud.github.io/vivivic-apps/시스템클라우드보기/) 이다.

## 이 프로그램이 하는 일

사장님이 SystemCloud 를 처음 쓰신다. **생산/외주를 쓰려면 무엇을 어떤 순서로 등록해야 하는지**를
한 화면에 박스로 보여 준다.

1. **로그인** (`login.js`) — 복잡한 로그인 화면 대신 아이디·비밀번호 칸만 보여 준다.
   입력값을 원래 칸(`#txtLoginId`·`#inputLoginPwd`)에 넣고 원래 로그인 단추(`#btnLogin`)를 누른다.
   **아이디·비밀번호를 어디에도 저장하지 않는다.** 3초 안에 안 넘어가면 원래 화면을 되돌려 보인다.
2. **안내 화면** (`guide.js`·`guide.css`) — 로그인 뒤 원래 화면을 숨기고(`html.vp-guide-on`)
   단계별 **정사각형 박스**만 보인다. 제목 옆 「↻ 새로고침」 은 페이지를 새로 불러온다.
   - 박스 = `STEPS` 한 줄. 순서와 이름은 **SystemCloud 실제 메뉴 그대로** 다
     (도입 › STEP1 거래처/품목/물류 초기설정 → STEP2 구매/수입·생산/품질 → STEP3 초기잔액 및 재고설정
     → 생산/외주 › 외주계약 → 실제 업무).
   - 박스를 누르면 창이 뜬다: **SystemCloud 현재 상태 · 할 일 · 양식(칸 목록, 내려받기, 올리기)**.
   - 박스 딱지: `등록됨`(초록) · `비어 있음`(빨강) · `확인 안 함`(회색). 양식 종류: `실제 양식` · `정리용 양식` · `화면 입력`.
3. **양식 내려받기** — SystemCloud 에 **이미 등록된 자료를 채워서** 내려준다 (사장님이 시키신 것, 10-13).
   - `실제 양식` = `templates/Rpt*.xlsx` (SystemCloud 업로드 화면의 「양식다운로드」 에서 받은 원본 8개).
     입력 시트 1줄은 항목코드, 2줄은 칸 이름, **3줄부터 자료**. 예시 줄은 지우고 채운다.
   - `정리용 양식` = 업로드 기능이 없는 화면(창고·워크센터·공정·공정흐름유형·품목별공정흐름유형·외주계약)의
     칸 이름으로 만든 엑셀. **SystemCloud 에 바로 올릴 수 없다** — 정리용이다. 칸 끝 `*` 은 필수 칸.
4. **작성한 파일 올리기** — 칸이 양식과 맞는지만 보고(실제 양식은 1줄 항목코드로 비교) 표로 보여 준다.
   **이 브라우저(chrome.storage.local `vpGuideUpload{번호}`)에만 둔다. SystemCloud 에 등록하지 않는다.**

## 기존 자료를 읽는 길 (`sc-read.js`, MAIN world)

SystemCloud 의 조회 요청(`/api/WebApi`)은 **암호화**돼 있다(`{k, a}`). **풀지 마라.**
대신 SystemCloud 자신의 화면을 써서 읽는다:

1. `Home.OpenPageSeq(프로그램번호)` 로 화면을 연다 (이미 열려 있으면 그 화면으로 간다).
   화면마다 `#{번호}_iframe` 이 생긴다 (같은 출처라 들여다볼 수 있다).
2. 그 화면의 AngularJS scope 에서 `scope._base.ExpExecuteToolbarEvent("Query")` — **「조회」 단추와 같다.**
   (`scope.Query()` 를 바로 부르면 `sendXml` 오류가 난다. 단추 `<a>` 를 `.click()` 해도 안 먹는다.)
3. 목록 시트 요소(`SS`·`SS1` 등)의 `GetAllData().Tables[0]` → `Columns`(항목코드)·`Rows`.
   **목록의 항목코드가 업로드 양식 1줄의 항목코드와 같다** (`WHName`·`ItemName`·`CustName` …).
   그래서 실제 양식은 같은 코드끼리 맞추고, 다른 것만 `ALIAS` 에 적는다.

`guide.js` 는 `window.postMessage({vpg:"read", id, seq, sheet, clear})` 로 부탁하고
`{vpg:"readResult", id, columns, rows | error}` 를 받는다.

## 무엇보다 먼저

- **SystemCloud 에서는 조회만 한다.** 저장·업로드·삭제·행삭제·「미등록공정 가져오기」·「소요자재가져오기」·
  「구매단가생성」 같은 단추는 **누르지 않는다.** 시키셔도 사장님이 직접 누르시게 한다.
- **비밀번호를 대신 넣지 않는다.** 로그인은 사장님이 하신다.
- **「현재 상태」 글(`STATE`)은 손으로 적은 것이다** — `CHECKED` 날짜에 각 화면을 조회해서 본 숫자다
  (창고 19 · 거래처 173 · 품목 1040 · 품목별공정흐름유형 552 · 워크센터 8 · 공정 2 · 공정흐름유형 2 ·
  구매단가 0 · 기초재고 없음(원장·엣지 재고 마이너스) · 외주계약 AMT 499건 미등록). 자동으로 바뀌지 않는다.
  새로 확인했으면 `STATE` 와 `CHECKED` 를 함께 고친다. **확인 안 한 것을 확인한 것처럼 적지 않는다.**
- 순서·메뉴 이름·양식 칸은 **실제 SystemCloud 화면에서 보고** 정한다. 짐작으로 만든 칸을 「실제 양식」 이라 하지 않는다.

## 배포 (변경할 때마다 같이 — 사장님이 「기본사항」 이라 하셨다)

1. `manifest.json` 의 `version` 을 올린다.
2. 이 폴더를 저장소 `vivivic-apps/시스템클라우드보기/` 로 맞춘다.
3. **`시스템클라우드보기.zip` 을 다시 만든다** (폴더 통째로, `.DS_Store` 빼고). 설치 안내의 「압축파일 받기」 가 이것이다.
4. 커밋·푸시. 사장님 컴퓨터 원본은 `~/Desktop/시스템클라우드보기` 다 (크롬이 거기서 읽는다).

⚠ 저장소 `.gitignore` 가 `*.xlsx` 와 `*.md` 를 막는다. 그래서 `templates/` 는 **zip 에만** 들어간다
(폴더만 받아 깔면 실제 양식 내려받기가 안 된다). 이 `CLAUDE.md` 는 `git add -f` 로 올린다.

## 시험할 때

- 확장 파일은 브라우저 미리보기로 못 연다. 코드 고친 뒤에는 사장님이 `chrome://extensions` 에서 ↻ 를
  누르셔야 반영된다 — 그 전 화면을 보고 「됐다」 하지 마라.
- 양식 채우기는 node 로 `templates/` 를 읽어 시험할 수 있다 (`XLSX.write(book,{type:"buffer"})` 로 쓴다.
  `cellStyles: true` 로 읽으면 파일이 15KB → 1.8MB 로 부푼다 — 쓰지 않는다).
- **가려진 탭에서는 `setTimeout` 이 1분에 한 번꼴로 늦춰진다.** 그래서 `sc-read.js` 는 탭이 가려져 있으면
  MessageChannel 로 기다린다. 크롬 도구로 페이지 안에서 `await` 로 오래 기다리면 도구가 멈춘다 —
  시작만 시키고 결과는 다음 호출에서 읽는다.
