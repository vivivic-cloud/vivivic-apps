# 서류관리 앱스 스크립트에 **더해** 주실 것 — 보링변환이 파일 속을 받는 길

> ## ⛔ 지금은 이것을 넣지 않아도 됩니다 (10-05 접어 둠)
>
> 이 쪽지를 쓴 뒤에 **뿌리가 따로 밝혀졌습니다.** 문이 안 열린 까닭은 스크립트에
> 길이 없어서가 아니라 **보링변환이 부르던 주소가 어긋나 있어서**였습니다.
> 서류관리 스크립트는 `doGet` 이 돌 때마다 `ensureUrl_()` 로 **제 주소를 스스로**
> `docs_config/sync` 의 `url` 에 적고 있었고, 보링변환은 사람이 적는
> `boring_config/설정` 의 `exec` 를 보고 있었습니다. 둘이 다른 값이었습니다.
>
> **보링변환이 `docs_config/sync` 를 먼저 읽도록 고쳤습니다(v1.12.0).**
> 그러면 지금 있는 `doPost` 길이 그대로 삽니다 — 여기 적힌 함수도 시계도 필요 없습니다.
>
> **아래는 접어 둡니다.** 주소가 또 어긋나거나 CORS 로 막히는 날, 그때 꺼내 보십시오.
> (보링변환 쪽에는 창고를 거치는 길이 이미 들어가 있어, 그날에도 이 쪽지만 넣으면 됩니다.)

---

보링변환(폰 화면) 쪽은 이미 다 되어 있습니다. **여기 적힌 것 하나만 더해지면 연결됩니다.**

> ⚠ **지금 있는 길은 한 톨도 건드리지 마십시오.** `doGet`·`doPost`·훑기 함수·
> `boring_files` 를 쓰는 자리 — 그대로 둡니다. **새 함수 하나와 시계 하나를 더하는 것**뿐입니다.

## 왜 이렇게 하나

지금은 보링변환이 `exec` 주소로 **POST 해서 답을 읽으려** 합니다. 그런데
브라우저가 그 답을 못 읽습니다(배포 주소가 바뀌거나, 로그인 화면으로 튕기거나,
답에 브라우저가 쓸 수 있다는 허락(CORS)이 없으면 그 자리에서 막힙니다).

**훑기는 이미 이 문제를 피해 가고 있습니다** — 답을 돌려주는 게 아니라
**파이어스토어에 직접 써 넣기** 때문입니다. 속 가져오기도 같은 길로 보내면 됩니다.
그러면 주소가 또 바뀌어도, 로그인으로 튕겨도 안 깨지고, 사장님 손도 안 갑니다.

## 주고받는 자리

    artifacts/vivivic-4b7ef/public/data/boring_requests/<driveId>

보링변환이 적는 것 (이미 됩니다 — 이름없는 손님으로 적고 읽히는 것 확인했습니다):

```json
{ "driveId": "1FtgbL-…", "상태": "기다림", "빈때": 1791185285442 }
```

앱스 스크립트가 **같은 자리에** 써 넣을 것:

```json
{ "상태": "됨",  "name": "거실장_도어형_1001_01.cix", "b64": "<파일 속을 base64 로>", "답한때": 1791185290123 }
```

못 가져왔으면:

```json
{ "상태": "못함", "why": "볼 폴더 밖의 파일입니다", "답한때": 1791185290123 }
```

### 꼭 지켜야 하는 것

1. **`답한때` 를 반드시 넣습니다.** 보링변환은 `답한때 < 빈때` 인 것은 **지난번 답으로 보고
   버립니다.** 안 넣으면 답이 와도 화면이 계속 기다립니다.
2. `b64` 는 파일 바이트를 그대로 base64 로. 보링변환이 `TextDecoder('utf-8')` 로 풉니다.
3. **볼 폴더(`boring_config/설정` 의 `folder`) 밖이면 주지 않습니다.** 지금 POST 쪽이
   하는 그 검사 그대로입니다 — `why` 는 아무 말이나 괜찮습니다. 글자 그대로 화면에 뜹니다.
4. 파이어스토어 한 칸은 **1MB** 까지입니다. 그보다 크면
   `{ 상태:'못함', why:'파일이 너무 큽니다', 답한때 }` 로 적어 주십시오.
5. 답을 적은 뒤 **하루쯤 지난 것은 지워** 주십시오(`boring_requests` 가 계속 불어납니다).

## 무엇이 이 함수를 돌리나 — **시계(시간 기반 트리거)로 해 주십시오**

보링변환이 주소를 두드려서 깨우는 길은 **믿을 수 없습니다.** 그 두드림은 답을 안 읽는
`no-cors` GET 이라, 스크립트가 실제로 돌았는지 **화면에서 알 길이 없습니다.**

실제로 잰 것입니다:

- `boring_files` 300개가 **전부 2026-09-30T06:18:35.6Z 한 순간에 쓰였고, 그 뒤로 한 번도
  안 쓰였습니다.** 사장님이 10-02·10-04·10-05 에 화면을 여셨고 그때마다 두드림이 나갔는데도요.
- 다만 그 사이 드라이브에 **새 `.cix` 가 생기지도 않았습니다.** 그래서 「훑기가 멈췄다」 고
  단정하지는 못합니다 — 바뀐 것만 쓰는 구조면 안 쓰이는 게 맞습니다.
  **어느 쪽인지 지금 밖에서는 가릴 수 없습니다.**

그래서 **두드림에 기대지 않는 쪽**으로 해 주십시오:

- **1분마다 도는 시간 기반 트리거**를 하나 겁니다(`ScriptApp.newTrigger(...).timeBased().everyMinutes(1)`).
- 그 함수는 `boring_requests` 에서 `상태 == '기다림'` 인 것만 집어 답을 적습니다.
  **훑기는 하지 않습니다** — 드라이브를 통째로 훑는 건 값이 드니 지금 길 그대로 두십시오.
- 기다릴 것이 없으면 아무 일도 안 하고 끝냅니다(거의 언제나 이쪽입니다).

이렇게 하면 **주소도, 로그인도, CORS 도 끼어들 자리가 없습니다.**

## 덧붙여 — 돌고 있는지 밖에서 보이게

지금 「스크립트가 살아 있나」 를 아무도 못 봅니다. 위 함수가 돌 때마다 한 줄만 적어 주시면
다음부터는 바로 알 수 있습니다:

    artifacts/vivivic-4b7ef/public/data/boring_config/심장   ←  { "때": <지금 ms> }

## 보링변환 쪽은 이미 이렇게 되어 있습니다

- 줄을 누르면 ① 지금처럼 POST 로 곧장 묻고(되면 제일 빠릅니다) ② 막히면 **곧바로**
  `boring_requests` 에 적고 그 자리를 듣습니다.
- 180초까지 기다리고, 기다리는 동안 「파일을 가져오는 중입니다 (N초)」 만 보입니다.
- **사장님께 시키는 말은 한 마디도 없습니다.**

시험으로 끝까지 재 두었습니다(`보링변환/tests/bpp1.mjs`) — 앱스 스크립트 자리에
허수아비를 세워 ①곧장 길이 막혀도 들어오는 것 ②`exec` 주소가 **아예 없어도** 들어오는 것
③묵은 답을 안 집는 것 ④`상태:'못함'` 의 `why` 가 그대로 뜨는 것을 다 잽니다.
**위 두 가지(함수 + 시계)만 더해지면 바로 연결됩니다.**
