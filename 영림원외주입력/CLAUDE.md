# 영림원외주입력 — 이 집에서 지킬 것

영림원 ERP 테스트서버(아이앤지퍼니처 TEST)에 생산외주 자료를 등록하기 전에,
사람이 단계별로 입력해 두는 폼이다. 나중에 에이전트가 이 폼에 쌓인 것을 읽어 ERP에 넣는다.

> 영림원 입력 작업자는 `입력작업자/AGENTS.md` 부터 읽는다(`영림원외주입력/입력작업자/AGENTS.md`).

> ⚠ **외부 프로그램(영림원 등) 화면에 맞추는 작업은 반드시 실제 작동 화면을 직접 열어 확인한 뒤 한다.** 표는 오른쪽 끝·아래 끝까지 밀어 모든 칸을 보고, 칸 이름은 화면 글자 그대로 옮긴다. 화면에서 못 본 칸·값은 넣지 않고 「확인 못 함」으로 보고한다. 기록·추측·화면 밖 데이터로 칸을 만들지 않는다. (2026-10-31 사장님 지시 「빨리 바꾸고 다음부터 이런작업 할때는 무조건 실제 작동화면 확인하고 하는것을 깃에 남겨 모든작업자가 유념하도록 해줘」 — 워크센터 원가센터·칸 이름 잘못 사례)
> 이 폼의 칸(`STEPS`)·양식 열·`erp-spec.json` 을 영림원에 맞춰 고칠 때도 같다 — 먼저 영림원 화면을 열어 본다.
> ⚠ **영림원에 넣을 때는 저장 전에 넣은 모든 행의 모든 칸(오른쪽 끝 비고까지)을 폼 값과 한 칸씩 대조하고, 폼에 없는 칸에 값이 있으면 저장하지 않는다. 저장 뒤 조회로 다시 대조한다.** (10-31 T이룸 워크센터 비고에 「T로앤」이 잘못 들어간 사례 — `입력작업자/AGENTS.md` 3-4)

## 파일
- `영림원외주입력.html` — 폼 한 장짜리. 파이어베이스 SDK 는 열 때 불러온다(못 불러와도 화면은 뜬다).
- `erp-spec.json` — 에이전트가 읽는 규격. 단계 순서 · ERP 메뉴 경로 · 화면에서 누를 순서 · 항목 대응표 · 필수 항목 · 확인 못 한 것.
  **폼의 `STEPS`·`ROUTES` 를 고치면 이 파일도 같이 다시 뽑는다**(아래 「규격 다시 뽑기」).

## 저장소 (파이어스토어)
- 프로젝트 `vivivic-4b7ef`, 익명 로그인 — 다른 앱들과 같다.
- 컬렉션은 **`erp_` 로 시작하는 것만** 쓴다: `erp_vendors` `erp_workcenters` `erp_classes`(v25 분류) `erp_items` `erp_materials`(v25 자재) `erp_processes` `erp_flows`(v19 — v20 부터 4단계 「공정·공정흐름」 화면이 `erp_processes` 와 함께 씀) `erp_boms` `erp_itemflows`(v48) `erp_contracts` + **`erp_imports`**(v23 영림원에서 불러오기 요청).
  **기존 업무 기록 컬렉션(`confirmed_orders` 등)은 건드리지 않는다.**
- 문서마다 `status`(대기 → 진행중 → 완료 | 오류, v34 4 품목·v40 3 분류 수정은 완료 → 수정대기 → 진행중 → 완료 | 오류) · `agentNote` · `createdAt` · `route`(ERP 메뉴 경로) 가 붙는다.
  행이 있는 단계(`erp_flows`, `erp_boms`, `erp_contracts`)는 `rows` 배열에 행을 담는다.
- 에이전트는 `status` 가 대기인 문서를 단계 순서대로 읽고, 처리한 뒤 `status`·`agentNote` 를 고친다.

  행 있는 단계(BOM·외주계약)는 **엑셀 한 줄 = 행 하나**, 머리 칸은 처음 나오는 값. 행 없는 단계는 한 줄이면 칸에 채우고, **여러 줄이면 줄마다 한 건**(v7, 아래). 빈 칸은 기본값을 그대로 둔다. **저장은 안 누른다**(채우기만).
  체크 칸은 O·V·Y·예·1·TRUE 면 체크, 거래처종류는 종류1~4 네 열(v9)과 예전 한 열(쉼표로 여럿) 모두 받는다. 날짜(이름이 `일` 로 끝나는 칸)는 엑셀 날짜 숫자·`2026.3.5` 를 `2026-03-05` 로.
  CSV 는 UTF-8(구글 스프레드시트) 로 읽고 깨지면 EUC-KR(한글 엑셀) 로 다시 읽는다.
- **필수 별표 (v4, 10-30)** — 사장님 말씀 「다운로드 양식에 각 입력에 필수 입력양식인 별표를 표시해줘」.

  필수(별표) 칸 — **v9 에서 늘었다(아래 「드롭다운 칸 필수」가 지금 목록)**. v4 때: 1 거래처 = 상호·거래처명 / 2 워크센터 = 사업단위·워크센터·생산부서·워크센터구분·외주거래처(사외외주일 때만, `reqIf`)·Capa산정구분·시작일 /
  3 품목 = 품명·품번·품목자산분류·기준단위·품목소분류 / 4 공정 = 공정명 / 5 BOM = 모품목명·모품목번호·모품목BOM차수·하위품명·하위품번·투입단위·소요량(분자)·소요량(분모) /
  6 외주계약 = 사업단위·외주거래처·공정차수·공정·통화·정산기준·외주단가·적용시작일.
  ⚠ 칸의 `req` 를 바꾸면 화면 별표·저장 검사·양식 별표·`erp-spec.json` 의 `required` 가 같이 바뀐다(규격은 다시 뽑아야 함). 양식 머리를 만들 때 `f.label` 대신 `labs` 를 쓰므로 열 너비도 `labs` 기준.
- ⚠ 외주계약은 머리 「사업단위」와 행 「단위」가 **같은 키 `unit`** 이다. 업로드에서 키로 가르면 섞인다 → 칸(필드 객체)으로 가른다. `rowFs.indexOf(f)` 를 키 비교로 바꾸지 말 것.
- ⚠ 품번을 엑셀에 `00123` 처럼 적으면 엑셀이 앞 0 을 지운다(양식 칸을 글자 서식으로 만들지는 않았다).
- 시험법: `connectDb` 를 `Promise.resolve(null)` 로 바꾼 복사본을 로컬 서버로 열고(파이어베이스 안 나감), `URL.createObjectURL` 을 가로채 양식 Blob 을 받은 뒤(v6 부터 `writeFile` 대신 `saveFile`) 값을 채워 `DataTransfer` 로 파일 칸에 넣는다.

## 사업자등록증 업로드 (v5, 10-30) — 1단계 거래처만

  1. PDF → pdf.js 3.11.174(cdnjs, 작업지시서와 같은 판)로 **글자층**을 꺼낸다. 홈택스에서 받은 PDF 처럼 글자층이 있으면 OCR 보다 정확하다(글자 그대로).

  법인/개인 ← 글에 법인사업자·법인등록번호·법인명 → 법인, 일반·간이·면세과세자·개인사업자·생년월일 → 개인, 둘 다 없으면 사업자번호 가운데 두 자리 81~88 → 법인.

- 시험(10-30, 가짜 이름·번호로 만든 견본, 가짜 저장소 복사본): ① 글자층 PDF(법인, 크롬 인쇄) 7칸 모두 맞음 ② 기울이고 흐린 사진 jpg(개인) 7칸 모두 맞음

## 8단계 저장 뒤 비우기 · 화면 겹침 (v52, 11-04)
- 사장님 말씀: 「저장이 끝나면 이전 불러온 목록 깨끗이 비우고 다음 제품 선택할 수 있게 해줘야지. 한번 뭔가 저장되면 뭔가 화면 구성이 이상해져.」
- **화면이 이상해진 원인(재현함)**: 저장 뒤 줄은 「흐름 추가」 단추가 없어진다. 그 단추(`display:flex`)가 드롭다운과 상태 칩을 위아래로 갈라 주고 있었는데, 단추가 없으면 칩이 드롭다운 옆 같은 줄로 붙어 칸 밖으로 밀려 **「원장 공정」 칸 글자를 덮었다**. 겸해서 줄 높이가 107→52 로 줄어 표가 437px 짧아지고 아래 상품검색이 위로 튀었다. 고침: `.ifbox select{display:block}`. 품번을 못 이은 빨간 줄도 같은 까닭이라 함께 고쳐진다. 시험은 칸 안 요소가 칸 밖으로 나가는지 줄마다 잰다.
- **저장 다 되면**(`clearAll` + `fn.again`): 표·안내 상자·상품검색(고른 값·부속 카드)을 비우고 `last` 도 지워 같은 상품을 다시 고를 수 있다. 검색 방법은 쓰던 대로 두고 그 검색 칸에 초점, 화면은 알림 줄로 올린다. 알림은 `out`(pslink) 한 줄 「N건 저장했습니다. 다음 상품을 고르세요.」.
- `onPick.again`(psBox): `push()` 로 다시 연 뒤 틀 안 `selectSearchMethod`. ⚠ `열기` 는 검색 방법 칸을 숨기기만 해서 그대로 두면 검색 칸이 안 보인다. 공용 부품(`shared/발주상품고르기*`)은 안 고쳤다(조혼가구와 같이 씀).
- **저장 안 한 줄이 있을 때**(흐름 안 고름·품번 못 이음): 비우되 알림에 「저장 안 한 줄 N개는 상품을 다시 고르면 나옵니다」를 붙인다. 말없이 사라지지 않게.
- **일부 실패**: 비우지 않고 실패한 줄만 남긴다. 상태 「저장 실패」+이유(`r.fail`), 「모두 저장」하면 그 줄만 다시 가고 다 되면 비운다. 줄이 줄어 표가 화면 밖으로 나가지 않게 표로 올린다. 저장 전 검사(`freshCheck`) 실패는 그대로 안 비운다.
- 문서 칸·`erp-spec.json` 안 바뀜.
- 시험(11-04, v50 과 같은 틀 · 진짜 쓰기 0 · 영림원 없음 · 저장 실패는 가짜 저장소 `add` 거절): 1280·375 수납장 4개 끝까지 「고름 → 줄마다 기대값·칸 겹침 없음 → 저장 → 다 비워짐·초점」, **18건 18품번**, 문서 칸 8개, 넘침 0, 콘솔 오류 0 · 같은 상품 다시 고름 · 직접 검색 방법 유지·초점 뒤 바로 타자 · 8줄 중 2줄 실패 → 2줄 남음·이유 → 다시 저장 8건·비워짐 · 안 고른 줄 알림·다시 고르면 나옴 · 6단계 갔다 돌아옴 · BOM 고르기 그대로.

## 함정 — 건드리면 안 되는 자리
- ⚠ **시험은 진짜 파이어베이스로 나간다.** 이 환경에서도 `gstatic`·`googleapis` 가 열려 있어, 가짜를 제대로 못 걸면
  시험 문서가 **진짜 `erp_` 컬렉션에 쓰인다**(10-30 에 실제로 한 건 쓰였다가 지웠다). 시험은 브라우저에서
  `https://www.gstatic.com/firebasejs/**` 를 **`https://www.gstatic.com` 으로 시작하는 정규식**으로 가로채 가짜 SDK 를 주고,
  그 밖의 바깥 요청은 모두 막은 채 돌린다. (`**/gstatic.com/**` 글롭은 `www.` 때문에 안 걸린다.)
- `STEPS` 의 각 단계에는 `title`(문자열, 단계 이름)이 있다. 기록 한 건의 제목을 만드는 함수는 **`recTitle`** 이다.
  같은 이름을 두 번 쓰면 뒤의 것이 덮어써서 화면에 코드 조각이 나온다(10-30 에 있었던 일).
- 파일이 외부에서 읽는 값(저장소에서 온 문서)은 **전부 `textContent`/DOM 으로만** 그린다. `innerHTML` 로 바꾸지 않는다.
- 이 저장소는 공개다. 이 폴더에는 서버 주소(`inghometest.ksystemace.com`)·기존 외주처 이름 6곳·ERP 메뉴 구조가 들어 있다(사장님이 공개 저장소에 올리기로 하셨다).
  **비밀번호·계정·실제 거래 자료는 절대 넣지 않는다.**

## 알아낸 것
- (v43) `showBulk` 는 단계에 `name` 칸이 있다고 여겼다(BOM 은 없어 깨짐) — 이름 칸이 다른 단계는 `nameK` 를 단다. 「모두 저장」은 입력 칸 `collect` 를 안 거치니 행 필수·빈 행은 `bulkState`·`bulkRows` 가 본다. iframe(상품검색) 아래로 `scrollIntoView` 를 `smooth` 로 하면 끊긴다.
- (v42) 엑셀 이어지는 드롭다운은 「줄마다 후보를 수식으로 펼친 숨긴 시트 + 줄마다 dataValidation」 이 옛 엑셀·구글 둘 다 무난(INDIRECT·이름 정의 없음). 실제 엑셀 확인은 `osascript` 로 Microsoft Excel 을 열어 값 넣고 `calculate` 뒤 읽으면 된다(저장은 샌드박스로 막힘, 「복구할까요」 창이 뜨면 AppleEvent 가 멈춤 — `with timeout` 을 걸 것). 손으로 만든 공유 수식(`t="shared"`) xlsx 는 엑셀이 손상으로 봤다.
- (v41) 칸 안내 글을 상황 따라 바꿀 땐 `api.setHint(글, placeholder)` — 칸 정의 `hint` 는 엑셀 머리 메모에도 들어가니 두 경우(제품·자재)를 다 담아 두고, 화면만 고른 품목구분에 맞춰 바꾼다.
- (v40) 분류 문서는 소분류 한 줄이라 대·중분류 이름은 여러 문서에 겹쳐 있다 — 이름을 고칠 땐 `clsPlan` 으로 묶어 한 트랜잭션(`db.updateAll`)으로 쓴다. 같은 대·중 찾기는 `ylwCode` 우선(영림원 이름이 겹칠 수 있음), 품목·자재 `small` 은 경로 글자라 같이 바꿔야 드롭다운·`clsErr` 가 안 깨진다.
- (v38) 상품검색 안내의 「있음」은 폼 기록(status)만 본다. 영림원에서 불러온 분류 이름은 「대_중_소」 꼴(T리빙룸_T수납장_T올화이트)이라 소분류를 이름 끝(「_T색상」)으로 찾는다. `replaceChildren` 에 배열을 그대로 넘기면 「[object HTMLDivElement]」 글자가 된다 — `h('div',{},배열)` 로 감쌀 것.
- (v37) 4 품목 목록은 검색어가 있어야 카드가 나온다. 목록을 다시 그릴 때 `listBox.replaceChildren` 로 검색칸까지 갈아 끼우지 말 것 — 치는 중 초점이 날아간다(`listSearch` 는 제목 줄만 바꿈).
- (v35) 셀 표 붙여넣기는 상자(`.sheetbox`)의 paste 를 받아 `e.target` 의 data-id·data-k 로 시작 칸을 잡는다. select 는 편집 칸이 아니라 브라우저가 paste 를 안 줄 수 있다 — 글 칸에서 시작하면 늘 된다.
