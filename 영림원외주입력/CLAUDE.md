# 영림원외주입력 — 이 집에서 지킬 것

영림원 ERP 테스트서버(아이앤지퍼니처 TEST)에 생산외주 자료를 등록하기 전에,
사람이 단계별로 입력해 두는 폼이다. 나중에 에이전트가 이 폼에 쌓인 것을 읽어 ERP에 넣는다.

## 파일
- `영림원외주입력.html` — 폼 한 장짜리. 파이어베이스 SDK 는 열 때 불러온다(못 불러와도 화면은 뜬다).
- `erp-spec.json` — 에이전트가 읽는 규격. 단계 순서 · ERP 메뉴 경로 · 화면에서 누를 순서 · 항목 대응표 · 필수 항목 · 확인 못 한 것.
  **폼의 `STEPS`·`ROUTES` 를 고치면 이 파일도 같이 다시 뽑는다**(아래 「규격 다시 뽑기」).

## 저장소 (파이어스토어)
- 프로젝트 `vivivic-4b7ef`, 익명 로그인 — 다른 앱들과 같다.
- 컬렉션은 **`erp_` 로 시작하는 6개만** 쓴다: `erp_vendors` `erp_workcenters` `erp_items` `erp_processes` `erp_boms` `erp_contracts`.
  **기존 업무 기록 컬렉션(`confirmed_orders` 등)은 건드리지 않는다.**
- 문서마다 `status`(대기 → 진행중 → 완료 | 오류) · `agentNote` · `createdAt` · `route`(ERP 메뉴 경로) 가 붙는다.
  행이 있는 단계(`erp_boms`, `erp_contracts`)는 `rows` 배열에 행을 담는다.
- 에이전트는 `status` 가 대기인 문서를 단계 순서대로 읽고, 처리한 뒤 `status`·`agentNote` 를 고친다.

## 엑셀 양식 받기 · 올리기 (v2, 10-30)
- 단계마다 안내 문구 아래에 **「양식 다운로드」 · 「엑셀 업로드」** 버튼. 함수: `downloadTemplate` · `uploadSheet` · `readBook` · `cellVal`, 폼 쪽은 `buildForm` 의 `fill(head,rowVals)`.
- SheetJS `https://cdn.sheetjs.com/xlsx-0.20.3/...` 를 **누를 때만** 불러온다(이 저장소 다른 앱들과 같은 판). 파일은 브라우저 밖으로 안 나간다.
- 양식 = 시트 하나(이름 = 단계 이름), 1행 = 열 이름 = **화면 칸 이름 그대로**(머리 칸 + 행 칸 순서). 파일명 `외주입력_<번호>_<단계>_양식.xlsx`.
  1 거래처: 상호,거래처명,거래처상태,국내외구분,신용등급,법인/개인,사업자번호,대표자성명,전화번호,업태,종목,거래처종류
  2 워크센터: 사업단위,워크센터,생산부서,워크센터구분,외주거래처,Capa산정구분,시작일,종료일,자재출고창고,제상품출고창고,납품창고,현장창고
  3 품목: 품명,품번,규격,영문명,품목자산분류,품목상태,기준단위,품목소분류,내외자구분,중요도,대표품목
  4 공정: 공정명,특이사항,공정검사여부
  5 BOM: 모품목명,모품목번호,모품목규격,모품목BOM차수 | 공정,표시순서,하위품명,하위품번,하위규격,하위BOM차수,투입단위,소요량(분자),소요량(분모),하위유무
  6 외주계약: 사업단위,외주거래처 | 제품명,제품번호,공정차수,공정,외주품명,외주품번,단위,통화,정산기준,부가세포함여부,외주단가,적용시작일
- 올리기: .xlsx/.xls/.csv. 시트는 단계 이름 시트가 있으면 그것, 없으면 첫 시트. 위 10줄 안에서 열 이름이 하나라도 맞는 줄을 머리로 본다(띄어쓰기·앞뒤의 `*` 무시, 열 순서 상관없음, 모르는 열은 버림).
  행 있는 단계(BOM·외주계약)는 **엑셀 한 줄 = 행 하나**, 머리 칸은 처음 나오는 값. 행 없는 단계는 한 줄이면 칸에 채우고, **여러 줄이면 줄마다 한 건**(v7, 아래). 빈 칸은 기본값을 그대로 둔다. **저장은 안 누른다**(채우기만).
  체크 칸은 O·V·Y·예·1·TRUE 면 체크, 거래처종류는 쉼표로 여럿. 날짜(이름이 `일` 로 끝나는 칸)는 엑셀 날짜 숫자·`2026.3.5` 를 `2026-03-05` 로.
  CSV 는 UTF-8(구글 스프레드시트) 로 읽고 깨지면 EUC-KR(한글 엑셀) 로 다시 읽는다.
- **필수 별표 (v4, 10-30)** — 사장님 말씀 「다운로드 양식에 각 입력에 필수 입력양식인 별표를 표시해줘」.
  `downloadTemplate` 이 열 이름 뒤에 `*` 를 붙인다(화면 `lab()` 과 같은 꼴·같은 기준: 칸 정의의 `req` 또는 `reqIf`). 올리기는 `normHead` 가 **앞·뒤** `*` 와 띄어쓰기를 떼고 맞추므로 별표 양식·예전 양식·`* 상호` 꼴 모두 된다.
  필수(별표) 칸: 1 거래처 = 상호·거래처명 / 2 워크센터 = 사업단위·워크센터·생산부서·워크센터구분·외주거래처(사외외주일 때만, `reqIf`)·Capa산정구분·시작일 /
  3 품목 = 품명·품번·품목자산분류·기준단위·품목소분류 / 4 공정 = 공정명 / 5 BOM = 모품목명·모품목번호·모품목BOM차수·하위품명·하위품번·투입단위·소요량(분자)·소요량(분모) /
  6 외주계약 = 사업단위·외주거래처·공정차수·공정·통화·정산기준·외주단가·적용시작일.
  ⚠ 칸의 `req` 를 바꾸면 화면 별표·저장 검사·양식 별표·`erp-spec.json` 의 `required` 가 같이 바뀐다(규격은 다시 뽑아야 함). 양식 머리를 만들 때 `f.label` 대신 `labs` 를 쓰므로 열 너비도 `labs` 기준.
- ⚠ 외주계약은 머리 「사업단위」와 행 「단위」가 **같은 키 `unit`** 이다. 업로드에서 키로 가르면 섞인다 → 칸(필드 객체)으로 가른다. `rowFs.indexOf(f)` 를 키 비교로 바꾸지 말 것.
- ⚠ 품번을 엑셀에 `00123` 처럼 적으면 엑셀이 앞 0 을 지운다(양식 칸을 글자 서식으로 만들지는 않았다).
- 시험법: `connectDb` 를 `Promise.resolve(null)` 로 바꾼 복사본을 로컬 서버로 열고(파이어베이스 안 나감), `URL.createObjectURL` 을 가로채 양식 Blob 을 받은 뒤(v6 부터 `writeFile` 대신 `saveFile`) 값을 채워 `DataTransfer` 로 파일 칸에 넣는다.

## 디자인 (v3, 10-30) — 에이엠티·조혼가구와 같은 모양
- 사장님 말씀: 「디자인을 비비빅에 배포된 프로그램들의 디자인 일관성에 맞게 수정해줘」. **CSS·머리띠 마크업·단추 아이콘만** 바꿨다. 기능 코드는 그대로.
- 판 번호는 파일 맨 위 주석과 머리띠 `VIVIVIC` 옆 배지(`.ver`)에 같이 있다. 고칠 때 둘을 같이 올린다(지금 v8 — v4 는 양식 별표, v5 는 사업자등록증 업로드, v6 은 목록 칸 드롭다운, v7 은 여러 줄 업로드, v8 은 구글시트 양식 받기·올리기).
- 가져온 값(새로 지은 값 없음):
  - 색·글꼴: 두 집 `body` — 흰 바탕, 글자 `#37352f`, 흐린 글자 `#787774`, 테두리 `#ededeb`/`#e3e2e0`, 채움 `#f1f1ef`·`#f5f5f4`·`#f7f6f3`·`#fbfbfa`, Inter. **밝은 테마만**(옛 어두운 테마 지웠다).
  - 머리띠 `.topbar`: 두 집 `<header>`(흰 바탕·아래 줄·높이 64·`font-black text-xl tracking-tighter` VIVIVIC·9px 판 배지).
  - 단계 줄 `nav button`: `.nav-link`(활성 = `#f1f1ef` + 안쪽 테두리). 카드·입력칸·단추: 두 집 로그인 카드(`rounded-2xl`)·입력칸(`rounded-lg`, 초점 `#37352f`)·단추(`#37352f` 굵게).
  - 표 `.tw table`: 에이엠티 `.tl-wo-table`(머리 `#f5f5f4`·800 굵기 `#787774`·칸줄 `#f0eeec`). 스크롤바: `.custom-scrollbar`(`#d3d1cb`).
  - 아이콘: lucide 선 아이콘 원자료 경로를 `ICONS`/`ico()` 에 적어 단추 안에만 쓴다(`shared/lucide.min.js` 를 싣지 않는다 — 조혼가구와 같은 방식).
- 표는 한 종류뿐(기록 펼침 안의 행 표). 가로 넘침은 `.tw` 상자 안에서만, 상자 높이를 `60vh` 로 묶어 가로 스크롤바가 늘 화면 안에 있다. 375 폭에서 문서 너비 375(넘침 없음) 잼.
- ⚠ `html`/`body` 에 `overflow-x:hidden` 을 걸지 않았다 — 넘침을 숨기면 재지 못한다. 넘치면 원인 칸을 고친다.
- ⚠ 폰(≤480)에서 단계 카드 안 단추 넷(양식 다운로드·엑셀 업로드·구글시트 양식·구글시트 업로드)은 두 줄로 반씩 선다(`.card>.actions .btn{flex:1 1 calc(50% - 4px)}`, v8).
  1단계 거래처만 다섯째 단추 「사업자등록증 업로드」(`.btn.cert`)가 있어, 폰에서는 그것만 `flex-basis:100%` 로 아랫줄 한 줄을 쓴다(v5). 구글시트 링크 줄(`.gsrow`)도 한 줄 전체.
- 확인: 가짜 저장소 복사본으로 1280·375 화면, 5단계 양식 다운로드(열 14개) → 채운 엑셀 업로드(2행 채움), `?viggle=1&box=youngrim` 으로 열림.

## 사업자등록증 업로드 (v5, 10-30) — 1단계 거래처만
- 사장님 말씀: 「거래처 입력에 사업자등록증 업로드 할 수 있는 버튼 만들어줘 사업자등록증은 피디에프 혹은 사진 파일 일 수 있고 업로드 되면 파일을 스캔해서 파악된 내용이 해당 페이지 입력에 맞는 내용으로 채워지도록 해줘」
- 거래처 카드의 「엑셀 업로드」 옆 **「사업자등록증 업로드」** 단추(아이콘 `scan`). 받는 파일: PDF · 사진(jpg/png/heic 등, `accept` = `application/pdf,.pdf,image/*,.heic,.heif`).
  함수: `uploadCert`(흐름) · `certLines`(파일 → 글 줄) · `pdfLines`/`pdfCanvas`/`photoCanvas`/`ocrCanvases` · `parseCert`(글 → 칸 값) · `loadScript`.
- **읽는 방식과 고른 까닭**: 저장소에 OCR·AI 읽기·Claude/파이어베이스 함수 같은 서버 쪽 읽기는 **없다**(작업지시서가 pdf.js 로 PDF 를 그림으로 뜨는 것뿐). 키·비밀값 없이 되는 **브라우저 안 읽기**로 했다. 파일은 밖으로 안 나간다.
  1. PDF → pdf.js 3.11.174(cdnjs, 작업지시서와 같은 판)로 **글자층**을 꺼낸다. 홈택스에서 받은 PDF 처럼 글자층이 있으면 OCR 보다 정확하다(글자 그대로).
     글자층에 `000-00-00000` 꼴이 없으면 스캔 PDF 로 보고 1~2쪽을 그림으로 떠서 2번으로.
  2. 사진·스캔 PDF → tesseract.js 5.1.1(jsdelivr) **한국어(`kor`)** OCR. 긴 변 ≈2400px 로 키워 읽는다. 처음 한 번 한국어 자료(약 수 MB)를 받느라 오래 걸린다(이후 브라우저 저장).
  3. HEIC 은 사파리 말고는 못 연다 → 못 열 때만 heic2any 0.0.4(jsdelivr)를 불러 JPG 로 바꾼다.
  도구 셋 다 **누를 때만** 불러온다(엑셀 SheetJS 와 같은 방식).
- **칸 매핑**(화면에 있는 칸만. 주소·개업일 칸은 화면에 없어 안 채운다):
  상호·거래처명 ← 「법인명(단체명)」 또는 「상호」 값(둘 다 같은 값) / 사업자번호 ← `000-00-00000` 꼴 숫자(검증숫자 맞는 것 우선) /
  대표자성명 ← 「대표자」 또는 「성명」 / 업태 ← 「업태」 뒤 ~ 「종목」 앞 / 종목 ← 「종목」 뒤 (여러 줄이면 `, ` 로 잇는다) /
  법인/개인 ← 글에 법인사업자·법인등록번호·법인명 → 법인, 일반·간이·면세과세자·개인사업자·생년월일 → 개인, 둘 다 없으면 사업자번호 가운데 두 자리 81~88 → 법인.
  칸 이름은 글자 사이 띄어쓰기를 무시하고 찾는다(「대 표 자」). 값은 같은 줄에서 다음 칸 이름 앞까지.
- 채운 칸은 `form.fill(got,[])` 로 넣는다(엑셀 업로드와 같은 길). 못 읽은 칸은 손대지 않고 안내에 「못 읽은 칸(…)은 직접 입력」. **저장은 사람이 누른다.**
- 시험(10-30, 가짜 이름·번호로 만든 견본, 가짜 저장소 복사본): ① 글자층 PDF(법인, 크롬 인쇄) 7칸 모두 맞음 ② 기울이고 흐린 사진 jpg(개인) 7칸 모두 맞음
  ③ 글자층 없는 스캔 PDF(150dpi) — 6칸 맞고 사업자번호 한 자리 틀림(214→224) → 검증숫자로 잡아 「사업자번호가 틀린 번호로 읽혔습니다」 안내가 뜬다. 1280·375 화면 넘침 없음.
- ⚠ 정확도 한계: OCR 은 흐리거나 기울거나 그림자 진 사진에서 글자를 틀린다(특히 숫자 한 자리·이름 한 글자). 칸 이름(「업태」 등)을 못 읽으면 그 칸은 빈다.
  업태·종목이 **표처럼 여러 줄**(둘째 줄부터 칸 이름 없이 값만)이면 첫 줄만 들어간다. 정확도가 모자라면 그때 서버 쪽 AI 읽기를 검토(키는 서버에만).
- ⚠ pdf.js 그리기는 `intent:'print'` 로 한다 — 화면용은 requestAnimationFrame 을 써서 창이 가려지면(폰에서 다른 앱으로 넘어가면·미리보기 창이 숨으면) 멈춘다.
- ⚠ Chrome 이 만든 PDF 는 글자층 조각에 제어문자(`\u0001`)가 끼고 한 글자씩 조각난다 → `pdfLines` 가 조각 사이 간격으로 붙이고 `parseCert` 가 제어문자를 지운다. 이 둘을 빼면 「주 식 회 사」·대표자 못 찾음이 된다.
- ⚠ 사업자번호 찾는 정규식에 `(?<!\d)`(lookbehind)를 쓰지 않는다 — 옛 아이폰 사파리에서 문법 오류로 **앱 전체가 안 뜬다**. `(^|\D)` 로 대신했다.

  - 올리려는 시트는 **링크 공유를 켜야** 읽힌다(로그인 없이 읽기 때문). 켜는 동안 링크를 아는 사람은 그 시트를 볼 수 있다 — 다 올린 뒤 꺼도 된다.
  - 받기 양식의 **앞 단계 자료 목록 드롭다운(외주거래처·공정·품번)** 은 엑셀처럼 받는 순간의 저장소 값이 아니다. 양식을 만들 때(가짜 저장소, 목록 비어 있음) 값이라 **외주계약의 외주거래처(기존 6곳)·공정(조립·가공)처럼 폼 코드에 고정된 목록만** 들어 있고,
    워크센터의 외주거래처·BOM 하위품번 등은 드롭다운 없이 직접 적는다. 최신 목록이 꼭 필요하면 엑셀 양식을 쓴다.
  - 양식 시트 6장은 사장님 소유. 직원이 사본을 만들려면 양식 시트(또는 폴더)를 「링크가 있는 모든 사용자 · 뷰어」로 사장님이 켜 주셔야 한다(드라이브 연결 도구로는 「모든 사용자」 공유를 못 켠다). 사장님 본인은 그대로 된다.
  - 폼의 칸·목록(`STEPS`·`opts`·별표)을 바꾸면 **구글시트 양식은 저절로 안 바뀐다** → 엑셀 양식을 받아 다시 변환해 같은 폴더에 올리고 `GS_TEMPLATES` ID 를 바꾼다(아래 함정).
- ⚠ 함정: 구글 변환은 SheetJS 가 만든 xlsx 를 그대로 올리면 **워크센터 양식만 첫 시트가 빈 채로** 바뀌었다(두 번 같음, 원인 모름). 테마·docProps·metadata 를 뺀 작은 xlsx 로 올리니 됐다.
  양식을 다시 만들면 올린 뒤 꼭 CSV 로 내려받아(드라이브 `export text/csv`) 1행 열 이름이 있는지 본다.
- 시험(10-31, 가짜 저장소 복사본): 6단계 「구글시트 양식」이 6개 `/copy` 주소를 연다 · 견본 CSV(별표 머리·`2026. 11. 1` 날짜·목록 밖 외주거래처)로 워크센터 채움 →
  날짜 `2026-11-01`, 외주거래처 「직접 입력」+값 · 거래처 2줄 → 일괄 업로드 목록 버튼 2개 · BOM 2행 채움 · 진짜 공개 견본 시트(구글 예제)는 「열 이름을 찾지 못했습니다」 · 공유 안 된 실제 시트(양식 원본)·없는 시트는 공유 안내 · 링크 아닌 주소는 「구글시트 링크가 아닙니다」 · 375 폭 넘침 없음.
  **실제 거래 자료로는 시험하지 않았다.**

## 단계 순서 (앞 단계가 뒤 단계의 재료다)
거래처 → 워크센터(외주거래처로 거래처를 고른다) → 품목 → 공정 → BOM(엑셀 업로드 양식) → 외주계약(단가는 계약 화면 안에서 입력)

## 규격 다시 뽑기
`STEPS`·`ROUTES`·`SPEC` 을 고친 뒤, 폼의 `<script>` 안에서 `var F=function` 부터 `window.__erpSpec=SPEC;` 앞까지를
함수로 감싸 `SPEC` 을 돌려받아 `erp-spec.json` 으로 저장한다.

## 함정 — 건드리면 안 되는 자리
- ⚠ **시험은 진짜 파이어베이스로 나간다.** 이 환경에서도 `gstatic`·`googleapis` 가 열려 있어, 가짜를 제대로 못 걸면
  시험 문서가 **진짜 `erp_` 컬렉션에 쓰인다**(10-30 에 실제로 한 건 쓰였다가 지웠다). 시험은 브라우저에서
  `https://www.gstatic.com/firebasejs/**` 를 **`https://www.gstatic.com` 으로 시작하는 정규식**으로 가로채 가짜 SDK 를 주고,
  그 밖의 바깥 요청은 모두 막은 채 돌린다. (`**/gstatic.com/**` 글롭은 `www.` 때문에 안 걸린다.)
- `STEPS` 의 각 단계에는 `title`(문자열, 단계 이름)이 있다. 기록 한 건의 제목을 만드는 함수는 **`recTitle`** 이다.
  같은 이름을 두 번 쓰면 뒤의 것이 덮어써서 화면에 코드 조각이 나온다(10-30 에 있었던 일).
- 파일이 외부에서 읽는 값(저장소에서 온 문서)은 **전부 `textContent`/DOM 으로만** 그린다. `innerHTML` 로 바꾸지 않는다.
- 이 저장소는 공개다. 이 폴더에는 서버 주소(`inghometest.ksystemace.com`)·기존 외주처 이름 6곳·ERP 메뉴 구조가 들어 있다(사장님이 공개 저장소에 올리기로 하셨다).
  **비밀번호·계정·실제 거래 자료는 절대 넣지 않는다.**

## 알아낸 것
- ERP 화면에서 **실제로 열어 본 것**: 거래처등록 · 워크센터등록 · 품목등록 · 공정등록 · BOM등록업로드 · 외주계약등록.
- **아직 못 본 것**: 공정흐름유형 · 품목별공정흐름유형 화면, 통화·정산기준·품목자산분류 드롭다운의 전체 선택지,
  거래처종류 표의 아래쪽 항목, BOM 엑셀 양식의 정확한 열 이름, 각 화면의 저장 동작과 오류 문구.
  → 폼에서는 이런 칸을 직접 입력 칸으로 두었다(v6 부터 목록 칸은 드롭다운 + 「직접 입력」). 에이전트가 처음 돌 때 확인해서 `erp-spec.json` 의 `unverified` 를 채운다.
- ERP 외주계약등록은 **외주거래처 = 워크센터** 기준이다. 서버에 이미 있는 외주 워크센터: 아인가구 · AMT · 경기산업 · 조혼가구 · 럭스디자인 · 진아산업.
  서버에 이미 있는 공정: 조립 · 가공.
- 품목등록·거래처등록·외주계약등록에는 업로드가 없다(건별 입력). **업로드가 있는 것은 BOM 뿐**이다.
  (이 폼의 「엑셀 업로드」는 ERP 업로드가 아니라 **폼 칸을 채우는 것**이다. 10-30 사장님 지시로 6단계 모두에 달았다.)
