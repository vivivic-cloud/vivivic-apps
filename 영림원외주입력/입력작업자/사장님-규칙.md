# 사장님이 정한 업무 규칙

새 말씀이 규칙이 되면 바로 여기에 날짜와 함께 더한다. 이 파일과 말씀이 다르면 말씀이 맞다 — 이 파일을 고친다.

## 공정 (10-31)
- 공정 = **재단 · 엣지 · 보링 · 조립**.
- NC 공정 업체 = 아래 표(11-04).

## 공정별 외주 업체 (10-31)
| 공정 | 업체 |
|---|---|
| 재단 | AMT · 경기산업(=경기재단) · 조혼가구 |
| 엣지 | 이룸산업 · 조혼가구 · AMT |
| 보링 | 로앤디자인 · 조혼가구 · AMT (AMT 는 11-04 말씀 「보링 워크센터에 에이엠티가 안나타나요」) |
| 조립 | AMT · 조혼가구 · 아인가구 · 진아산업 · 럭스디자인 |
| NC | AMT · 조혼가구 · 진아산업 (11-04 말씀) |

- 입력폼 9단계(v55) 드롭다운이 이 표를 쓴다(`WC_RULE`). 표에 없는 공정(곡면엣지·포장 등)은 등록된 워크센터 전부. 표를 바꾸면 폼도 고친다.
- 공정마다 **기본 업체**를 두고, **주문마다 업체를 바꿀 수 있어야** 한다.
- 「경기재단」은 영림원에 없고 「경기산업」이 같은 곳이다.
- 실제 업체는 8곳(AMT·경기산업·조혼가구·이룸산업·로앤디자인·아인가구·진아산업·럭스디자인).

## 공통부속 기준 (10-31)
- 다음이 **모두 같으면 같은 부속**: 원장명 · 마감 · 마감색상 · 재단W · 재단D · W엣지면 · D엣지면.
- 같은 부속은 품목 하나로 만들고 여러 제품 BOM 에서 나눠 쓴다.

### 엣지필름 (11-04)
- 소요량 = 부속당 ((재단W × W엣지면 + 재단D × D엣지면) ÷ 1000 + 0.04) × 1.02 M(말씀 「(세팅으로 나온 값+40mm)*2%  로 부속당 계산」, 40mm 는 부속당 한 번 · 2% 는 여유분). 엣지 가공비는 나중에 외주계약 단가로 다룬다.
- 필름은 부속마다 다를 수 있다(말씀 「이건 부속마다 옵션이 다를 수 있음을 인지하고 작업해야 합니다」).
- 말씀 「테스트 자료를 입력하면서 논리를 찾을거니까 이전 작업의 논리를 참고하지마」 · 「기존에 등록된 엣지필름 관련 영림원의 데이터를 사용하지 않을 예정 입니다. 모든 데이터는 테스트 데이터를 새로 입력 하면서 작업합니다.」 · 「기존거 수정하는것보다 논리를 새로 만드는게 편하니까 그런 부분은 참고하지마」 — 기존 영림원 엣지필름 품목·BOM 을 쓰거나 맞추지 않는다. T 자료로 새로 넣는다.
- 말씀 「엣지필름은 매입해서 가공업체에 보내주는겁니다」 — 자재 등록과 BOM T엣지 줄로 재고·소요량을 잡는다.

### 공통부속 단서를 부속 정보에 둔다 (11-01 — 칸·꼴은 미정)
- 사장님 말씀(11-01): 「일단 깃에 공통부속 입력을 위한 단서를 부속정보 어딘가에 갖고있어야 한다는 메모를 해놔」 (바로 앞 「내가 만드는 입력폼이 이런것 때문인거야」).
- 영림원 품목등록에는 「공통부속」 표시 칸이 **없다**(11-01 확인 범위). 공통부속은 같은 품번이 여러 제품 BOM 에 들어가는 것으로만 드러난다(BOM 역전개).
- 그래서 **부속 정보(입력폼 품목/부속 자료) 어딘가에 공통부속임을 알 수 있는 단서를 꼭 갖고 있어야 한다.** 예: 공통부속 묶음 번호 · 쓰는 제품 목록 · 7항목 기준 키(원장명·마감·마감색상·재단W·재단D·W엣지면·D엣지면).
- **어떤 칸·어떤 꼴로 둘지는 미정.** 후보: 품번 규칙 · 폼 전용 칸 · 영림원 품목기타분류·추가정보(저장 뒤 켜지는 칸 — 확인 못 함).
- 판정 기준: 사장님 7항목(원장명·마감·마감색상·재단W·재단D·W엣지면·D엣지면)이 모두 같으면 같은 부속.

## 부속의 공정 판단 (10-31)
- 시트의 **재단부속코드 · 엣지부속코드 · 보링부속코드** 칸에 값이 있으면 그 공정을 거친다.

## 테스트 꼬리표 (10-31)
- 테스트로 만드는 자료는 **이름 앞에 `T`** (예: `TAMT`, `T조혼가구`).
- 기존 자료는 건드리지 않는다.

## 테스트 품목·자재는 모두 T 를 붙여 새로 (11-01 말씀)
「테스트 등록이 므로 모든것을 T를 붙여 새로 등록할 거야」
- 테스트 품목·자재(제품·반제품·원장·철물 **모두**)는 영림원 기존 자료(알렉스 제품 4개 R-al12h 등 · 알렉스 부속 162개 · 원자재 71개)를 **쓰지 않는다**. 이름 앞에 `T` 를 붙여 **새로** 등록한다.
- 기존 자료는 값의 꼴(품목자산분류·소분류·단위·규격 표기 등)을 **참고하는 데만** 쓴다(고치거나 BOM 에 걸지 않는다).

## 자재 대·중·소 분류 (11-03 말씀)
「자재 대중소 분류를 다시 지정합니다. T보드-T엘피엠-T201양면 입니다」
- 자재(품목구분 「자재」) 분류 = **대분류 보드 종류 · 중분류 마감 · 소분류 색상/규격**. 예: `T보드 > T엘피엠 > T201양면`. (⚠ 소분류는 11-03 말씀으로 바뀜 — 아래)
- 11-03 말씀: 「자재 대분류가 보드일때 중분류는 자재의 마감이 무엇인지를 명시합니다. 소분류는 중분류로 분류된 자재의 거래처에서 사용하는 제품콛드를 사용합니다. 이 입력규칙을 해당 입력에 안내가 되게 해주세요」
  - **대분류 = 보드**(테스트 T보드)일 때: **중분류 = 그 자재의 마감**(T엘피엠 — LPM·라미날 등) · **소분류 = 그 마감 자재를 공급하는 거래처가 쓰는 제품코드**(T201양면).
  - 입력폼 v41 이 3 분류(품목구분 자재)·5 자재 자재소분류·엑셀/구글시트 양식 머리 메모에 이 규칙을 안내한다(막지는 않음).
- 위 단계 이름을 앞에 붙여 잇지 않는다(제상품 규칙과 같음).
- 11-02 에 넣은 옛 자재 분류 `T원자재 > T판재 > T화이트`(2006005/2005019/2004064)는 지우거나 고치지 않는다. 어떻게 할지는 사장님이 정하신다.
- ⚠ 11-03 확인: 영림원 화면에서 대분류 2006005 이름이 이미 「T보드」로 저장돼 있었다. 중 2005019(→T엘피엠)·소 2004064(→T201양면)는 화면에 고친 채 저장 안 된 상태였다. 작업자가 한 일이 아니다.

## 품목 대·중·소 분류 — 바뀜 (11-01 말씀, 아래 옛 규칙 대신)
「아니 대중소 분류 다르게 정했어 T리빙룸/T수납장/T올화이트 이렇게」
- 테스트 제품 분류 = **대분류 `T리빙룸` · 중분류 `T수납장` · 소분류 `T올화이트`**(품목구분 「제상품」). 위 단계 이름을 앞에 붙여 잇지 않는다.
- 「대중소 분류 내가 직접 입력했다 T리빙룸 T수납장 T올화이트」 — **사장님이 영림원 품목대중소분류정의에 직접 넣으셨다**(폼 거치지 않음, 코드는 화면 확인 못 함).
- 뜻: **대분류 = 공간(리빙룸 …) · 중분류 = 제품 종류(수납장 …) · 소분류 = 상품색상(올화이트 …)**. (아래 옛 「대 = 제품 종류, 중 = 시리즈」 대신)
- **소분류 = 제품정보 시트의 「상품색상」 열 값**은 그대로. 상품색상(올화이트 등)은 제품에만 있는 속성 — 부속 이름의 색은 마감색상(예: 화이트).
- 그래서 같은 소분류 이름(T올화이트)이 여러 중분류 밑에 생길 수 있다 → 입력폼 v26 은 품목·자재 소분류를 「대분류 > 중분류 > 소분류」 경로로 고른다.
- 11-01 작업자가 영림원에 만든 대분류 **T수납장(2003015)** 은 옛 규칙으로 만든 것 — 지울지·둘지는 사장님이 정하신다(지우지 않음).

## (옛) 품목 대·중·소 분류 (11-01 말씀 — 위 「바뀜」으로 대신함)
「그럼 티등록에 대한 대 중 소 분류를 T수납장-T수납장알렉스-T수납장알렉스올화이트 이렇게 해서 등록해 보자」
- **대분류 = 제품 종류**(수납장·서랍장·거실장·옷장·테이블 …) · **중분류 = 시리즈**(알렉스·토리 …) · **소분류 = 제품 색상**(올화이트 …).
- 이름은 위 단계 이름을 앞에 붙여 잇는다: 테스트는 `T수납장` → `T수납장알렉스` → `T수납장알렉스올화이트`(품목구분 「제상품」).
- 한 분류에 여러 제품을 넣어도 된다. 소분류 색상은 **제품 색상과 같은 것만** 넣는다. 테스트 제품 4개는 모두 올화이트.
- 11-01 덧붙임 「내가 보낸 제품정보의 상품색상 열이 소분류가 되면 된다고 , 부속에는 올화이트 라는 구분은 없어 올화이트는 모드 제품의 색상속성이야」
  - **제품 소분류 = 제품정보 시트(「영림원 예시」 등)의 「상품색상」 열 값**(예: 올화이트 → `T수납장알렉스올화이트`).
  - 「올화이트」 같은 상품색상은 **제품에만 있는 속성** — 부속(반제품)에는 쓰지 않는다. **부속 이름의 색은 마감색상(예: 화이트)을 그대로** 쓴다.
  - 이번에 등록하는 `T수납장 > T수납장알렉스 > T수납장알렉스올화이트` 는 **제품용**이다.
- **아직 미정**: 부속을 어느 분류에 넣을지. 자재 분류는 아직 등록하지 않는다.

## 사업자번호 (10-31 말씀 「고쳐줘」 — 폼 v12)
- 사업자번호는 **숫자 10자리**. 하이픈은 넣어도 빼도 되고, 폼은 `000-00-00000` 꼴로 저장한다. 10자리가 아니면 폼이 저장을 막는다.
- 거래처종류에 **외주가공 · 국내매입 · 국내매출**이 하나라도 있으면 사업자번호 **필수**(영림원이 요구).
- 검증숫자가 틀린 번호는 경고만 하고 저장은 된다.
- 사업자번호는 실제 자료다 — 작업자가 지어 넣지 않는다. 틀린 대기 자료는 사장님이 폼에서 고치신다.

## 워크센터 외주거래처 (10-31 말씀 — 폼 v14)
「워크센터 입력양식  외주거래처에 기존 저장된 외주거래처가 드롭다운 목록으로 나와야 되는거 아니냐 등록이 안된 업체명은 이곳에 입력할 수 없는거잖아」
- 워크센터 외주거래처는 **영림원에 등록된 외주가공 거래처만**. 폼 목록 = 1단계 거래처 중 거래처종류에 외주가공이 있고 상태 「완료」인 것.
- 폼은 목록 밖 이름을 저장하지 않는다. 그래도 대기 워크센터의 외주거래처가 영림원 거래처조회에 없으면 넣지 말고 오류 + agentNote.
- 영림원에 원래 있던 외주거래처(아인가구·AMT 등)는 폼 목록에 없다(가져올지는 사장님이 정하신다).

## T워크센터 창고 (10-31 사장님 결정 — 폼 v15)
- T워크센터의 창고(자재출고·제상품출고·납품·현장·생산입고·생산입고(반제품))는 **모두 그 워크센터와 같은 이름의 창고**.
- 업체 사이 이동은 **자재이동**으로 한다(납품창고를 다른 업체로 잡지 않는다 — 기존 AMT·경기산업의 예외 꼴을 따르지 않음).
- 폼은 이 값을 자동으로 채우지 않는다(사람이 넣음). 워크센터등록 화면에 원가센터 칸은 없다(10-31 관리 방이 실제 화면으로 확인).

## 공정흐름 (11-01 말씀 — 폼 v19 공정흐름유형 단계)
「영림원의 공정흐름유형등록에 맞는 셀 양식을 다시 작성되게 해줘야되는거 아니야?」
- 부속마다 공정 순서(흐름)가 정해져 있다. 사장님이 드신 흐름 예(폼에 미리 넣지는 않음):
  재단 / 재단→엣지 / 재단→엣지→보링 / 재단→NC / 재단→엣지→NC / 재단→NC→곡면엣지 / 재단→NC→곡면엣지→엣지 / NC멤브레인 /
  재단→엣지→보링→NC→곡면엣지 / 재단→NC→곡면엣지→보링 / 재단1→엣지1→재단2→엣지2 / 재단1→엣지1→재단2→엣지2→보링.
