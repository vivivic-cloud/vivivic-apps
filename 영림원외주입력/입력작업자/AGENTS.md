### 3-0. 날짜 지난 화면 쓰지 않기 (11-08)
영림원 입력 화면 일자 칸은 **화면을 연 날** 값이고 「신규」로도 안 바뀐다. 날짜가 바뀐 뒤 저장할 때는 탭을 닫고 다시 연다(`ylw.reopen(화면번호)`). 폼에 날짜 칸이 없어 기본값으로 저장되는 칸(501617 외주발주일 · 501613 외주납품일 · 500940 출고일 · 501125 · 501563 · 501568 · 501576 · 501054 · 501060 · 501065 · 501067 · 501071)은 오늘인지 읽고 아니면 저장하지 않는다. 칸 ID = `화면별-요령.md` 「날짜 지난 화면」. 폼 값을 넣게 정해진 칸(`reqdate`·`dlvDate`·`podate`·`bldate` 등)은 각 절 그대로(이 칸들에 현재일을 쓸지는 사장님 말씀 없음 — 확인 필요).

### 3-3. 수정대기 처리 (품목 v34 · 자재 v92 · 분류 v40 · 흐름 v53)
폼에서 완료 건을 「수정」하면 `status` 수정대기(`edit` = changed·before·after). ⛔ **신규를 누르지 않는다** — 이미 있는 것을 고치는 일.
- 공통 순서: 다시 읽어 아직 수정대기인지 → 진행중 → 코드로 조회 → 화면 값이 `edit.before` 와 같은지(다르면 고치지 말고 오류 + 영림원 값) → **`edit.changed` 칸만** `edit.after` 로 → 저장 전후 모든 칸 대조 → 완료 · `edit` null · `editLog` 끝에 완료 줄. 실패면 오류, `edit` 그대로.
- **자재(3-3-자재)**: 바뀐 칸이 이미 `edit.after` 와 같으면 저장하지 않고 대조만 → 완료(「영림원 이미 같음」). ⚠ 수정 첫 건은 화면을 보며(500251 저장 뒤 내외자구분 수정은 시험 전). 번호가 바뀐 건(`edit.ref`)은 BOM·소요자재 줄 대조만, 영림원에서 고치지 않는다. 불러온 문서·두 문서로 있는 같은 자재를 작업자가 지우거나 합치지 않는다.
- **분류(3-3-분류)**: 수정대기 문서 **하나만** 영림원에서 처리(따라 바뀐 문서는 손대지 않음). 같은 단계는 수정대기를 대기보다 먼저. 502365 에서 `ylwCode` 로 찾는다. ⚠ 이미 있는 분류명을 고쳐 저장되는지는 확인 못 함.
- **흐름(3-3-흐름)**: 상세가 비었는지 보고, 줄이 있으면 고치지 않고 오류. `ylw.flow.fillRows`·`verifyRows`(`fillHeads` 안 씀). 공정 먼저.
- ⚠ 수정대기 중 불러오기를 돌리면 「영림원과 다름」이 붙을 수 있다 — 끝낸 뒤 다시 비교.
- 자세히 = 절차 원문 「3-3.」「3-3-자재.」「3-3-분류.」「3-3-흐름.」.

- **`erp_proddlvs` 새 꼴(`all:true`, v171~v175)**: 공정·업체 묶음마다 한 건. 같은 `prodId` 는 **줄 `seq` 차례로 앞 공정부터**(앞 공정 문서가 없으면 「앞 공정 납품 대기」로 기다림). 줄마다 501610 「외주납품」 → 501613 외주납품일·수량 → 저장 → `dlvNo`(입고 저절로 → `inNo`). `moveKind` 가 있으면(폼 v214 부터는 `wh` 없는 옛 생산 줄만 — `wh` 가 있으면 폼이 출고 칸을 비운다) **다음 줄 납품 전에** 500938 → 500940 자재출고(입고창고 `toWc`, 재공품 줄 출고창고 `wc`, 금회출고 = `dlvQty`) → `outNo`. 원장·필름은 여기서 옮기지 않는다. 「현재고가 부족하여」면 그 줄에서 멈추고 오류. ⏳ 한 문서 여러 줄을 한 번에 넣을지·완성 부속 조립업체 출고는 첫 건 화면 보며.

## 4. 지켜야 할 규칙
- ⛔ **비밀번호를 넣지 않는다.** 로그인 화면이면 멈추고 「사장님 로그인 필요」.
- **로그인을 기다릴 때는 혼자 다시 본다(11-10 사장님).** 알린 뒤 차례를 끝내지 말고 1분마다 그 탭을 다시 읽어 로그인되면 바로 이어 간다. 30분이 지나도 로그인 화면이면 그때 멈추고 다시 알린다.
- ⛔ **기존 자료를 고치거나 지우지 않는다.** 새 행만 만든다. 삭제·행삭제·덮어쓰기·업로드는 사장님께 먼저 묻는다(예외: 폼의 **수정대기** 문서의 바뀐 칸만 — 3-3·3-4).
- **저장 전에 확인한다.** 값이 다르면 저장하지 않는다.
- **사장님 말씀이 우선이다.** 이 문서와 말씀이 다르면 말씀을 따르고 이 문서를 고친다.
- **시킨 것만 한다.** 시키지 않은 화면·자료는 보기만 하고 보고. 한 단계가 끝나면 관리자가 「다음」을 줄 때까지 멈춘다.
- 테스트 자료는 이름 앞에 `T`(`사장님-규칙.md`).
- ⛔ 공개 저장소 — **비밀번호·계정·실제 거래 자료(사업자번호 등)·실제 재고 값은 깃에 적지 않는다.** 이름·코드·화면 사실만.
- ⚠ **실제 운영 전에 영림원 → 폼 일괄 불러오기를 해야 한다**(단계마다 「영림원에서 불러오기」, 3-2).
- 영림원에 **직접** 넣은 자료(폼을 거치지 않은 것)가 생기면 `작업일지.md` 에 바로 적는다(무엇을·어느 화면·코드/이름).
- 참고: 영림원 환경설정 「하위 반제품 생산계획 완료예정일 설정」 3 → 0 (11-08 사장님 허락, 되돌리는 값 3 — `../CLAUDE.md` 지금 차례).

## 5. 기록하는 법
- 채팅에만 남은 사실은 다음 작업자가 못 본다. **알아낸 것은 그 자리에서 파일에 적는다.**
- `작업일지.md`: 맨 위에 `## YYYY-MM-DD 한 줄 제목` → 한 일 · 만든 자료(화면·이름·코드 표) · 막힌 점 · 배운 점. **날이 바뀌면 그저께 이전 절은 `../보관/작업일지/YYYY-MM.md` 맨 위로 옮긴다**(작업일지에는 오늘·어제만).

- 낡은 설명은 지우지 말고 고친다(왜 바뀌었는지 일지에). 커밋 메시지는 한국말 한 줄.
