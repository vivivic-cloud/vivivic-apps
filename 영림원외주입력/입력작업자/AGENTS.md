이 문서는 특정 AI 전용이 아니다. Claude·ChatGPT·Gemini·RPA·사람 누구든 이 폴더만 읽고 일을 이어받을 수 있게 쓴다.

> 🔐 **저장소 로그인(11-09, 폼 v127) — 폼 저장소(erp_*)는 익명으로 못 읽고 못 쓴다(규칙 배포 뒤).** 입력 작업자는 붙박은 익명 계정 하나를 쓴다. 비밀번호 없음.

> 🚩 **막히면 폼에 바로 보고한다. 폼만 보고도 무엇을 고칠지 알 수 있게 적는다.** 영림원 저장이 막히거나 대조가 틀리면 그 문서 `status` 오류 + `agentNote` 에 줄을 나눠 적는다: ① 어느 단계에서 막혔나 ② 영림원 문구 그대로 ③ 까닭(화면에서 본 값) ④ 여기까지 된 것과 번호 ⑤ 사장님이 고칠 것 ⑥ 폼에서 지금 못 하는 것(코드 수정이 필요한 것) ⑦ 같은 까닭으로 멈춘 다른 문서. 영림원 문구만 옮겨 적지 않는다. 같이 멈춘 대기 문서에도 까닭을 적는다. 채팅 보고는 그다음이다. (2026-11-07 사장님 「이런 상황이 오면 폼에 바로 보고해서 수정해야 될 부분이 나타나도록 깃에 메모 남기고 지금 상황 폼만 보고도 뭘 수정해야 알 정도로 해줘」)

> 🔑 **영림원은 새 탭을 열기 전에 이미 로그인된 탭이 있는지 먼저 찾아 그 탭을 쓴다. 새 탭은 꼭 필요할 때만 열고, 일이 끝나면 닫는다. 로그인 화면이 나오면 사장님께 새로 로그인을 부탁하기 전에 다른 로그인된 탭부터 확인한다.** (2026-11-01 사장님 「로그인했는데 니네가 이런식으로 로그인 해달라고 해서 이미 로그인되어 있는 화면도 세개나 더있다」) — 크롬 새 탭은 로그인이 이어지지 않는다(11-01 세 번 겪음). 사장님이 보고 계신 화면은 건드리지 않는다. 탭을 닫을 때는 저장 안 한 내용이 없는 것만, 사장님이 쓰실 로그인된 탭 하나는 꼭 남긴다.

> ⚡ **화면에 스크립트가 있으면 먼저 스크립트로 넣는다. 없는 화면은 처음 넣을 때 손으로 하고, 끝나면 그 화면 스크립트를 만들어 푸시한다. 화면이 바뀌어 스크립트가 틀리면 고쳐서 푸시한다.** 목록·쓰는 법·한계 = `스크립트/README.md`. (2026-11-01 사장님 「각 입력마다 채우기 스크립트에 대한 정보를 깃에 저장해서 작업자가 확인하고 빠릿하게 작업할 수 있도록 만들어줘」)

> ⚠ **외부 프로그램(영림원 등) 화면에 맞추는 작업은 반드시 실제 작동 화면을 직접 열어 확인한 뒤 한다.** 표는 오른쪽 끝·아래 끝까지 밀어 모든 칸을 보고, 칸 이름은 화면 글자 그대로 옮긴다. 화면에서 못 본 칸·값은 넣지 않고 「확인 못 함」으로 보고한다. 기록·추측·화면 밖 데이터로 칸을 만들지 않는다. (2026-10-31 사장님 지시 「빨리 바꾸고 다음부터 이런작업 할때는 무조건 실제 작동화면 확인하고 하는것을 깃에 남겨 모든작업자가 유념하도록 해줘」 — 워크센터 원가센터·칸 이름 잘못 사례)

> 🧭 **작업 흐름에 필요한 확인·불러오기·등록은 입력폼 안에서 끝나게 만든다.** 사장님이 다른 단계로 옮겨 다니지 않게 한다. 사장님 말씀(글자 그대로, 2026-11-07): 「「자재 등록 먼저」 이런 상황일때 팝업으로 자재를 등록 할 수 있게 해달라는 이런 흐름에 맞는 작업을 직관적으로 할 수 있게 해달라는거야 - 그럼 자재등록이 된건지 안된건지 먼저 확인해야 할테니 영림원에서 등록된자재를 불러오기도 해야 하고 확인할것이 많잖아 그런 모든 액션을 이 입력폼에서 할 수 있게 해보자는거야」

## 3. 일하는 순서 (한 건마다)
1. **대기 자료 읽기** — 파이어스토어(프로젝트 `vivivic-4b7ef`, 익명 로그인) 컬렉션 `erp_vendors` → `erp_workcenters` → `erp_classes`(폼 v25 분류) → `erp_items` → `erp_materials`(폼 v25 자재) → `erp_processes` → `erp_flows` → `erp_boms` → `erp_itemflows`(폼 v48) → `erp_itemmats`(폼 v57) → `erp_itemwcs`(폼 v55, ⚠ 공정차수 없는 품목은 넣지 말고 오류 — 화면별-요령 500865 · 중간 공정은 `erp_materials` 재공품 완료 뒤, 3-6) → `erp_contracts` → `erp_imporders` → `erp_imppays` → `erp_impinvs` → `erp_impbls`(폼 v74 수입BL) → `erp_impins`(폼 v74 수입입고) → `erp_purprices`(폼 v78) → `erp_purchases` → `erp_purdelvs`(폼 v80 원장 구매, 3-10) → `erp_prods` → `erp_proddlvs` → `erp_prodmoves`(폼 v81 생산 관리, 3-11) 순서. 같은 단계 안에서는 `createdAt` 오름차순. `status` 가 `대기` 인 것만.
   - 앞 단계에 대기·수정대기·오류가 남아 있으면 뒤 단계는 건너뛰고 `agentNote` 에 이유를 적는다(영림원에 이미 있는 자료는 예외).
   - 사장님이 채팅으로 직접 시키신 일(예: T 테스트)은 폼을 거치지 않을 수 있다. 그때도 아래 2~5 를 똑같이 한다.
2. **진행중으로 바꾸기** — 시작하면 `status` = `진행중`.
   - ⚠ 사람이 폼에서 대기·오류 건을 지울 수 있다(v13 「선택 삭제」·「대기·오류 모두 삭제」). 처리 직전(진행중으로 바꾸기 전) 그 문서가 아직 있는지·아직 `대기` 인지 다시 읽어 확인한다 — 없으면 건너뛴다. 진행중·완료 건은 폼에서 안 지워진다.
3. **영림원 입력** — 그 화면 스크립트가 있으면 스크립트로(`스크립트/README.md`), 없으면 `화면별-요령.md` 의 그 화면 요령대로. 먼저 **조회해서 같은 이름이 이미 있는지** 본다. 있으면 새로 만들지 않는다.
4. **저장 전 확인 → 저장 → 조회로 확인**
   - 붙여넣기·입력 뒤 저장하기 전에, **넣은 모든 행의 모든 칸(오른쪽 끝 비고까지)을 화면에서 폼 값과 한 칸씩 대조한다.** 폼에 없는 칸에 값이 들어가 있으면 저장하지 않는다.
   - 저장 뒤 조회로 **다시 한 칸씩 대조**한다(행이 생겼는지만 보지 않는다).
   - 사례(10-31): 워크센터 여러 줄 붙여넣기 때 T이룸 행 「비고」에 다음 줄 첫 글 「T로앤」이 들어간 채 저장됐다. 코드 칸만 보고 비고를 안 봐서 놓쳤다(사장님 말씀 「이런일이 없도록 입력폼 깃에 기록해두고 해당 작업을 할때 확인하도록 해줘」).
5. **상태 바꾸기** — 됐으면 `완료`, 안 됐으면 `오류` + `agentNote` 에 화면에서 본 오류 문구 그대로.
6. **기록** — `작업일지.md` 에 적고, 새로 안 화면 사실은 `화면별-요령.md` 에, 사장님 말씀 중 규칙이 될 것은 `사장님-규칙.md` 에. 커밋·푸시.

### 3-0-미등록. 폼 드롭다운 목록 밖 값 (폼 v117, 11-08)
폼 v117 부터 모든 드롭다운이 목록 밖 글자도 받는다(사장님 「다른 드롭다운목록도 텍스트 입력 가능하게 해줘」). 폼은 막지 않고 칸 아래·저장한 항목 카드에 「미등록」만 보인다. 그래서 대기 문서에 영림원에 없는 값(거래처·품번·창고·통화·단위·분류·흐름·워크센터 등)이 들어올 수 있다. 문서마다:
1. 넣기 전에 문서의 드롭다운 칸 값(머리·줄 모두)이 영림원에 있는지 그 화면 코드도움·드롭다운(또는 조회 화면)에서 **먼저 조회**한다. 폼 목록에 없는 값이 특히 그렇다.
2. 모두 있으면 보통대로 넣는다.
3. 하나라도 영림원에 없으면 **영림원에 저장하지 않는다.** `status` = 오류, `agentNote` = 「영림원에 없음: <칸 이름> 「<값>」(<본 화면·코드도움>)」 꼴로 칸·값을 모두 적는다. 사장님이 폼에서 값을 고쳐 대기로 되돌리신다.
4. 영림원에 없는 값을 영림원에 새로 등록하지 않는다(거래처·자재·창고 등을 만들지 않음). 신규 감지·등록은 나중 일(`영림원외주입력/CLAUDE.md` 「드롭다운 목록 밖 입력 (v117)」).

### 3-0. 날짜 지난 화면 쓰지 않기 (11-08)
영림원 입력 화면의 일자 칸은 **화면을 연 날** 값이 들어가고 「신규」로도 안 바뀐다. 날짜가 바뀐 뒤 저장할 때는 화면 탭을 닫고 다시 연다(`ylw.reopen(화면번호)`). 폼에 날짜 칸이 없어 화면 기본값이 그대로 저장되는 칸은 오늘인지 읽고, 아니면 저장하지 않는다. 새 Chrome 탭은 로그인 화면이 나오므로 쓰지 않는다.
- 해당 칸(11-08 화면에서 본 칸 ID): 501617 `datPODate_dat` · 501613 `datOSPDelvDate`류 외주납품일 · 500940 출고일 · 501125 이동일 · 501563 요청일 · 501568 품의일 · 501576 발주일 · 501054 P/O · 501060 Payment · 501065 Invoice · 501067 B/L · 501071 입고일. 정확한 ID 는 `화면별-요령.md` 「날짜 지난 화면」.
- 폼 문서 값을 넣게 정해진 칸(`reqdate` · `dlvDate` · `podate` · `bldate` 등)은 그 절 그대로다. 외주발주일 말고 이 칸들에도 현재일을 쓸지는 사장님 말씀 없음.

### 3-1. 공정흐름유형(`erp_flows`, 폼 v19 — v20 부터 폼 4단계 「공정·공정흐름」)
- 폼 v20: 흐름을 저장할 때 목록에 없던 공정이 `erp_processes` 에 대기로 함께 쌓인다(`name`·`memo`·`inspect:false`). **공정을 먼저 넣고 흐름을 넣는다**(위 순서 그대로).
- 문서 = `name`(공정흐름유형) · `memo`(특이사항) · `rows`[`seq` 공정순서 · `proc` 공정명 · `next` 후속공정순서 · `last` 최종공정여부]. seq·next·last 는 폼이 채운 값 그대로 넣는다(고치지 않는다).
- 넣는 법은 `화면별-요령.md` 「공정흐름유형등록 (500228)」의 「넣는 법(11-01)」: 왼쪽에 이름 → 저장 → 행 번호 더블클릭 → 상세에 `seq\tproc\tnext` 붙여넣기 → last 줄 최종공정여부 체크 → 저장 전 대조 → 저장 → 조회·더블클릭으로 다시 대조.
- `proc` 는 폼의 공정 기록(대기·진행중·완료) 또는 함께 쌓인 새 공정이다(v20). 흐름을 넣을 때 영림원 공정등록에 그 이름이 아직 없으면(공정이 대기·오류로 남음) 넣지 말고 오류 + agentNote.
- 폼 v22 부터 `name` = rows 의 `proc` 를 「-」로 이은 것(예: T재단-T엣지-T보링). 공정 이름에는 「-」가 없다.
- 공정검사여부(상세)는 회색이라 넣지 않는다. 같은 공정이 두 번 나와도 정상(11-01 T중복시험 저장됨).

### 3-2. 불러오기 요청 처리 순서 (`erp_imports`, 폼 v23 — 영림원 → 폼)
사장님 말씀(11-01): 「이렇게 기존정보 불러오는 버튼도 각 입력에 맞게 코드 수정해서 작업할 수 있도록 실제화면 조사할 것 미리 조사해서 입력폼에 적용해줘」 · 「기존 정보란 이알피에 실제 적용된 각 정보를 불러와야 하는거야」.
원천은 **영림원에 실제 저장된 자료**(조회 화면에서 읽은 값)다. 영림원에는 아무것도 저장·삭제하지 않는다.
1. **요청 읽기** — `erp_imports` 에서 `status` 대기인 것을 `createdAt` 순서로(`ylw.imp.pending()`). 문서 = `stepKey`(누른 단계) · `steps`(읽을 단계 키, 4단계는 `processes`·`flows` 둘) · `only`(`all` 전체 / `T` 이름이 T로 시작) · `mode`(`count` 건수만 / `import` 불러오기).
2. **화면 준비** — ⚠ 이미 열린 탭도 **조회를 다시** 한다(열린 탭의 표는 옛 값, 11-04 T조립을 이렇게 놓침). `steps` 마다 그 조회 화면을 열고 조건을 맞춰 화면 「조회」(`화면별-요령.md` 「영림원 → 폼 불러오기용 조회 화면 조사」 표의 조회 조건). 로그인 화면이면 멈추고 「사장님 로그인 필요」.
   - 거래처조회 = 등록일 시작 x 로 비움 · BOM등록조회-모품목기준 = 최초작성일 두 칸 비움 + BOM등록(500145) 화면을 열어 둠 · 나머지는 열면 저절로 조회.
3. **스크립트 실행** — `공통.js` → `불러오기-공통.js` → 그 단계 `*-읽기.js` → `await ylw.imp.run(요청)`. 스크립트가 진행중 → 읽기 → 폼과 비교 → 완료/오류 + `agentNote`(단계마다 「영림원 n건 · 폼에 없음 · 같음 · 다름」과 다른 점 목록) + `result` 를 적는다.
   - 스크립트 싣기(11-06): 영림원 탭에서 `raw.githubusercontent.com` main 의 파일을 `fetch` + 전역 `eval` 하면 된다(공통 → 불러오기-공통 → 읽기). 오래 걸리는 단계는 45초 제한에 걸리니 백그라운드로 돌리고 결과 변수를 읽는다.
   - `count`: 세기만 한다. 폼 문서는 하나도 안 바뀐다.
   - `import`: **폼에 없는 것만** 넣는다 — `status 완료` · `source 영림원` · `agentNote 「영림원에서 불러옴(MM-DD)」` · `importedAt` · `importId`.
     폼에 같은 열쇠(거래처·워크센터·공정·흐름 = 이름, 품목 = 품번, BOM = 품번+차수, 외주계약 = 외주거래처)가 있으면 **덮어쓰지 않는다**: 같으면 건너뜀, 다르면 그 문서의 `ylwDiff` 칸에만 차이(폼은 「영림원과 다름」 칩으로 보임). 폼 문서의 status·agentNote·다른 칸은 안 건드린다.
     **예외 하나(폼 v53)**: 불러온 흐름(`source` 영림원·완료·수정 중 아님)의 `rows` 칸이 없거나, 비었는데 영림원 상세에 줄이 있으면 `rows` 만 채운다(`agentNote` 도 바뀜). 폼에 값이 없으니 덮어쓰기가 아니다. 공정흐름 읽기는 상세까지 읽는다 — `rows` 가 비면 폼이 「공정 없음」으로 막는다.
   - **「영림원에 없음」 지우기(폼 v106, v104 숨김을 바꿈)**: 사장님 말씀(글자 그대로) 「입력폼 불러오기시 해당 불러오기 완료후에 실제 영림원에서 불러온게 아닌 입력폼의 기록에만 남아있던 저장 목록이 계속 표기 되는것 같아요. 이를 확인하여 불러오기시 실제 영림원 현재 상태에 맞게 저장 목록이 보이도록 해주세요」 · 「거래처 뿐 아니라 불러오기로 확인된 속성중 드롭다운에 표기되어야할 것이 있다면 적용되도록 해주세요. 불러오기를 통해 삭제되었음이 확인된 부분도 삭제 되어야 합니다」(11-08).
     **대상** = 읽은 범위 안(그 단계 · `only` T 면 `I.STEPS[].t` · 읽기 스크립트의 `got.scope(폼문서)` 기간 등)에서 폼에 **status 완료**로 있는데 영림원 조회에 없는 문서. 대기·진행중·오류·수정대기, 요청 `steps` 밖 메뉴는 안 건드린다.
     **지우는 순서**(`I.run` 이 한다): ① 요청 `steps` 를 **모두** 읽고 비교한다(넣음·다름 기록) — 하나라도 오류면 **하나도 안 지운다**. ② 단계마다 멈춤 장치 `I.goneStop`: **영림원 0건인데 지울 것이 있으면 멈춤** · **지울 것이 5건 넘고 범위 안 완료의 30% 넘으면 멈춤** · 읽기가 `noGone`(다 못 읽음)·`scopeErr`(조회 조건이 요청과 다름)·`t` 없음이면 안 봄. ③ 묶음 `I.gone`: 앞 문서(수입Order←Payment←Invoice←BL←입고 · 구매 입력←납품 · 생산←외주납품·자재출고)는 **그 뒤 문서가 모두 같은 불러오기에서 지워질 때만** 지운다(아니면 「남김 — 뒤 문서가 남음」). 뒤 문서 먼저 지운다. ④ 지우기 직전 문서를 다시 읽어 아직 완료일 때만 지운다(updateTime 전제조건). ⑤ `result[단계].지움·지운것(열쇠=번호)·남김·멈춤`, agentNote 「지움 n건: 번호…」·「지우지 않음: 까닭 — 번호…」·「남김」.
     **멈췄을 때**: 영림원 화면에서 조회 조건(사업단위·기간·T)과 건수를 눈으로 확인한다. 정말 0건·정말 그만큼 지워졌으면 같은 요청을 대기로 돌리고 `await ylw.imp.run(요청, {allowEmpty:true})` 또는 `{allowMany:true}` 로 다시 돌린다. 조건이 틀렸으면 고쳐서 다시 조회한다. 사장님께 묻지 않고 켜지 않는다 — 화면 확인 없이 켜지 않는다.
     **읽기 스크립트 규칙**: 조회 조건이 요청 범위와 다르면(시작일이 좁음 등) `scopeErr: '까닭'`, 화면을 다 못 읽었으면 `noGone: true`, 기간이 있는 화면은 `scope(폼문서)` 로 기간 밖 문서를 뺀다. 새 단계는 `I.STEPS` 에 `t` 를 단다. `count` 는 「지울 것」만 센다.
     옛 v104 `ylwGone` 표시(진짜 저장소에는 없음)는 다시 읽히면 지워진다. 지운 문서는 폼 목록·드롭다운에서도 빠진다.
   - **같음도 `ylwCheckedAt` 을 적는다(폼 v105).** 폼은 완료이면서 `source` 영림원이거나 `ylwCheckedAt` 이 있는 거래처, 그리고 불러온 문서(구매단가 구매거래처·구매 입력 매입처·수입 수입처·워크센터 외주거래처)에 나온 거래처 이름을 거래처 종류와 상관없이 그 드롭다운에 더한다(v107 부터 이름 글자 그대로만 — 종류 붙임 없음). **v106 부터 거래처 밖 드롭다운도** 같은 기준(확인된 문서 = 완료 · source 영림원 또는 ylwCheckedAt 이고 ylwDiff 없음)으로 그 칸 값을 더한다(단위·통화·창고·공정·워크센터·품번 등). 대조 항목도 같다 — 폼 고정 목록 밖 값이면 영림원 그 화면 코드도움에 나오는지 본다.
     ⚠ **대조 항목(폼 v105):** 이렇게 더해진 거래처는 폼 기준 종류(구매 = 국내매입, 수입 = 해외매입, 외주 = 외주가공)와 다를 수 있다. 영림원에 저장할 때 그 화면 코드도움에 그 거래처가 실제로 나오고 저장되는지 본다. 안 나오거나 저장이 막히면 저장하지 말고 오류 + agentNote 에 화면 글자를 적는다(거래처종류를 영림원에서 고칠지는 사장님이 정한다). 첫 사례 = 구매단가 T해피코(해외매입) 501868 — 영림원에 구매거래처로 이미 저장돼 있음(불러오기 bc8dde5).
   - 화면에 칸이 없어 못 읽는 폼 칸(거래처 국내외구분·법인/개인 · 외주계약 단위·부가세포함여부)은 넣지도 비교하지도 않는다 → agentNote 「못 읽은 것」에 적힌다.
4. **큰 단계** — 품목(1,568개)·BOM(552개, 모품목마다 화면을 열어 20분 넘게)은 사장님이 「건수 먼저 보기」로 센 뒤 고르신다. `import`·`all` 요청이 오면 그대로 하되 시간이 걸린다고 보고한다.
5. **확인·기록** — 폼에서 그 단계 목록에 「영림원」 칩이 붙었는지 본다. `작업일지.md` 에 요청·결과를 적고 푸시한다.

#### 3-2-더. 수입·구매·생산 메뉴 읽는 순서 (폼 v85)
사장님 말씀(11-06): 「각 메뉴에서 영림원의 해당 기 입력내용 불러오는 버튼을 모두 생성해야 합니다. 기존에 이렇게 되어 있는 메뉴들을 참고해서 작업하세요」.
칸·열쇠 = `../erp-spec.json` `imports.steps`. 위 1~5번 순서·덮어쓰지 않는 규칙은 그대로다. **조회·읽기만 한다. 영림원 저장·행삭제·다음 단계 단추는 누르지 않는다.**
- **읽기 스크립트가 아직 없다.** 첫 요청 때 화면을 열어 `*-읽기.js` 를 만들고, `불러오기-공통.js` `I.STEPS` 에 그 단계를 더한다(칸은 화면 글자 그대로). 비교 칸은 읽은 칸만 넣는다. `t`(아래 표 「T 범위」를 폼 문서 칸으로)도 단다 — 「영림원에 없음」(3-2 3번)에 쓴다. 11-08 에 영림원 T 구매·수입·생산·외주 시험 자료를 지웠으니 폼의 그 완료 문서들은 첫 불러오기에서 「영림원에 없음」이 된다.
- **`steps` 에 적힌 순서대로 읽는다.** 뒤 문서는 앞 문서로 이어진다(`link`). 앞 문서를 못 찾으면 넣지 말고 agentNote 에 적는다. 이어지지 않으면 폼이 이미 끝난 일을 다시 하라고 단추를 띄운다.
- **⏳ 화면 확인 필요** = 기록에 조회 칸이 다 없는 자리다. 조회 화면을 오른쪽 끝·아래 끝까지 보고 칸을 `화면별-요령.md` 에 적은 뒤 처리한다. 화면에서 못 본 칸은 읽지 말고 「확인 못 함」으로 agentNote 에 적는다. 화면이 없으면 요청을 오류로 두고 까닭을 적는다. 다르면 `imports.steps` 를 코드 수정자에게 알린다.

### 3-3. 수정 대기 처리 순서 (`erp_items` `status` 수정대기, 폼 v34 — 영림원에 이미 있는 품목 고치기)

#### 3-3-분류. 분류 수정대기 (`erp_classes` `status` 수정대기, 폼 v40)
사장님 말씀(11-02): 「분류에는 수정 입력 없나」 → 「분류도 수정할 수 있게 합시다」.
고칠 수 있는 칸 = 대분류(`big`)·중분류(`mid`)·소분류(`name`) 이름 · 순서(`sort`) · 사용여부(`use`) · 비고(`memo`). 순서·사용여부·비고는 **소분류 줄**의 값. 품목구분(`kind`)은 잠김.
- **나무라서 한 번만 고친다**: 대·중분류 이름을 고치면 폼이 같은 대·중분류의 다른 분류 문서(big·mid)와 그 분류를 쓰는 품목·자재 문서(small 경로)를 **이미 바꿔 두었다**(editLog 「따라 바뀜」, 상태 그대로, 목록은 `edit.tree`). 영림원에서는 **수정대기 문서 하나만** 처리한다 — 대·중분류는 영림원에 하나뿐이고 품목은 분류를 코드로 물고 있다. 따라 바뀐 문서는 손대지 않는다.
- 같은 단계에서는 **수정대기를 대기보다 먼저** 한다(대기 문서가 이미 새 대·중분류 이름을 쓰고 있을 수 있음).
1. 다시 읽어 아직 수정대기인지 보고 `status` 진행중.
2. 품목대중소분류정의(502365) → 품목구분 `kind` 라디오 → 조회 → **`ylwCode` 「대/중/소」 코드**로 대분류 줄 찾기 → 더블클릭 → 중분류 줄 → 더블클릭 → 소분류 줄. 코드가 없으면 `edit.before` 이름 경로로 찾는다. 없으면 오류 + agentNote 「분류 없음」.
3. 화면 이름·사용여부가 `edit.before`(바뀌지 않은 칸은 문서 값)와 같은지 본다. 다르면 고치지 말고 오류 + agentNote 에 영림원 값.
4. `edit.changed` 칸만 고친다: big → 대분류 표 그 줄 분류명 · mid → 중분류 표 그 줄 분류명 · name → 소분류 표 분류명 · sort/use/memo → 소분류 줄 순서/사용여부/비고. 표마다 저장.
5. 저장 전 그 표 모든 줄 대조(바뀐 칸이 그것 하나인지) → 저장 → 조회·더블클릭으로 **코드가 그대로**이고 이름이 `edit.after` 와 같은지 대조.
6. 완료 + 이력: `status` 완료 · agentNote 「영림원 수정함(MM-DD): 대분류 …」 · `edit` null · `editLog` 끝에 `{at, kind:'완료', changed, before, after, note}`. 실패면 오류(edit 그대로).
7. `작업일지.md` 에 적는다.
- ⚠ **확인 못 함**: 영림원에서 이미 있는 분류명을 고쳐 저장할 수 있는지 · 대·중분류 이름을 고치면 이어 붙인 하위 이름(예 `리빙룸_수납장`)도 따라 바뀌는지. 처음 할 때 화면으로 보고 `화면별-요령.md` 「품목대중소분류정의」에 적는다. (폼은 이어 붙인 하위 이름을 바꾸지 않고 「따로 수정하세요」라고만 안내한다.)

   - ⚠ **외주발주일 = 저장하는 그날(사장님 11-08 「폼에서 저장된 날짜를 영림원으로 보내는게 아니라 폼에 입력되어 저장 되더라도 날짜가 바뀌면 현재일이 적용되게」).** 저장 전에 501617 화면 탭을 닫고 다시 열어 외주발주일이 오늘인지 읽는다. 오늘이 아니면 저장하지 않고 멈춘다. 스크립트 = `스크립트/외주발주-업체별-채우기.js`(`ylw.reopen` · `ylw.dateGuard`). 폼 날짜를 넣지 않는다.
   - ⚠ **납기일이 현재일보다 앞이거나 같아 저장이 막히면** 폼에 없는 날짜를 넣지 않는다. 오류 + agentNote(맨 위 🚩 꼴)로 남긴다. 같은 날이 통과하는지는 시험 전이다.
4. **외주발주(전 공정 한꺼번에, 사장님 결정 11-06 · ✅ 저장 시험 끝):** 501608 에서 `rows` 의 **모든 공정**을 차례로 `외주발주` → 501617. 외주거래처 = 문서 `wc` 대조(다르면 머리 외주거래처를 코드도움으로 바꾸고 표 납품창고 `WHName` 도 같은 업체로 고친다 — 11-06 T-al-p02 1건 저장. 납품창고는 저절로 안 바뀐다. 계약 없는 업체·작업지시 쪽 변경은 시험 전) → 저장 → `소요자재가져오기` → 저장. 다음 공정 소요자재에 재공품 줄이 있는지 본다(없으면 오류). 외주처재고가 모자란 줄은 agentNote 에 적는다. `rows.orderNo`. `stage: 외주발주`.
   - ✅ 앞 공정 납품 전에 재단·엣지·보링·조립 발주가 모두 저장된다(11-06 `화면별-요령.md` 「전 공정 외주발주 한꺼번에 저장 시험」). 외주처재고 0 이어도 저장된다. 막히면 억지로 맞추지 말고 오류 + 화면 문구.
5. **필름(임시 기준):** 엣지 발주를 넣을 때 그 소요수량을 자재이동 501125 외주불출로 본사 창고 → 엣지 업체 창고로 옮긴다. 수량 칸은 폼에 없다.
6. 문서 완료 + agentNote 에 번호. 완료가 되어야 폼 카드에 [납품 입력]이 열린다.

**완료일 고침(폼 v100, `dueEdit` 가 있는 대기 문서)** — 사장님이 오류·대기 카드의 [생산계획완료일 고치기]로 고친 문서다. 폼은 `dueDate` 만 바꾸고 `status` 대기 · `agentNote` 빈칸으로 돌린다. 앞 메모는 `dueLog` 끝 `note` 에 남는다. `stage` 가 없던 문서는 `dueEdit` 가 null 이다 — 그냥 처음부터 처리한다.
1. `dueEdit` = `{before, after, at, stage}`. **`planNo`·`stage`·`rows.workNo`·`rows.orderNo` 는 그대로다. 생산계획·작업지시를 새로 만들지 않는다.** 처리 전 500498 값이 `before` 와 같은지 본다. 다르면 오류.
2. ⏳ **시험 전:** 저장된 생산계획 완료일을 `after` 로 고칠 수 있는지 · 작업지시 일자를 어디서 고치는지 · 작업지시취소가 필요한지. 첫 건은 화면을 보며 찾고 결과를 `화면별-요령.md` 에 적는다. **취소·삭제가 필요하면 멈추고 사장님께 먼저 묻는다.** 못 고치면 오류 + 🚩 꼴로 적는다.
3. 일자가 맞으면 `dueEdit: null`(`dueLog` 는 지우지 않는다), `stage` 다음 단계부터 위 순서대로 잇는다.
- 폼의 이른 완료일 안내 = 제품 완료일 < 오늘 + 4일. 문구로 계산한 값이고 저장 시험 전이다. 같은 날이면 되는지 모른다. 알게 되면 코드 수정자에게 넘긴다(`prodDueWarn`). 부속만 만들 때의 일자 규칙은 기록이 없어 폼이 안 본다.

**`erp_proddlvs`**
1. `prodId` 문서가 완료이고 앞 공정 납품이 입고완료인지 본다. 아니면 건너뛴다(문서가 없으면 오류). 501614 로 같은 납품이 이미 있는지 본다.
2. 501610 줄 선택 + `외주납품` → 501613 외주납품일·납품수량을 문서 값으로 → 대조 → 저장. ⏳ 값을 바꿔 저장·나눠 납품은 시험 전이다. 첫 건은 화면을 보며 넣는다. `dlvNo`.
3. 501614 입고완료(`inNo`) · 501621 투입 · 501186 재공품 · 501179 재고 대조. 결과 글을 `stock`.
4. **재공품 출고는 여기서 하지 않는다.** 「현재고가 부족하여」 문구면 오류 + 문구 그대로. ✅ 재공품을 안 보낸 채 납품하면 막힌다(11-06). 문구에 모자라는 품번이 모두 나온다. 납품 업체 창고 재고만 본다.
5. 문서 완료.

**`erp_prodmoves`** (자재출고. 재공품은 자재이동 501125·이동입력 501096 에 안 잡힌다)
1. 같은 `prodId`·`itemNo`·`seq` 의 납품 문서 완료 합이 이 출고까지의 합 이상인지 본다. 아니면 건너뛴다(납품이 먼저).
2. 500938 작업지시번호 `workNo` 조회 → `nextProc` 줄 선택 + `출고처리` → 500940. 출고유형 외주출고 · 입고창고 = `toWc` 대조.
3. 재공품 줄 출고창고 = `fromWc` · 금회출고수량 = `qty`. 다른 자재 줄은 요청수량 그대로(0·행삭제 안 됨). ⏳ 요청수량과 다르게 저장은 시험 전.
4. 저장 → `outNo`. 501186 에서 앞 업체가 줄고 다음 업체에 생겼는지 대조해 `stock`. 완료.
- ✅ **같은 업체 연속 공정:** 공정 사이 출고가 필요 없다(11-06 T-al-p02, 500940 없이 납품 저장). 폼 v84 부터 이 경우 단추·문서가 없다. 그래서 500940 으로 필름을 함께 옮길 수 없다 — 그 공정 필름은 자재이동 501125 외주불출로 입력 작업자가 옮긴다(같은 시험). v84 전에 만든 `fromWc` = `toWc` 문서가 오면 500940 을 저장하지 말고 agentNote 에 적고 멈춘다.
- ⏳ **`kind` 완성 부속(폼 v84 [완성 부속 보내기]) — 영림원 출고 시험 전.** 부속 마지막 공정 업체 → 조립 업체. 부속 출고에도 위 2~4 번을 쓰는지 아직 모른다: 조립 작업지시 `workNo` 로 500938 조회 → `nextProc`(T조립) 줄 → 500940, 부속 줄 출고창고 = `fromWc` · 금회출고수량 = `qty`. 조립 소요자재의 다른 부속 줄이 함께 나올 때 어떻게 할지도 모른다. **첫 건은 화면을 보며 넣고 결과를 `화면별-요령.md` 에 적는다.** 막히면 오류 + 화면 문구. 재고 대조는 501186 대신 501179. 부속이 조립 업체 창고에 없으면 조립 납품은 막힌다(11-06). 조립 업체와 마지막 공정 업체가 같으면 폼은 문서를 만들지 않는다(같은 창고 재고로 보고 정한 것, 시험 전).

**막히면** 오류 + 화면 문구. 처리한 단계는 `stage` 에 남긴다.

## 4. 지켜야 할 규칙
- **비밀번호를 넣지 않는다.** 로그인 화면이 나오면 멈추고 「사장님 로그인 필요」로 보고한다.
- **기존 자료를 고치거나 지우지 않는다.** 새 행만 만든다. 삭제·행삭제·덮어쓰기·업로드는 사장님께 먼저 묻는다. (예외: 폼의 **수정대기** 문서 — 위 3-3·3-3-분류·3-4-필름, 그 문서의 바뀐 칸만.)
- **저장 전에 확인한다.** 값이 다르면 저장하지 않는다.
- **사장님 말씀이 우선이다.** 이 문서와 말씀이 다르면 말씀을 따르고, 이 문서를 고친다.
- **시킨 것만 한다.** 시키지 않은 화면·자료는 보기만 하고 보고한다.
- 테스트 자료는 이름 앞에 `T` 를 붙인다(`사장님-규칙.md`).
- 한 단계가 끝나면 관리자가 「다음」을 줄 때까지 멈춘다(시키신 범위 밖으로 나가지 않는다).
- 공개 저장소다. **비밀번호·계정·실제 거래 자료(사업자번호 등)는 깃에 적지 않는다.** 이름·코드·화면 사실만 적는다.
- ⚠ **실제 운영 전에 영림원 → 폼 일괄 불러오기를 해야 한다** — 폼 v23 부터 단계마다 「영림원에서 불러오기」 단추가 있다. 요청이 오면 위 3-2 순서로 처리한다(`../CLAUDE.md` 「실제 운영 전 꼭 할 일」).
- 영림원에 **직접** 넣은 자료(폼을 거치지 않은 것)가 생기면 `작업일지.md` 에 바로 적는다(무엇을·어느 화면에·코드/이름). 불러올 때 맞출 목록이 된다.

## 5. 기록하는 법
- 채팅에만 남은 사실은 다음 작업자가 못 본다. **알아낸 것은 그 자리에서 파일에 적는다.**
- `작업일지.md`: 맨 위에 `## YYYY-MM-DD 한 줄 제목` → 한 일 · 만든 자료(화면·이름·코드 표) · 막힌 점 · 배운 점.
- `화면별-요령.md`: 화면 제목 아래에 사실만. 확인한 날짜를 붙인다. 확인 못 한 것은 「확인 못 함」이라 적는다.
- 낡은 설명은 지우지 말고 고친다(틀린 것은 고치고, 왜 바뀌었는지 일지에 남긴다).
- 커밋 메시지는 무엇을 했는지 한국말 한 줄.
