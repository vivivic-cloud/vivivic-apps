## 바뀐 꼴
- 등록 한 건 = 외주거래처 하나(501605 머리) **그대로**. 줄(rows)만 같은 컬렉션 조각 문서로 나눔.
- 머리 문서 `erp_contracts/{id}` = 예전 칸 모두(unit·vendor·status·agentNote·bd·route·…) − `rows` + `__parts`(조각 열쇠 배열, 예 `["c0","c1"]`) + `__n`(줄 수).
- 조각 문서 `erp_contracts/{id}~{열쇠}` = `{__part:1, head:id, key, rows:[줄…], i:[원래 줄 차례…]}` — 제품번호(pcode) 처음 나온 차례대로 40제품씩. **status 없음** → 대기 질의·깨우미에 안 잡힘.
- 예전 꼴(머리 안에 rows)도 그대로 유효 — 폼이 다음에 rows 를 고칠 때 나눔. 11-26 지금 erp_contracts 문서 0건(옮길 것 없음).
- 저장소 규칙 그대로(같은 컬렉션 `match /{col}/{id}`).

## 영림원 작업자 스크립트에서 고칠 것 (이 방은 스크립트를 안 고침)
1. **읽기**(`불러오기-공통.js` `I.list`, 외주계약 입력 때 문서 읽기, `창고백업.py`, `구글시트양식/한행입력표/저장소읽기.py`·`표만들기.py`): `erp_contracts` 는 `__part` 문서를 빼고, 머리에 `__parts` 가 있으면 조각을 모아 `i` 차례로 `rows` 를 만든 뒤 `__parts`·`__n` 을 지운다.
   ```js
   // docs = 컬렉션 전체(평평한 객체, id 포함)
   const P = {}; docs.filter(d => d.__part).forEach(d => ((P[d.head] = P[d.head] || {})[d.key] = d));
   const heads = docs.filter(d => !d.__part).map(h => {
     if (!Array.isArray(h.__parts)) return h;
     const a = []; h.__parts.forEach(k => { const p = (P[h.id] || {})[k]; if (p) p.rows.forEach((r, j) => a.push([p.i[j], r])); });
     a.sort((x, y) => x[0] - y[0]); const o = Object.assign({}, h, { rows: a.map(x => x[1]) }); delete o.__parts; delete o.__n; return o;
   });
   ```
   - 한 문서만 읽을 때: 머리를 읽고 `__parts` 마다 `erp_contracts/{id}~{열쇠}` 를 읽어 같은 셈.
2. **상태만 고치기**(status·agentNote·ylw…): 머리 문서만 PATCH — 조각은 그대로(지금과 같음).
3. **rows 를 쓰기**(`I.add` 로 영림원에서 불러온 외주계약 넣기 등): 줄이 많으면 같은 꼴로 나눠 쓴다(머리 + 조각, 지난 조각은 지움). 줄이 적으면(문서 1MB 훨씬 아래) 예전처럼 머리 안 rows 로 넣어도 폼이 읽음.
4. 지울 때: 머리 + `__parts` 조각 모두.
5. `I.apply` 의 「영림원에 없음」 지울 후보 셈은 머리만 셈(조각은 `__part` 로 빼야 함 — 안 빼면 열쇠 없는 문서로 섞임).
