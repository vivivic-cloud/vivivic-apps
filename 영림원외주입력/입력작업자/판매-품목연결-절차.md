# 온라인 판매 상품 ↔ 영림원 품목 연결 — 절차 (2026-11-14 TEST 서버에서 실제로 해 봄)

곳: `https://inghometest.ksystemace.com` 「아이앤지퍼니처(TEST)」 · 맥북프로 크롬. 메뉴·칸 이름은 화면 글자 그대로.
목표 체계: 입력폼 → 입력 작업자(AI)가 영림원 등록. 이 문서는 그 등록 순서다(폼 단계는 아직 없음).

> **✅ 확정(11-14 사장님 결정)**: 「영림원 품번은 벤더피아 단품코드와 일치하게 등록할 예정」 → 온라인 판매 상품과 영림원을 이을 때 **따로 연결표를 두지 않는다. 벤더피아 단품코드 = 영림원 품번**(벤더피아연동은 단품코드를 앞뒤 빈칸 지우고 소문자로 비교 — 품번도 그렇게 같게). 아래 시험의 `T-…` 품번은 TEST 서버 시험용이다. 판매 묶음은 아래 경우 1(세트품) · 쇼핑몰품목매핑등록으로.

## 경우 1 · 세트 (온라인 1개 = 영림원 제품 A + B)

### 1. 품목등록 (500215) — 세트품 품목 만들기
1. 「신규」 → 품명 · 품번 · 기준단위(EA) · 품목소분류(코드도움) 입력.
2. **품목자산분류 = 「세트품」** 고름.
3. 「저장」. → **「세트품목」 체크가 저절로 켜진다**(직접 못 누르는 회색 칸. 품목자산분류설정의 세트품 = 세트품목 ☑ 때문).
- 11-14 시험: `T[시험]세트 알렉스 높은 수납장 1200+800` · `T-set-al12h80h` · 품목코드(ItemSeq) 1696 · 소분류 T리빙룸_T수납장_T올화이트.

### 2. 세트구성품등록 (502184) — 물류 › [물류] 기본정보
1. 「조회」 → 왼쪽 「세트품목정보」에 세트품이 나온다 → 그 줄 **더블클릭** → 오른쪽 머리에 세트품명이 들어옴.
2. 오른쪽 「세트구성품정보」에 구성품 한 줄씩: **세트구성품명**(코드도움 — 품명으로 찾음. ⚠ 품번 칸에 넣으면 안 잡힘) · 구성품단위 · **구성품수량** · **단가 비율** · 기본창고(비워도 됨).
3. 「저장」.
4. 왼쪽 줄 **「판매출고시세트자동입고」 체크**(⚠ 스크립트 SetText 로는 저장 안 됨 → 체크칸을 진짜로 클릭) → 「저장」 → 「조회」로 ☑ 확인.
- 11-14 시험: T-al12h(T(KRW) 알렉스 1200 높은 수납장 올화이트) 수량 1 · 단가 비율 60 / T-al80h(… 800 높은 …) 수량 1 · 단가 비율 40 · 기본창고 빈칸. 「세트구성」 ☑ · 「판매출고시세트자동입고」 ☑.

### 3. 판매 — 거래명세서입력 (500626)
1. 거래처(판매거래처 코드도움) · 출고구분 정상판매 · 줄에 **세트품 한 줄**(품명 코드도움) · 판매단가 · 수량 → 「저장」 → 거래명세서번호 생김.
2. 머리 오른쪽 끝 **「출고/취소」** 단추(창이 좁으면 머리를 오른쪽으로 밀어야 보임 · 「모든기능」 안에는 없음) → 「출고처리이(가) 완료되었습니다.」 → 「출고」 체크 켜짐.
   - ⚠ 저장만 하면 출고가 아니다. 이 단추를 눌러야 세트 자동입고·재고 차감이 생긴다.
3. 매출: TEST 서버 판매거래처 기본 **매출시점 = 세금계산서매출** → 매출은 「모든기능」 › 「세금계산서발행」(= 매출세금계산서발행(매출) 500642) 저장 때 잡힌다. (전송 안 함.)
- 11-14 시험: 거래처 네이버 · 세트 1개 · 판매단가 100,000 · 부가세 10,000 · 거래명세서 **202611140001** · 세트입고 **202611140001** · 매출세금계산서 **202611140001**.
