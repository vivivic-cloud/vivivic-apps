# 채우기 스크립트 — 화면에 스크립트가 있으면 먼저 이것으로 넣는다

사장님 말씀(11-01): 「각 입력마다 채우기 스크립트에 대한 정보를 깃에 저장해서 작업자가 확인하고 빠릿하게 작업할 수 있도록 만들어줘」 (「동작 너무 느리지 않냐」).

## 목록

|---|---|---|---|---|---|

## 실행하는 법
1. 영림원 탭(사장님이 로그인해 둔 것)에서 **`공통.js` → 그 화면 파일** 순서로 파일 내용을 그대로 실행한다(Claude in Chrome 이면 `javascript_tool` 에 붙여 넣기). 로그인 화면이면 멈춘다.
2. 폼 대기 자료를 읽는다(`../화면별-요령.md` 「폼 자료 읽고 쓰기」). 파이어스토어 REST 문서는 `ylw.fs(문서)` 로 보통 객체가 된다. **대기인 것만, 이름 겹침 없는지** 본다(스크립트도 같은 이름이 이미 있으면 건너뛰고 `건너뜀` 에 적는다).
3. 그 화면을 열고 화면의 **「조회」** 를 누른다(빈 행 위치를 맞추려고). `Home.OpenPageSeq(번호)` 로 열 수 있다.
4. `await ylw.<화면>.fill(목록)` → 돌려준 것: `모두맞음` · `틀린칸` · `대조표`(행·칸·폼·화면·맞음, 코드도움 칸은 「(코드)」 줄로 코드가 잡혔는지) · `넣은것` · `건너뜀`.
5. **`모두맞음` 이 true 일 때만** 화면 「저장」을 누른다. 틀린 칸이 있으면 저장하지 않고 「조회」 → 「변경된 내용이 반영되지 않습니다…」 확인으로 버린 뒤 원인을 고친다.
   대조표는 화면에 보이는 칸 **전부(오른쪽 끝 비고까지)** 를 본다 — 폼에 없는 칸에 값이 있으면 틀림으로 나온다(AGENTS.md 3-4).
6. 저장 뒤 「조회」 → `ylw.<화면>.verify(목록)` 으로 이름으로 찾아 다시 대조(행 번호가 바뀔 수 있어서). 저장 안 된 줄(`WorkingTag` 가 남은 줄)도 틀림으로 나온다.
7. 폼 상태를 완료/오류로 바꾸고 작업일지에 적는다.

⚠ 저장·삭제·조회 단추는 스크립트가 누르지 않는다. 단추를 누를 때는 확대(zoom)로 자리를 보고 누른다 — 공정등록은 조회·저장이 붙어 있어 11-01 에 잘못 저장한 적이 있다.

## 어떻게 넣나(공통.js 안쪽)
- 표 화면은 **붙여넣기 이벤트를 스크립트로 보낸다**: 시트 `SetFocus()` → `SetActiveCell(0부터 센 행, '열이름')` → 시트 안 `contenteditable` DIV 에 `ClipboardEvent('paste')`(탭으로 이은 한 줄).
  사람이 Cmd+V 한 것과 같은 길이라 **코드도움 칸(거래처·창고·공정·부서·드롭다운)이 이름으로 코드가 잡힌다**(11-01 창고·워크센터·공정에서 코드 확인).
- **체크 칸**은 붙여넣기(1·True)로 안 켜진다 → `ylw.setChk` = 시트 `SetText(행, 열, '1')`. 화면 체크 표시도 켜진다. `SetText` 는 코드도움을 안 거치니 글·코드 칸에는 쓰지 않는다.
- 줄마다 0.8~1.5초 기다린다(코드도움 조회 시간). 줄 수가 많아도 사람 손보다 훨씬 빠르다.

## 알려진 한계
- **여러 줄을 한 번에 보내면 아무것도 안 들어간다**(`\n`·`\r\n` 둘 다, 11-01) → 스크립트가 한 줄씩 보낸다.
- 공정흐름유형: **상세를 한 번이라도 연 뒤에는 왼쪽 표에 붙여넣기가 안 된다 — 「조회」로도 안 풀린다**(사람 Cmd+V 도 안 됨, 11-01) → `fillHeads` 는 화면을 **닫고 다시 연** 직후에 한다(모든 흐름 이름을 한 번에 넣고 저장).
  상세는 **행 번호 더블클릭**으로 사람이 연다(스크립트로 여는 법 못 찾음). `fillRows` 는 오른쪽 위 공정흐름유형 칸이 그 흐름 이름이 아니거나 상세에 이미 줄이 있으면 넣지 않고 멈춘다.
  11-01 실제 12흐름: 흐름마다 「더블클릭 → fillRows → 대조 확인 → 저장」, 끝나고 「조회 → 흐름마다 더블클릭 → verifyRows」 모두 맞음. 12흐름 약 6분.
- 거래처등록은 표 화면이 아니다(칸 하나하나). **사업자번호(틀 칸)는 스크립트로 안 들어간다** → 칸을 누르고 Home → 숫자 10자리 타자. 순서는 `../화면별-요령.md` 「거래처등록 — 한 건 넣는 순서」.
  `ylwKinds` 로 종류 체크는 되지만(화면 표시 확인) **저장까지는 안 해 봤다** → 처음 쓸 때 저장 뒤 거래처조회로 종류 확인, 안 되면 손 클릭.
- 빈 행이 모자라면(화면 아래 빈 줄 수보다 많이 넣을 때)는 아직 안 겪어 봄 — 대조표에 「(행 없음)」이 나오면 거기서 멈추고 저장한 뒤 이어서 넣는다.
- 워크센터 사업단위는 표에 칸이 없어 조회조건(본사)을 따른다. 본사가 아니면 스크립트가 건너뛴다.

## 규칙
- **화면에 스크립트가 있으면 먼저 스크립트로 넣는다. 없는 화면은 처음 넣을 때 손으로 하고, 끝나면 그 화면 스크립트를 만들어 푸시한다. 화면이 바뀌어 스크립트가 틀리면 고쳐서 푸시한다.** (11-01, `../AGENTS.md` 맨 앞)
- 스크립트마다 맨 위 주석에: 무엇을 하는지 · 어느 화면(번호) · 받는 것 · 쓰는 법 · 확인한 날짜.
- **저장·삭제를 누르는 스크립트는 만들지 않는다**(사장님 허락 전). 채우기·읽기·대조까지만.
- 새 스크립트는 저장하지 않고 시험한다: 채우고 대조표 확인 → 「조회」로 버림.
- 비밀번호·계정·실제 거래 자료(사업자번호 등)를 스크립트에 넣지 않는다. 로그인된 브라우저에서만 돈다.
- 만들면 이 표 · `../AGENTS.md` 파일 표 · `../작업일지.md` 에 적는다.
