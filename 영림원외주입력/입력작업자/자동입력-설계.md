## 1. 확인한 사실 (코드·설정에서 직접 봄)

- 입력 작업자는 이미 터미널에서 Firestore 에 들어간다: `스크립트/작업자표.py`(REST, 익명 계정 갱신표 `~/.vivivic/erp-agent.json` 600). 폼 「담당자 관리」에서 사장님이 준 권한만큼 읽고 쓴다(규칙 `firestore-rules-제안-v259-구글만.rules`의 `erp_staff`·`can()`). → **토큰 인증은 이미 있다.** 새 비밀번호·포트 필요 없음.

## 3. 설계

### 3-1. 한 줄 그림
```
폼(사람) ──저장──▶ Firestore 'erp_*' 문서 status=대기
                       │  (폼이 저장할 때 신호 문서 1장도 갱신)
깨우미(입력 PC, 상시) ──3~10초마다 신호 문서 1장만 읽음──▶ 새 대기 있나?
   있으면 → 한 건 집어 '진행중'으로 잠금 → claude -p "입력대기 건 처리" → 완료/오류로 바꿈
```
외부에서 PC 로 들어오는 길 없음(PC 가 먼저 나가서 묻기만).

### 3-2. 신호 방식 (읽기 값 아낌) — 사장님 선택 ① 과 관련
컬렉션이 30개 넘는다. 매 5초 전부 훑으면 하루 수십만 읽기(무료 한도 5만/일 넘음, 유료 과금 가능) → **신호 문서 1장**을 쓴다.
- 폼이 대기를 저장·수정대기 만들 때 `erp_agentq/ping` 에 `{n: 증가, at: 시각}` 을 같이 씀(폼 코드 한 줄 — 만들기 단계). 깨우미는 이 문서 1장만 읽음(5초마다 = 하루 약 1.7만 읽기).
- `n` 이 바뀌면 → 대기 전체 훑기(3-4 「찾기」).
- **안전망**: 신호가 놓쳐도 되게 5분마다·재접속 때·시작 때 전체 훑기 1번(컬렉션 약 35번 질의).
- 폼 코드를 안 고치는 대안(임시): 5분 주기 전체 훑기만 — 단순·느림(최대 5분 지연). **첫 판을 이걸로 시작해 신호 문서는 2차**로 해도 됨.
- 나중에 SSE/웹소켓: 같은 신호 문서를 Firestore 실시간 듣기(listen)로 바꾸면 됨. 깨우미 안의 「신호 받는 곳」 한 함수만 갈아끼우게 만든다.

### 3-3. 건 집기(중복 방지)
- 집을 때 REST 의 **조건부 쓰기**(문서 `updateTime` 이 읽은 그때와 같을 때만 쓰기)로 `status 대기→진행중` + `claimedBy`(깨우미 이름·PC·시각) 를 한 번에 씀. 두 번째가 오면 거절 → 건너뜀. (AGENTS 「처리 직전 다시 읽기」와 같은 취지.)
- 폼에 `claimedBy` 칸이 새로 생기는 것은 폼 화면 영향 없음(모르는 칸은 무시되는지 만들기 전에 확인 — ⏳).
- 진행중이 **오래(예: 30분) 그대로**이면 → 죽은 처리로 보고 자동 재시작 안 함. `오류`+「깨우미가 멈춘 흔적」으로 바꿔 사장님께 알림(영림원에 이미 저장됐을 수 있어 자동 재입력은 위험).

### 3-4. 실행 순서와 한 번에 하나
- 깨우미는 **일꾼 1명**: 지금 처리 중이면 새 신호는 `대기열 있음` 표시만 하고, 끝난 뒤 다시 「찾기」(= 줄만 세움).
- 「찾기」: AGENTS 3장 컬렉션 순서대로 `status==대기`(수정대기 포함) 첫 건. 앞 단계에 대기·오류가 있어 건너뛰는 규칙도 입력 작업자(claude)가 그대로 지킴 → 깨우미는 건을 직접 고르지 않고 **`claude -p "입력대기 건 처리"` 에 맡김**, 깨우미는 「대기 몇 건 있는지·이번 실행이 끝났는지」만 본다.
- 실행: `claude -p "입력대기 건 처리: 입력작업자/AGENTS.md 를 읽고 대기 1건만 처리"`(프롬프트 한 줄은 임시). 끝나면 깨우미가 그 건의 `status` 를 다시 읽어 확인:
  - 완료 → 다음 건 찾기 / 오류 → 사유는 AI 가 이미 적음, 다음 건으로(같은 단계 뒤 건은 AGENTS 규칙대로 건너뜀) / **아직 진행중** 이면 실행 실패로 보고 `오류`+사유.
- 한 번에 최대 N건(임시 10건) 뒤 쉬어 쿨다운 → 폭주 방지.

### 3-5. 끊김 복구
- 깨우미 시작·인터넷 재접속·잠깨어남 때 「찾기」 1번(놓친 건 없게). 깨우미가 죽었다 살아나면 `진행중`+`claimedBy`=자기 이름의 오래된 건은 3-3 처럼 오류로 돌림(자동 재시도 안 함).

### 3-6. 보안
- 외부 포트·터널 없음. 신호·건 읽기쓰기는 **작업자표 토큰**(이미 쓰는 익명 계정, 관리자가 준 권한만). 갱신표 파일은 600, 로그·깃에 안 남김. 깨우미 로그에는 건 id·상태만(거래 내용·토큰 안 적음).
- 별도 「깨우미 전용 계정」을 두는 것이 더 깨끗하나(임시: **작업자표 그대로 사용**), 사장님 허락 뒤 선택.

### 3-7. 맥 잠자기 방지 · 상시 실행
- 깨우미는 `caffeinate -i`(화면 잠금은 안 막고 잠자기만 막음)로 감싸거나 `launchd` 로 로그인 시 자동 시작·죽으면 재시작. 뚜껑 닫으면 소용없음 → 입력 PC 는 전원 연결·뚜껑 열림(또는 외부 모니터) 필요. 앱 쪽 `request_keep_awake` 방법도 있음. (임시 — 만들 때 확정)
- 크롬이 꺼져 있거나 영림원 탭이 없으면 깨우미는 건을 안 집고 「오류 안 남기고」 대기 상태로 두며 사장님께 알림? → 결정 ② 참고.

### 3-8. 로그인·화면 이상 때 멈춤
- `claude -p` 가 「영림원 로그인 필요」「크롬 연결 안 됨」 로 끝나면: 그 건 `오류`+사유 1줄, **깨우미 전체를 멈춤(정지 표시)** 하고 알림. 사장님이 로그인 후 「다시 시작」 신호 1개를 풀어야 이어감(같은 이유로 건마다 오류가 쌓이지 않게).
- 알림: 맥 알림 + 신호 문서에 `stopped: 사유` → 폼 위쪽 띠로 보이게(2차).

### 3-9. 자동 대상 제외 (사장님 허락 건으로 남김)
- 삭제·행삭제·덮어쓰기·설정 변경(환경설정·「환율받기」 같은 저장 단추 아닌 설정류), 취소가 필요한 `dueEdit`(AGENTS 4장), `edit.removed` 가 있는 수정대기(소요자재), 「⏳ 시험 전 첫 건은 화면을 보며」 인 종류 전부(AGENTS 곳곳).
- 구현: 깨우미가 `claude -p` 에 「자동 허용 종류 목록」을 같이 줌(임시 목록: 이미 시험된 종류만 — 구매 요청·품의·발주, 발주수정+짝 납품, 거래처·품목·자재 등 일반 등록). 목록 밖 건은 건드리지 않고 `agentNote`: 「사장님 허락 필요」 로 두는 것이 아니라 **`대기` 그대로 두고 신호 문서 `skipped` 목록에만 올림**(폼 상태 안 바꿈 — 폼 규칙 지키기).
- 영림원 쪽 삭제·설정 변경이 필요해지면(AGENTS 4장 대로) 그 자리에서 멈추고 사장님께.

## 4. 만드는 순서(허락 뒤, 작게)
1. (시험) `claude -p` 로 크롬 도구가 되는지 — 대기 0건 상태에서 「읽기만」 으로.
2. 깨우미 v1: 5분 훑기 + 건 집기(조건부 쓰기) + `claude -p` 실행 + 끝 확인 + 멈춤. 건 종류 1개(구매 발주수정/납품 등 이미 단단한 것)만 자동.
3. 폼에 신호 문서 한 줄 + 3~10초 확인으로 단축.
4. 자동 종류를 하나씩 늘림.
5. 나중: 실시간 듣기(SSE 대신 Firestore listen).

## 5. 사장님이 정해 줄 것
1. **신호 방식**: (가) 폼에 「신호 문서」 한 줄 추가해 3~10초 반응(추천) · (나) 폼 안 고치고 5분마다 훑기로 먼저 시작
2. **크롬·영림원이 안 열려 있을 때**: 건 안 집고 기다리며 알림(추천) vs 오류로 남김
3. **처음 자동으로 맡길 종류**: 임시 = 구매(요청·품의·발주·발주수정·납품). 늘려 갈 순서
4. **입력 PC**: 맥미니·맥북프로 중 어느 기기에 깨우미를 둘지(뚜껑·전원 조건 포함)
5. 깨우미 전용 계정을 따로 둘지(임시 = 지금 입력 작업자 계정 그대로)
6. `claude -p` 방식이 안 되면 대안(입력 전용 방을 상시 열어 두고 메시지로 깨움)으로 가도 되는지
