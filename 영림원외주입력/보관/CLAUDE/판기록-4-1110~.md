## 발주 박스 [object] 깨짐 · 거래처 박스 겉 납품완료 뺌 (v210, 11-12)
- 지시(분배 방 경유): 사장님이 폼 화면에서 복사해 보내신 공통부속 발주 박스 글에 「[object HTMLDivElement],…」 8개. 사장님 말씀(글자 그대로): 「발주서 거래처 박스 표면에 납품완료 표기 하지마」.
- **원인**: `asmLine` 의 발주 박스 안(`asmTile` body)이 `[ds.map(asmProdCard), …]` 꼴 — 배열 안 배열. `h()` 는 자식 배열을 한 겹만 펴서 안쪽 배열이 글자로 바뀌었다(생산 문서 수만큼 「[object HTMLDivElement]」, 공통부속 발주 = 부속마다 생산 문서라 8개). 넘기기 전 발주(`[asmPoTable(a)]`)도 같은 꼴로 깨져 있었다. v204 정사각 박스로 바꿀 때 생김.
- **고침**: 안 = `[a?asmPoTable(a):null, 넘기기 못 한 까닭]`. 원래 나오려던 `asmProdCard`(부속마다 공정 · 업체 · 외주납품/자재출고 칩 · 생산계획번호)는 지시대로 펼치기로도 안 보이게 뺐다(함수는 남김, 부르는 곳 없음). 발주 품목 표(품명·품번·규격·단위·수량)는 남겼다. 영림원 조립 발주 생산(링크 발주서 없는 줄)은 안이 빈다.
- **거래처 박스 겉면**: `asmCountChips` 에서 「납품완료 n」 칩만 뺐다(이 함수는 거래처 겉면 한 곳만 씀). 안쪽 「작업」 박스 겉 칩 「납품완료 n」·공정 박스 칩·납품완료 묶음, 납품완료 제품명을 흐리게·뒤로 보내는 정렬(`wn`·`nm`)은 그대로 — 바꾸지 않음. 거래처 박스 순서는 이름순이라 납품완료와 상관없음.
- 다른 화면: 같은 꼴(`return [x.length?x.map(…):[…]]`)은 이 한 곳뿐(grep). 가짜 사본에서 `h()` 에 배열 안 배열 감지를 넣고 발주서·주간생산계획·외주납품·발주서관리 화면을 열어 0건. 링크 `발주.html` 은 자료가 없어 화면으로는 못 봄.
- 시험(11-12, 파일 사본 · `connectDb` 메모리 가짜 · 진짜 쓰기 0 · 영림원 없음): v209 사본 = 거래처 → 작업 → 조립 → 발주 박스 안 「[object HTMLDivElement],[object HTMLDivElement]」 재현 · v210 = 같은 길에서 발주 품목 표, 「[object」 0 · 납품 끝낸 발주가 있을 때 v209 겉면 「납품완료 1」 → v210 없음, 작업 박스 안 「납품완료 1」 그대로.
