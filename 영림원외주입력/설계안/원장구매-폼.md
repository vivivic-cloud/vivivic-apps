# 원장 구매 입력 폼 설계안 (2026-11-06)

> **코드 작업 전 준비 자료다.** 폼은 아직 안 바뀌었다. 끝의 「사장님 결정」은 11-06 에 답을 받았다(9장). 「화면 재확인」(8장)도 11-06 에 봤다. 남은 항목은 8장 표의 「확인 못 함」이다.
> 칸 이름은 `입력작업자/화면별-요령.md` 「원장 매입 입력 분석」·「원장 재고 시험 준비 조사」에 적힌 화면 글자 그대로다. 영림원 칸은 새로 짓지 않았다. 새로 지은 것은 폼 문서의 키뿐이다.
> 공개 저장소다. 실제 거래처·단가를 적지 않는다. 시험 매입처는 「매입처 A·B」로 적는다.

## 1. 정해진 것

| 내용 | 근거 |
|---|---|
| 단계를 생략하지 않는다: 구매요청 → 구매품의 → 구매발주 → 구매납품 → 구매입고 | 사장님 말씀 「원장관련 생략 하지 않습니다」(11-06). 수입의 BL·입고만 남긴 생략을 원장에 적용하지 않는다 |
| 원장은 재단 업체 창고로 입고한다. 본사 창고를 거치지 않는다 | 사장님 말씀(`입력작업자/사장님-규칙.md` 「자재 입고·보관」) |
| 한 원장을 어느 매입처에서든 살 수 있다. 매입처는 줄마다 고른다 | 시험 |
| 품의 1건이 매입처별 발주로 저절로 나뉜다 | 시험 |
| 납품을 저장하면 입고까지 저절로 된다 | 시험 |
| 구매단가등록 501868 폼은 다른 작업자가 만든다 | 지시. 이 설계에 넣지 않는다 |

**규칙 문서와 다른 범위:** `사장님-규칙.md` 는 「요청부터 정산까지 전 단계」라고 적었다. 사장님 결정(11-06): 정산·세금계산서는 지금은 빼고 폼은 입고까지만 만든다. 나중에 추가 작업이 필요하다(결정 4번).

## 2. 표시 뜻

**값 출처**
- **사장님 입력**: 폼에서 넣는다.
- **앞 단계**: 앞 단계 화면에서 넘어온다.
- **기본값**: 화면이 처음부터 채워 둔다.
- **자동**: 코드도움이나 영림원이 채운다.
- **안 씀**: 폼에 칸을 두지 않는다. 영림원 칸을 비워 둔다.

**확인 정도**
- **시험**: 11-06 저장 시험에서 그렇게 저장됐다.
- **화면**: 칸은 화면에서 봤다. 그 값으로 저장해 보지는 않았다.
- **추측**: 기록으로 짐작했을 뿐이다. 칸을 만들기 전에 확인한다.

`*` 필수 · `©` 코드도움 · (회색) 입력 안 됨. 화면 표시 그대로다.

## 5. 폼 페이지 구성

수입 페이지(v75)와 같은 꼴로 **단계 줄의 입구 하나 + 안쪽 탭**을 쓴다. 1~11단계 흐름 밖이다.

```
[점검표] [수입 관리] [구매 관리] [1 거래처] [2 워크센터] …

구매 관리
  [구매 입력] [납품 입고]
```

탭을 둘로 나눈 까닭: 요청·품의·발주는 주문할 때 끝나고, 납품은 원장이 도착할 때 넣는다. 납품을 저장하면 재고가 바로 잡히니 주문과 같이 넣으면 재고가 먼저 생긴다. 요청·품의를 한 화면에 넣고 납품 탭을 따로 두는 것은 사장님 결정이다(결정 1·2번).

구매단가 501868 폼을 같은 페이지 탭으로 둘지는 그 폼을 만드는 작업자의 결과를 보고 맞춘다.

### 탭 1 「구매 입력」 (요청 → 품의 → 발주)

보통 입력 폼 + 행 구조다.
- **머리:** 요청일(오늘)
- **줄(여러 줄):** 품번 · 요청수량 · 납기요청일 · 창고 · 구매거래처 · 단가
- 품명·규격·단위는 `auto` 칸이다. 저장할 때 5 자재에서 채운다(수입BL `impblDoc` 과 같은 꼴).
- 같은 원장을 두 매입처에서 사면 **줄을 둘로 나눈다**. 시험과 같은 꼴이다.
- 저장 뒤 목록에서 줄과 상태, 영림원 번호를 본다.

| 칸 | 고르는 목록(제안) |
|---|---|
| 품번 | 5 자재 중 품목자산분류 원자재. 엣지필름(`edgeIsFilm`)은 뺀다. 11단계 재단 단가가 원장을 찾는 기준과 같게 맞춘다 |
| 창고 | 재단 업체 창고. 재단 = AMT·경기산업·조혼가구(`사장님-규칙.md`). 테스트는 T에이엠티·T경기·T조혼 |
| 구매거래처 | 1 거래처 중 완료이고 `kinds` 에 국내매입거래처가 있는 것(수입처 `dl-impvendors` 꼴) |

**저장 막는 것(제안):** 필수 빈칸 · 요청수량 0 이하 · 단가 빈칸이나 0 이하 · 소수 셋째 자리 이상 수량(영림원 구매/자재 수량 소수 자리가 2) · 목록 밖 값.

### 탭 2 「납품 입고」 (납품 → 입고 자동)

입력 폼 없는 표다(`noForm:1`, 수입입고 `impPickFn` 꼴).
1. 발주 단추 목록: `erp_purchases` 완료 문서의 `pos` 중 **남은 수량이 있는** 발주. 번호와 매입처가 보인다.
2. 고르면 납품일(오늘)과 줄이 나온다. 납품수량 처음 값 = 남은 수량, 창고 처음 값 = 발주 창고. 품명·규격·단위·단가는 글자로만 보인다.
3. 「저장」 전 안내: 「저장하면 재고에 잡힙니다」.
4. 남은 수량이 0 이 된 발주는 목록에서 빠진다.

**나눠 납품을 지원한다**(결정 3번, 시험 끝). 발주 하나에 납품 문서가 여러 개 생긴다. 남은 수량 = `poqty` - 그 발주·품번의 앞선 납품 `qty` 합계(오류 문서 뺌, 처리 전 문서 포함). 영림원이 넘치는 수량을 막지만 폼에서도 막는다.

**납품 수량이 0 인 줄(이번에 안 온 원장)은 저장 시험 전이다.** 입력 작업자가 그 줄을 빼는 방법을 시험한 뒤 폼을 맞춘다.

### 안 넣는 것
- 영림원에서 불러오기 · 점검표 칸(수입 페이지와 같다)
- 정산·세금계산서 칸. 지금은 뺀다. 나중에 추가 작업이 필요하다(결정 4번)
- 재단 업체 간 이동 501125
- 자재소요계획 501735 연결. 소요자재생성이 탭을 멈추고 아무것도 안 만들어서 요청수량은 사장님이 직접 넣는다

### 만들 때 같이 할 것
- `STEPS`·`ROUTES` 를 고치면 `erp-spec.json` 을 다시 뽑는다.
- 사장님은 엑셀 저장이 안 되니 양식을 만든다면 구글시트 양식도 같이 만든다(v27 말씀).
- 판 번호 첫 줄 주석 꼴을 지킨다(`freshCheck`).
- 쓰기 규칙 파일이 저장소에 없다. 새 컬렉션 쓰기는 배포판에서 확인한다.

## 6. 저장 문서 꼴

컬렉션 이름과 키는 제안이다. `erp_` 로 시작하는 규칙만 따랐다. 값은 시험 자료 예시다.

### `erp_purchases` — 탭 1 저장 한 번 = 요청 1건 = 품의 1건

```json
{
  "reqdate": "2026-11-06",
  "rows": [
    { "cname": "(자동)", "ccode": "T-pb18-wt", "cspec": "2440*1220", "unit": "EA",
      "qty": 1, "duedate": "2026-11-10", "wh": "T에이엠티",
      "vendor": "T매입처A", "price": 1 },
    { "cname": "(자동)", "ccode": "T-pb18-wt", "cspec": "2440*1220", "unit": "EA",
      "qty": 1, "duedate": "2026-11-10", "wh": "T에이엠티",
      "vendor": "T매입처B", "price": 1 }
  ],
  "stage": "",
  "reqno": "",
  "apprno": "",
  "pos": [],
  "status": "대기", "agentNote": "", "createdAt": 0, "route": {}
}
```

입력 작업자가 단계마다 채운다.
- `stage`: 마지막으로 저장한 단계. `요청` · `품의` · `발주`
- `reqno` · `apprno`: 요청번호 · 품의번호
- `pos`: 발주마다 `{ "pono": "발주번호", "vendor": "매입처" }`

`stage` 를 둔 까닭: 중간에 멈춰도 다시 시작할 때 **이미 저장한 단계를 또 저장하지 않게** 하려는 것이다. 영림원 번호는 저장 때 생기므로 폼에서 겹침을 막을 다른 열쇠가 없다.

### `erp_purdelvs` — 탭 2 저장 한 번 = 발주 하나의 납품 한 번

```json
{
  "purId": "erp_purchases 문서 id",
  "pono": "발주번호",
  "vendor": "T매입처A",
  "dlvdate": "2026-11-10",
  "rows": [
    { "cname": "(자동)", "ccode": "T-pb18-wt", "cspec": "2440*1220", "unit": "EA",
      "poqty": 1, "qty": 1, "price": 1, "wh": "T에이엠티" }
  ],
  "dlvno": "",
  "status": "대기", "agentNote": "", "createdAt": 0, "route": {}
}
```

`poqty` 는 발주수량으로, 폼 대조용이다. 나눠 납품은 납품마다 문서 하나다. `qty` 는 이번에 온 수량이다. `dlvno` 는 입력 작업자가 납품번호를 적는다.

## 7. 입력 작업자 처리 순서

`AGENTS.md` 차례 끝에 `erp_purchases` → `erp_purdelvs` 를 더한다. 같은 컬렉션은 `createdAt` 순서다. 전표·정산·세금계산서는 누르지 않는다. 화면이 멈추면 다시 누르지 않고 조회로 저장 여부부터 본다. 넣기 전과 저장 뒤 모든 줄 대조는 다른 단계와 같다.

**`erp_purchases`** (문서를 진행중으로 바꾼 뒤, `stage` 다음 단계부터)
1. **구매요청 501563:** 신규 → 요청일 → 줄마다 품번·요청수량·납기요청일·창고·구매거래처 → 대조 → 저장 → 조회 대조. `stage: 요청` · `reqno`.
2. **구매품의:** 요청의 「구매품의등록」 → 501568. 줄마다 단가, 비어 있으면 구매거래처를 넣는다. 넘어온 거래처·창고·수량·납기를 문서와 대조 → 저장. `stage: 품의` · `apprno`.
3. **구매발주:** 구매품의조회 501569 에서 그 품의 줄 선택 → 「구매발주일괄생성」 → 창 502682 「발주생성」.
   - ⚠ 501569 는 품의당 한 줄이고 거래처 칸에 첫 거래처만 보인다. 나뉜 것은 발주를 만든 뒤 본다.
   - ⚠ 구매발주조회 501578 첫 줄은 합계 줄이다. 줄 위치를 잴 때 센다.
   - 발주 수 = 문서 매입처 수인지 보고, 줄마다 매입처·수량·단가·창고를 대조한다. `stage: 발주` · `pos`.
4. 문서 완료 + agentNote 에 번호.

**`erp_purdelvs`**
1. `purId` 문서가 완료가 아니거나 `pono` 가 그 문서 `pos` 에 없으면 시작하지 않는다(대기·진행중이면 건너뜀, 없으면 오류 + agentNote).
2. **구매납품:** 구매발주조회 501578 에서 `pono` 줄 선택 → 「구매납품등록」 → 501583. 화면 수량은 남은 수량이다. 납품일을 넣고, 줄의 납품수량·창고를 문서 값으로 고친 뒤 대조한다.
   - ⚠ 납품일 칸을 넣은 뒤 빈 곳을 누르면 달력의 날짜가 눌릴 수 있다. Tab · Escape 로 닫고, 저장 전 날짜를 다시 읽는다.
   - 문구 「해당 건 진행정보이(가) 초과되었습니다.」 = 남은 수량보다 많다. 문서를 오류로 둔다.
3. 저장 → 납품번호 `dlvno`.
4. **입고 확인:** 납품조회 501585 = 입고완료. 구매입고입력 501589 에 넣지 않는다.
5. **재고 확인:** 501179 에서 그 창고 수량이 `qty` 만큼 늘었는지 본다.
6. 문서 완료 + agentNote.

**막히면** 오류 + 화면 문구. 수량·창고를 문서와 다르게 맞추지 않는다. 처리한 단계는 `stage` 에 남긴다.

## 9. 사장님 결정 (2026-11-06 답 받음)

1. **구매요청과 구매품의를 폼 한 화면에서 한 번에 넣어도 될까요?**
   영림원에는 요청·품의·발주가 따로 다 등록됩니다. 단계를 건너뛰는 것이 아니라 사장님이 넣는 곳만 하나로 합칩니다. 원장·수량·납기·창고·매입처·단가를 한 번에 넣습니다.
   요청과 승인을 다른 사람이 하거나 날짜가 다르면 화면을 나눠야 합니다.
