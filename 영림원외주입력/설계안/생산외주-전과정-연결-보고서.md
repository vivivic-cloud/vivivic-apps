# 생산·외주 전 과정 연결 보고서

사장님 말씀(그대로): 「그럼 이곳까지 테스트 입력해서 전과정을 영림원입력폼에 연결 시킬 수 있도록 보고서 작성 해줘 실제 프로그램을 만들어야 하는 일이니까 잘 작성해줘」

이 문서는 **입력폼(`영림원외주입력.html`)의 생산/외주 기능을 만들거나 고치는 작업자**가 읽는다. 아래 사실은 모두 2026-11-12 영림원 테스트 서버 실제 화면에서 저장·조회해 본 것이다. 못 본 것은 「확인 못 함」으로 따로 적었다.

## 3. 단계별 자세히 (프로그램이 따라야 할 차례)

### 3-1. 생산계획 · 확정 · 반제품 계획 · 작업지시 (500498)
1. 표 빈 줄에 **사업단위 「본사」 먼저** 붙여넣기 → 품번 → 생산계획수량 → 생산계획완료일. 저장하면 생산계획번호 · 생산계획시작일(= 완료일)이 생긴다.
2. 줄 「선택」 + 「일괄확정처리」.
3. 「반제품 생산계획 생성」 → 부속 7줄(BOM 수량) → **저장** → 부속 번호 `계획번호-001~-007`. 부속 완료일 = 제품 완료일(설정 0).
4. 부속 7줄만 선택 + 「일괄확정처리」(제품 줄은 이미 확정이라 뺌).
5. 8줄 모두 선택 + 「작업지시생성」 → 브라우저 확인 창 「작업지시생성 하시겠습니까?」 → 화면 안 알림 「작업지시생성 완료되었습니다.」. 이번엔 탭이 1분 안에 풀림.
- 폼 연결: 지금 `erp_prods` 처리 그대로(`AGENTS.md` 3-11). **고칠 것 없음.**

### 3-2. 외주발주 — 업체별 한 장 (501608 → 501617)
- 501608 조회 조건 「생산일」 기본이 오늘~+7일이라 **완료일이 그 밖이면 안 나온다** → 조회 끝 날짜를 완료일까지 넓히고 생산계획번호로 거른다.
- `스크립트/외주발주-업체별-채우기.js` `ylw.po.vendor(업체, 줄수, /^계획번호/)` 로 다섯 장 모두 저장(이 스크립트 첫 실제 저장 — 됨). ⚠ 이 스크립트는 501617 을 다시 열므로 「소요자재가져오기」 확인 창(「기존에 등록된 자료는 삭제됩니다. 삭제하시겠습니까?」)이 새 화면에서 뜬다 → 돌리는 동안 `ylw.dlgOn()` 을 1초마다 다시 걸어야 탭이 안 멈춘다.
- 결과: **한 업체 = 발주 한 장 = 여러 작업지시 줄.** 그래서 같은 업체 줄들의 `rows.orderNo` 는 같은 번호다.
- 엣지 발주 소요자재에 **필름 + 앞 공정 재공품(_1)**, 보링 발주에 **재공품(_2)**, 조립 발주에 **부속 7종**이 들어왔다(9단계 재공품 줄 등록이 끝나 있어서).
- 폼 연결: 지금 그대로. 폼이 「업체별 한 장」을 이미 규칙으로 갖고 있다.

### 3-3. 엣지필름 이동 (500938 → 500940) — 외주발주 직후
- 500938 은 **외주발주 한 장마다 출고요청 한 건**(요청번호 = 외주발주번호, 이름은 첫 줄로 보임).
- 엣지 발주 요청(0005)을 「출고처리」하면 500940 에 **필름 6줄 + 재공품 6줄**이 같이 나온다. 아직 재단 납품 전이라 재공품 줄은 **줄 머리 → 「행삭제」 → 화면 안 확인 창 「선택한 행을 삭제하시겠습니까?」 확인**으로 하나씩 뺐다(띄엄띄엄이라 6번).
- 필름 줄 출고창고 `OutWHName` 을 「T본사」로 붙여넣기(코드 37) → 저장 → 「자료가 저장되었습니다.」 → **알림을 닫아야** 재고가 바뀐다.
- 재단 발주 요청(0003·0004, 원장)은 쓰지 않는다 — 원장은 이미 업체 창고에 있다(사장님 11-10). 요청은 「작성」으로 남는다.
- 폼 연결: 지금 `erp_prods` 처리 5번 그대로. 폼 칸 없음.

### 3-4. 외주납품 (501610 → 501613)
- 501610 은 **발주 한 장이 한 줄**. 그 줄 「선택(Sel)」 + 「외주납품」 → 501613 에 그 발주의 **모든 줄**이 납품수량 = 발주수량으로 들어온다. 외주납품일 = 오늘(화면 기본).
- 저장 → 외주납품번호. 입고는 저절로(501614 진행상태 「입고완료」), 자재투입도 저절로.
- 시트 오류(「현재고가 부족하여」)는 이번엔 한 번도 안 났다 — 앞 공정 출고를 먼저 했기 때문.
- 폼 연결: 지금 `erp_proddlvs`(v174 = 같은 공정·같은 업체 줄 묶음 한 건)와 **딱 맞는다** → 한 문서 = 501613 한 번. `rows.dlvNo` 는 그 문서 모든 줄에 같은 번호.
  - ⚠ 확인 못 함: **한 업체가 두 공정을 맡아** 발주 한 장에 재단·엣지 줄이 섞이면, 501613 에 두 공정 줄이 함께 들어온다. 앞 공정만 납품하려면 뒤 공정 줄을 행삭제해야 할 것으로 보이나 이번엔 그런 업체가 없었다.
  - 납품수량을 발주와 다르게 넣는 것(48·52)은 11-11 시험 끝(`../보관/적게 납품 시험 정리.md`).

### 3-5. 공정 사이 출고 · 완성 부속 출고 (500938 → 500940)
- **받는 업체의 발주 요청**을 고른다: 재단품 → 엣지 업체 = 엣지 발주 요청(0005, 두 번째 출고처리 땐 재공품 줄만 남아 나옴) · 엣지품 → 보링 = 보링 발주 요청(0006) · 완성 부속 → 조립 = **조립 발주 요청(0007)**.
- 입고창고는 저절로 받는 업체(T이룸·T로앤·T조혼). **줄마다 출고창고를 보내는 업체로** 붙여넣기:
  - 재단품 6줄 = T에이엠티(28) · 엣지품 4줄 = T이룸(29)
  - **완성 부속 7줄 = p01·p02 T이룸 · p03·p04·p07·p09 T로앤 · p11 T경기(34) — 한 장에 출고창고가 셋이어도 저장됨**(202611120004).
- 금회출고수량 = 요청수량 그대로(이번엔 납품수량 = 발주수량).
- 다 출고한 요청은 「완료」.
- 폼 연결: `erp_proddlvs` 줄의 `moveKind`·`toWc`·`wc` 그대로 쓰면 된다. **같은 받는 업체로 가는 줄은 한 장으로 묶어 넣을 수 있다**(폼 문서가 공정 묶음이라 자연히 그렇게 됨). 조립 출고는 `toWorkNo`(조립 작업지시) 요청 하나에 부속 마지막 공정 문서 여러 건(T이룸·T로앤·T경기)이 모인다 → **입력 작업자는 그 생산의 부속 마지막 공정 납품이 모두 끝난 뒤 한 번에** 넣는 것이 깔끔하다(따로 넣어도 되는지는 확인 못 함).

### 3-6. 조립 납품 (501610 → 501613)
- 부속 7종이 T조혼 창고에 다 있으니 그대로 저장(202611120009). 투입 = 기본 BOM 대로 부속 7종(사장님 11-10 「공통부속이 재고에서 빠져나가야 해요」 그대로).
- 완제품 T-al12h 1개가 **T조혼 창고**에 입고된다(본사 창고로 옮기는 일은 이번 범위 밖 — 확인 못 함).

### 3-7. 외주입고정산처리 (501622) — 「저장」까지
화면 도움말(요약): 외주 입고 건을 **입고 건별로 전표 처리하는 화면**. 외주입고입력·외주반품입력 건이 모두 조회된다. 줄마다 「세금계산서일」·「지급예정일」·「증빙」·「출납방법」을 넣고 저장한 뒤 「전표처리」 → 분개(차) (제)외주가공비 · 부가세대급금 / (대) 외상매입금 → 「매입장」에서 정산구분 「외주」로 조회. 네 값이 다른 건을 한꺼번에 전표처리하면 맨 위 줄 값만 쓰인다.

**화면 칸(표 오른쪽 끝까지 본 것)**: 선택 · 사업단위 · 외주입고일 · 외주거래처 · 외주입고번호 · 입고부서 · 입고담당자 · 전표기표번호 · 작업지시번호 · 외주품명 · 외주품번호 · 통화 · 입고수량 · 단가 · 금액 · 부가세 · 부가세포함여부 · 금액계 · 원화금액 · 원화부가세 · 원화금액계 · **세금계산서일 · 지급예정일 · 증빙 · 출납방법** · 특이사항(입력 못 함) · 자재투입여부. 위쪽 「전표정보」 = 원화금액 합계 · 원화부가세계 · 정산처리총액 · 적요 + 「전체선택」·「전표처리」. 오른쪽 접힘 「부가세보정」.

## 5. 새로 만들 것 — 「외주입고정산처리」 (제안, 사장님 결정 뒤)

> ⚠ 메뉴·탭·단추 이름은 영림원 그대로: 탭 이름 = **「외주입고정산처리」**. 화면에 설명 글을 넣지 않는다(CLAUDE.md v101). 아래 문서 이름·칸 키는 **제안**이다.

**사장님이 넣는 것** — 외주거래처를 고르면 그 업체의 **입고됐고 정산 안 된 줄**(폼 문서로 계산: `erp_proddlvs` 완료 줄)이 나오고, 업체 세금계산서를 받은 날 넣는다:
- 세금계산서일(날짜, 필수) · 증빙(목록 6개, 기본 전자세금계산서(일반과세)?) · 출납방법(현금지급·어음지급·예금지급) · 지급예정일(빈칸이면 영림원 저절로 값)
- 대조 칸(폼 기록만, 영림원에 안 넣음): 업체 명세서·세금계산서 금액 → 폼이 영림원 금액계 합과 비교해 다르면 저장 전 확인창. 지금 외주납품 화면의 「명세서 번호·금액」을 여기로 옮길지 **사장님 결정**.

**문서(제안) `erp_prodsettles`**: 한 건 = 한 업체 · 한 세금계산서. 머리 `vendor` · `taxDate` · `evid` · `payType` · `payDate` · `stmtNo`·`stmtAmt`(폼 기록) · `rows` = [{`dlvId`(erp_proddlvs id) · `dlvNo` · `inNo` · `itemNo` · `proc` · `qty`}]. 입력 작업자가 채우는 칸 = `rows.amt`·`rows.vat`(영림원 값) · `agentNote`. ⚠ 새 `erp_` 컬렉션이면 메뉴(`erpMenus` cols)·규칙·담당자 권한 다시 저장이 필요(CLAUDE.md 「저장소」).

**입력 작업자 처리 순서(이번 시험 그대로)**
1. 501622 조회: 외주입고일 범위 · 외주거래처(또는 외주입고번호 `inNo`) → 문서 `rows` 의 `inNo` 줄만 찾는다. 줄 수가 다르면 오류.
2. 그 줄들에만 세금계산서일·증빙·출납방법(·지급예정일) 붙여넣기 → 다른 줄에 U 가 붙지 않았는지 본다.
3. 툴바 「저장」 → 화면을 닫고 다시 열어 조회해 값 대조 → 영림원 금액·부가세를 문서에 적고 완료.
4. ⛔ 「전표처리」·「전체선택」·「부가세계산」·「금액반영」은 누르지 않는다(전표·금액이 바뀜 — 사장님 허락 전).
5. 반품(외주반품입력 501632)이 있으면 같은 화면에 −줄로 나온다(11-12 시험) → 같은 업체 정산에 함께 넣는다.

**발주서 박스·카드 상태**: 조립 입고 뒤 「정산」 단계를 하나 더 셀 수 있다(정산 문서 완료). 표시 여부는 사장님 결정.

## 6. 사장님 결정이 필요한 것
1. 외주입고정산처리를 폼에 만들지, 만들면 **업체별·세금계산서별 한 건**이 맞는지.
2. 「명세서 번호·금액」을 외주납품 화면에 둘지, 정산 화면 대조 칸으로 옮길지.
3. 증빙·출납방법 기본값(이번 시험 = 전자세금계산서(일반과세) · 예금지급).
4. 부가세 단수 차이(줄마다 반올림, 1~2원)를 「부가세보정」으로 세금계산서에 맞출지.
5. 「전표처리」(→ 매입장·매입세금계산서)까지 시험할지 — 전표가 생기면 되돌리기 어렵다.
6. 조립 완제품이 조립업체(T조혼) 창고에 입고된 뒤 본사·판매 창고로 옮기는 단계가 필요한지.

## 7. 확인 못 한 것
- 「전표처리」 이후(분개전표 · 매입장 · 매입세금계산서) — 사장님 결정으로 안 함.
- 「자재정산여부」 0 인 줄이 전표처리 때 막히는지, 자재정산을 어디서 하는지(501620·501925 에 단추 없음).
- 한 업체가 두 공정을 맡아 발주 한 장에 공정이 섞일 때 외주납품을 공정별로 나누는 길.
- 완성 부속을 업체마다 따로(조립 요청 하나를 여러 번) 출고하는 길 — 이번엔 한 번에.
- 외주입고번호가 늘 외주납품번호와 같은지.
- 「외주납품전표(QR)」 출력 양식 · 501622 숨은 단추 「외주입고일괄정산처리」(누르지 않음).
- 완제품을 조립업체 창고에서 옮기는 단계.
