## 1. 한눈에

사장님은 **처음 한 번**(무엇을·몇 개·언제까지·공정별 업체), **공정 끝날 때마다 한 번**(납품 수량·일자)만 넣는다. 나머지 영림원 화면은 입력 작업자가 처리한다.

```
[생산 관리] 페이지
 ① 새 생산     제품 또는 부속 / 수량 / 완료일 / 공정별 업체 → 저장(대기)
                    ↓ 입력 작업자: 생산계획·작업지시·첫 공정 외주발주
 ② 진행 중     공정 줄마다 [납품 입력] 납품 수량 / 납품 일자 → 저장(대기)
                    ↓ 입력 작업자: 납품 저장(입고·자재 투입 자동)
                    ↓ 다음 공정이 있으면: 외주발주 + 재공품을 다음 업체로 출고
                 다음 공정 줄에서 ② 반복
```

## 2. 페이지 위치 💡

- 1~11단계와 나눈 **별도 페이지 「생산 관리」**. 기준 자료 등록(1~11)과 매일 하는 일이 섞이지 않게 한다.
- 수입 페이지(v75)와 같은 꼴: 단계 줄의 입구 단추 하나, 안에서 탭 둘(새 생산 · 진행 중), 번호 없는 단계(`page:'생산'`), 점검표에는 넣지 않는다.
- 쓸 수 있는 품목: 폼 1~11단계가 **완료**된 제품·부속만. 앞 단계에 대기·오류가 있으면 고를 수 없다.
- 폰에서 쓰므로 표 대신 **공정 줄 카드**로 보인다.

## 3. 사장님이 넣는 흐름

### ① 새 생산

| 폼 칸 | 값 | 넘어가는 영림원 칸 | 상태 |
|---|---|---|---|
| 품번 | 제품 또는 부속 중 하나 고름(완료 품목 목록) | 500498 품번 | ✅ 제품·부속 모두 저장됨(T-al12h · T-al-p01) |
| 수량 | 숫자 | 500498 생산계획수량 | ✅ |
| 완료일 | 날짜 | 500498 생산계획완료일 | ✅ |
| 공정별 업체 | 공정 줄마다 드롭다운, 처음 값 = 9단계 우선순위 1 업체. 안 바꾸면 그대로 | 넘어가는 칸 **확인 못 함**(아래 4-3) | ✅ 우선순위 1 은 저절로 들어옴 · ⏳ 바꾸는 길 |

- 품번을 고르면 폼이 아는 자료로 공정 줄을 그려 보여 준다.
  - 부속: 공정 순서대로 줄(예: T재단 → T엣지).
  - 제품: 부속 줄을 BOM 수량 × 생산 수량으로 펼치고, 각 부속의 공정 줄과 제품의 T조립 줄(⏳ 조립은 시험 전).
- 업체 드롭다운 = 그 품목·공정에 9단계로 등록된 업체. 입력 때 다른 업체를 영림원이 막지 않지만 계약이 없으면 단가가 안 잡힌다(📖). 목록 밖 업체는 저장 시험 뒤 정한다.
- 시작일 칸은 두지 않는다. 시작일 = 완료일로 저절로 들어오고, 부속 일자는 제품 완료일 3일 앞으로 저절로 들어온다 ✅.

### ② 진행 중 — 납품 입력

공정 줄마다 카드 한 장. 지금 차례인 공정에만 [납품 입력]이 열린다.

| 폼 칸 | 값 | 넘어가는 영림원 칸 | 상태 |
|---|---|---|---|
| 납품 수량 | 처음 값 = 발주 수량 | 501613 납품수량 | ✅ 수량 그대로 저장 · ⏳ 바꿔 저장 |
| 납품 일자 | 처음 값 = 오늘 | 501613 외주납품일 | ✅ 넘어온 값 저장 · ⏳ 바꿔 저장 |

카드에 보이는 것(입력 아님):

```
T-al-p01  1개  완료일 11-13
 ① T재단  업체A  발주됨 → 납품됨 1 ✓  재공품: 업체B로 보냄 ✓
 ② T엣지  업체B  발주됨  [납품 입력]
```

- 영림원 번호(생산계획·작업지시·외주발주·외주납품)는 작업자가 써넣어 카드에서 볼 수 있다.
- 작업이 막히면 카드에 영림원 오류 문구를 그대로 보인다(`agentNote`).

## 4. 영림원 단계별 칸

**값 출처:** 사장님 = 폼 입력 · 폼 = 폼이 가진 자료 · 영림원 = 저절로 들어오거나 앞 화면에서 넘어옴 · 작업자 = 고정 처리.
아래는 시험에서 손댄 칸과 넘어온 칸이다. 필수 칸 중 시험 기록에 값이 없는 것은 「확인 못 함」으로 적었다.

|---|---|---|---|
| 사업단위 | 작업자 | 본사 | 표의 칸. **먼저** 넣지 않으면 「사업단위을(를) 먼저 입력해야 합니다.」 |
| 품번 | 사장님 | 제품 또는 부속 | |
| 품명 | 영림원 | | |
| 공정차수 | 영림원 | 00 | |
| 생산계획수량 | 사장님 | | |
| 생산계획완료일 | 사장님 | | |
| 생산계획시작일 | 영림원 | 완료일과 같음 | |

단추 순서: 저장 → 줄 선택 + `일괄확정처리` → (제품이면) 줄 선택 + `반제품 생산계획 생성` → 저장 → 부속 줄 확정 → 줄 선택 + `작업지시생성`.

- 반제품 줄의 수량(BOM)·일자(완료일 3일 앞)·원천(반제품)은 영림원 ✅. 저장 전에 수량을 고쳐도 되는지는 ⏳.

### 4-2. 작업지시 — `작업지시생성` 결과 ✅

입력 없음. 한 작업지시번호에 공정 줄(공정 순번)로 묶여 나온다. 「작업지시생성 완료되었습니다.」 탭이 몇 분 멈출 수 있다 → 다시 누르지 않는다.

### 4-3. 공정별 업체 변경 ⏳

기본(우선순위 1)일 때는 할 일 없음 ✅. 바꾸는 후보 셋, 모두 저장 시험 전:

| 작업지시입력 501634 | 표의 워크센터 | 📖 |
| 작업지시 워크센터일괄변경 502554 | 워크센터 | 📖 |

501608 줄 `선택` + `외주발주`.

|---|---|---|
| 외주거래처 | 영림원 | 우선순위 1 업체. 폼 값과 대조 |

## 5. 공정 사이 재공품 출고

**시험으로 안 것 ✅**
- 앞 공정 납품이 입고되면 재공품은 **앞 업체 창고**에 있다.
- 다음 공정 소요자재에 재공품 줄이 없으면 재공품을 안 쓴 채 완성이 입고된다. 재공품은 앞 업체에 그대로 남아 재고가 틀어진다.
- 줄이 있으면 다음 공정 외주발주 소요자재에 재공품이 들어오고, 납품 때 **다음 업체 창고에서** 투입된다.
- 재공품 이동은 자재이동 501125 · 이동입력 501096 으로 안 된다(코드도움에 재공품이 없음). **자재출고 500938 → 500940 으로 된다.**
- 영림원 소요자재에 재공품 줄이 있는 부속은 아직 T-al-p01 뿐이다. 나머지는 폼 v77 9단계가 줄을 만들었고(사장님 결정 「폼 자동 + 전체 반영」) 입력 작업자가 500299 에 넣는 차례다. **생산 폼은 이 등록이 끝난 뒤 쓴다.** 공정 3개 품목의 재공품 줄은 시험 전이다.

**폼에서 다루는 방식 💡**
- 사장님이 넣을 칸은 없다. 앞·뒤 공정 업체를 폼이 알기 때문에 작업자가 출고창고·입고창고를 정할 수 있다.
- **언제 처리하느냐**(사장님 결정 1): 앞 공정 납품 문서를 처리할 때 다음 공정 외주발주와 재공품 출고까지 잇는다. 카드에 「재공품: 업체B로 보냄」으로 보인다.
- 공정 하나짜리 부속(백판넬 등)과 마지막 공정 뒤에는 재공품 출고가 없다. 마지막 공정 완성 부속을 조립 업체로 옮기는 일은 ⏳.
- 다음 공정 소요자재에 재공품 줄이 없으면 작업자는 납품을 넣지 말고 오류로 둔다. 재고가 틀어지기 때문이다.

## 6. 저장 문서 꼴 💡

기존처럼 `erp_` 컬렉션, 문서마다 `status`(대기 → 진행중 → 완료 | 오류) · `agentNote` · `createdAt` · `route`. 문서 하나 = 작업자 일감 하나. 이름·필드는 제안이다.

**`erp_prods` — 새 생산 1건**
```js
{
  kind: '제품',            // '제품' | '부속'
  itemNo: 'T-al12h',
  qty: 1,
  dueDate: '2026-11-13',
  rows: [                  // 제품이면 부속마다, 공정마다 한 줄
    { itemNo: 'T-al-p01', qty: 1, seq: 1, proc: 'T재단', wc: '업체A', wcFirst: '업체A', last: false,
      state: '발주됨', orderNo: '', sentNext: false },
    { itemNo: 'T-al-p01', qty: 1, seq: 2, proc: 'T엣지', wc: '업체B', wcFirst: '업체B', last: true,
      state: '대기', orderNo: '', sentNext: false }
  ],
  planNo: '', workNo: ''   // 작업자가 써넣음
}
```
- `wcFirst` = 저장 때의 우선순위 1 업체. `wc` 와 다르면 업체를 바꾼 줄이다.
- `rows` 의 `state` · 번호 칸만 작업자가 고친다. 사장님 값(`qty` · `dueDate` · `wc`)은 고치지 않는다.

**`erp_proddlvs` — 납품 1건**
```js
{
  prodId: '<erp_prods 문서 id>',
  itemNo: 'T-al-p01', seq: 1, proc: 'T재단', wc: '업체A',
  dlvQty: 1,
  dlvDate: '2026-11-10',
  dlvNo: '', inNo: '',     // 작업자가 써넣음
  stock: ''                // 작업자가 501186 대조값을 글로 적음
}
```

`erp-spec.json` · `화면별-요령.md` · `AGENTS.md` 는 폼을 만들 때 함께 고친다.

## 7. 입력 작업자 처리 순서 💡

공통: 저장 전 모든 칸 대조, 저장 뒤 조회 대조(`AGENTS.md` 3-4). 시트 오류는 저장 전에 `MutationObserver` 를 걸어 모은다. `자료가 저장되었습니다` 알림이 없을 때가 많으니 **번호 칸으로** 확인한다. 외주발주서출력·MAIL·전표는 누르지 않는다.

**A. `erp_prods` 대기**
1. 처리 직전 문서가 아직 있고 대기인지 확인 → 진행중.
2. 500498 저장·확정. 제품이면 반제품 생성 후 나온 줄을 폼 `rows` 의 부속·수량과 대조. 다르면 멈추고 오류.
3. 처리할 줄 확정 + 작업지시생성.
4. 501608 → 501617. 외주거래처가 폼 `wc` 와 같은지 대조. 다르면 오류(업체 변경 길은 시험 뒤 적음).
5. 소요자재가져오기 → 저장. 외주처재고가 소요수량보다 적은 줄은 `agentNote` 에 적는다.
6. 번호를 문서에 쓰고 완료.

**B. `erp_proddlvs` 대기**
1. 그 공정이 차례인지(앞 공정 입고완료) 확인. 501614 로 중복 확인.
2. 501610 → 501613 일자·수량 넣고 저장. 부족 문구가 나오면 그대로 오류.
3. 501614 입고완료 · 501621 투입 · 501186 재고 대조.
4. 다음 공정이 있으면 501608 → 501617 → 소요자재가져오기 → 저장. 재공품 줄을 확인(없으면 오류).
5. 500938 → 500940: 재공품 줄 출고창고 = 앞 업체 창고로 저장.
6. 501186 대조: 앞 업체 재공품이 줄고 다음 업체에 생겼는지. 결과를 `stock` 에 쓰고 완료.
