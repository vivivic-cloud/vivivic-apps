## 2. 자료 흐름 (단계)
1. **엑셀** — 사장님이 국내 구매내역 엑셀을 매입현황 「엑셀 새로 불러오기」 로 올림 → `발주역입력_보드매입`.
2. **거래처 연결** — 매입현황 「거래처 연결」 → 「불러오기」 = `_거래처불러오기` 대기 → 입력 작업자가 폼 `erp_vendors` 완료 문서에서 네 칸만 `_영림원거래처` 로 옮김(영림원 안 열음) → 사장님이 고르면 `_거래처연결`.
3. **영림원보내기** — 거래처를 고르고 「영림원보내기」 표(33칸)에 분류·자재번호 등을 채움. 0.3초 뒤 자동저장: `줄`(고친 칸만) + **`보내기`**(줄마다 열쇠 「품목⇥규격」·상태 보냄/등록안함·지문·분류·자재등록 10칸·구매단가등록 14칸·단가이력, 바뀌면 `판` +1).
4. **폼이 받음** — 입력폼 「구매자재 일괄등록」 → 거래처 단추 → `보내기` 를 읽어 단계별 표(넘길 줄·못 넘길 줄과 이유) → **「등록대기」** = 한 트랜잭션으로 분류 → 자재 → 구매단가 문서(`status:대기`, `bd` 칸). 전부 아니면 하나도 안 들어감(v284).
5. **입력 작업자** — 대기 문서를 영림원에 넣음(품목대중소분류정의 502365 → 자재등록 500251 → 구매단가등록 501868) → 문서 `완료`(자재번호·ylwCode) 또는 `오류`(agentNote).
6. **결과 돌아감** — 입력폼 「구매자재 일괄등록」 을 **연 동안** 바뀐 칸만 `발주역입력_영림원폼/{거래처}.결과.{열쇠}.{분류|자재|구매단가}` = `{상태, 이유, 때, (자재번호)}` 로 씀 + `_분류.영림원` 갱신.
7. **매입현황이 보임** — 완료 줄은 「등록완료」 보기로(잠금) · 오류 줄은 빨강 + 고칠 칸 빨간 테 → 고치면 지문이 바뀜 → 4번으로(같은 오류 문서를 고쳐 다시 대기).

## 4. 입력 작업자가 지킬 것
- **`bd` 칸** = 「이 문서는 매입현황 어느 거래처 어느 줄의 몇 판 지문을 받은 것」. 지우거나 고치지 않는다 — 폼이 이것으로 「이미 있음 / 바뀐 줄」 을 가르고 `결과` 를 맞춘다(`bdDocOf`). 손으로 고치면 그 줄이 다시 「새 줄」 로 넘어온다.
- **반쪽 묶음 금지** — 한 줄은 분류 → 자재 → 구매단가 차례. 앞 단계가 오류면 뒤 단계는 영림원에 넣지 말고 「앞 단계 … 오류」 로 오류 처리(11-17 양지데코가 그렇게 함). 문서를 지울 때도 셋을 같이 본다(11-17 17:04 자재만 17건 남은 일).
- **같은 소분류 이름** — 영림원은 품목구분 자재 안에서 소분류 이름이 하나뿐(다른 대·중 밑이라도 거절, 11-17 확인). 폼은 막지 않는다(v278 사장님 「막지 마」) → 넣기 전에 `_분류.영림원` 과 견주고, 걸리면 넣지 말고 오류 + 이유(「이름을 바꿔 주세요」).
- **오류 다시 보내기** — 사장님이 매입현황에서 고치면 지문이 바뀌고, 「등록대기」 를 누르면 같은 오류 문서가 다시 대기가 된다. 새 문서를 따로 만들지 않는다.
- **오류 이유(agentNote)는 공개로 나간다**(`결과.이유`, 300자) — 계정·사업자번호·단가를 쓰지 않는다.
- **불러오기·중복 확인은 폼 데이터로** — 거래처 사본(4-1)·분류 사본은 폼 완료 문서에서 만든다. 영림원은 실제 등록할 때나 사장님이 대조하라 할 때만 연다(11-17 정정).
- **명세서(실제 매입) 넣기 전** 줄마다 `기준` 단가 대조 · 품목은 `연결`(·`더한표기`)로 자재번호를 찾는다(전달 글 6절, 폴더 CLAUDE.md 「지킬 것」).
- **분류는 폼·영림원 어디서도 지우지 않는다.**

## 6. 문제점 · 빠진 점 · 위험 (중요한 순서) — 고칠 거리 목록만
1. **공개 창고에 매입 단가·금액이 그대로 있다.** 규칙상 `public/data` 는 로그인(익명 포함)한 누구나 **읽고 쓴다**. 웹 주소의 Firebase 설정만 있으면 26년 국내 매입 원장 전체(`발주역입력_보드매입`), 품목별 단가(`보내기`·`기준`·`이력`), 영림원 거래처 199곳 이름·상태가 읽힌다. → 단가·금액을 담당자 전용 자리로 옮기거나 규칙을 좁힐지 사장님 결정(규칙 배포는 사장님 「배포하세요」 뒤).
2. **누구나 `보내기` 를 고쳐 쓸 수 있다.** 폼은 지문이 바뀐 줄을 그대로 다시 넘긴다 — 엉뚱한 값이 등록대기로 들어갈 수 있음(입력 작업자는 넣기 전 사장님 확인이 유일한 막이). 위 1번과 같은 해결.
3. **줄 열쇠 = 「품목⇥규격」 글자 그대로.** 엑셀 표기가 띄어쓰기 하나만 바뀌어도 고친 값·`결과`·폼 `bd` 가 그 줄에서 떨어지고 새 줄로 다시 넘어옴(같은 자재번호 → 「자재번호 겹침」). 해피코 「1T*18MM용」·「1T * 18mm용」 도 따로. 규격 칸이 비고 품목에 규격이 붙은 줄도 있음(「유백색무광 0.6*21*100⇥」).
4. **결과는 입력폼 메뉴를 열어 둔 동안만 돌아간다.** 아무도 「구매자재 일괄등록」 을 안 열면 매입현황 색이 낡는다(지금은 양지데코만 있어 맞음).
5. **오류 이유가 마우스(title)에만 보인다**(v1.18.1 사장님 「설명 글 0」). 사장님은 폰 — 폰은 마우스가 없어 이유를 못 본다. 빨간 칸만 보고 고쳐야 함.
6. **분류 목록이 세 곳**: 폼 `erp_classes`(로그인 때 직접 읽음, v1.20.0) · 공개 사본 `_분류.영림원` · 매입현황 `_분류.기억`(오타 「0,15t」 이 남아 드롭목록에 뜸). 입력폼 로그인 공유는 실제로 확인 못 함(비밀번호를 못 넣어서).
7. **같은 소분류 이름을 폼이 안 막는다**(v278). 매입현황이 빨강으로만 알림 — 그대로 「등록대기」 하면 영림원에서 오류가 되어 돌아온다(양지 사례). 엘데코 21·현준 3·재하 1 줄이 같은 꼴로 대기 중.
8. **두 곳에서 같은 칸을 고치면 늦게 저장한 쪽이 이긴다.** 옛 판 창이 `보내기`·`기준` 을 지운 일이 있었다(11-17 엘데코). 판 숫자도 거래처마다 들쭉날쭉(엘데코 64 · 현진 2).
9. **구매단가 = 마지막 단가 하나 · 적용시작일 2026-01-01(임시).** 단가이력 여러 줄·지난 날짜·단가 0원을 영림원이 받는지 확인 못 함. 현진·현준은 「별도 단가」 기준.
10. **해피코는 아직 넣을 수 없다** — 단가·적용시작일 빈칸, 통화 CNY·외자·직수입 임시, 거래처 연결 미확정, 분류·자재번호 빈칸.
11. **거래처 자동 맞춤은 이름 비교**(괄호·(주)·띄어쓰기 뺌, T 거래처 뺌). 「현준보드(서광)」 → 「현준보드」 처럼 이름이 달라 사람 확인이 필요. `_영림원거래처` 에 폐업 11곳도 섞여 있음.
12. **시험 자국** `발주역입력_영림원거래처` 7문서(가짜 「시험거래처」 포함)가 남아 있다(v1.5.0, 안 씀). 지울지 사장님 확인.
13. **매입현황 `기준`·`연결`·`이력`·`보내기` 가 같은 값을 여러 꼴로 저장**(문서당 수십 KB). 겹친 저장이 「저장중 오래」 의 원인이었던 적 있음(v1.14.0 에서 줄임).
14. **실제 매입(명세서 → 발주·입고) 역입력은 아직 없다** — 지금은 기준정보(분류·자재·구매단가)까지만. 다음 단계는 사장님이 정함.
