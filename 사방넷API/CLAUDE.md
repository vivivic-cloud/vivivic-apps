# 사방넷 API 규정 정리

확인한 날: 2026-11-27 (Claude 작업자, Chrome 으로 실제 화면을 열어 확인)
「확인 안 됨」 = 화면에서 직접 보지 못한 것. 추측으로 채우지 않는다.

## 결론

- **사방넷 API 있음.** 유료 부가서비스이다 (사방넷 사용료에 포함 안 됨).
- 공식 개발 문서는 **사방넷 연동 개발자센터** `https://developer.sabangnet.co.kr` 에 있다 (운영사 ㈜다우기술).
- 개발자센터는 **초대 받은 사람만 가입**할 수 있다. 명세(API 레퍼런스·워크플로우·FAQ)는 로그인해야 보인다.
  사방넷 쇼핑몰관리 아이디와 개발자센터 아이디는 따로이다.

## 신청 → 사용 순서 (개발자센터 「가이드」 화면 기준)

1. 사방넷 홈페이지 `API 서비스` 화면에서 「API 서비스 상담하기」로 신청한다.
2. 사방넷 **마이페이지 > 연동관리** 에서 앱 연동을 맡을 개발자에게 초대 메일을 보낸다.
3. 초대 메일 링크로 개발자센터에 가입한다. 첫 가입자 = 오너(Owner). 오너가 팀원(멤버)을 초대한다.
4. 개발자센터 상단 메뉴에 [앱] 또는 [솔루션] 환경이 나온다.
   - 앱(App): 우리 회사 내부 시스템(ERP·WMS 등)과 연동. **심사 없이** 바로 라이브 전환.
   - 솔루션(Solution): 다른 사방넷 고객사에 서비스하는 것. 사방넷 심사 필수.
5. 프로젝트를 만들고 **Client ID / Client Secret** 을 받는다.
6. API 를 부르는 서버의 **IP 를 화이트리스트(허용 IP)** 에 등록한다.
7. **OAuth 2.0** 으로 토큰을 받아 호출한다.
8. 샌드박스(고정 응답, 구조·인증 흐름 확인용)에서 시험 → 라이브 전환.

## 제공 기능 (개발자센터 워크플로우 4가지)

| 워크플로우 | 내용 (화면 설명 요약) |
|---|---|
| 상품 | 카테고리 등 사전 세팅, 상품 등록·수정, 쇼핑몰 전송 |
| 주문 | 여러 쇼핑몰 신규 주문 수집 → ERP/WMS 연동 → 운송장 번호 전송 |
| 클레임 | 취소·반품·교환 수집·처리, 반품/교환 송장 처리 |
| 문의사항 | 쇼핑몰 상품 문의(Q&A) 수집, 답변 전송 |

홈페이지 API 서비스 화면 문구: 「상품, 주문, 재고정보까지」 연동.

## 호출 방식

- 인증: OAuth 2.0 (Client ID + Client Secret → 토큰). 허용 IP 등록 필수. — 공식 가이드에서 확인.
- 아래는 **공식 문서가 아닌** 남의 공개 저장소(pharmsville-a11y/pharmsville_dashboard README)에 적힌 것. 참고만:
  - 운영 주소 `https://api.sabangnet.co.kr`, 주문 조회 `POST /v3/sb/order` (API 3.0), JSON 으로 보임.
  - 설정 값 이름: CLIENT_TYPE(SB_APP), CLIENT_CD, SECRET, SVC_ACNT_ID.
  - 주문 조회 때 `updateOrderStsYn=N` 이면 신규주문 상태를 바꾸지 않는다고 적혀 있음.
- 옛 방식(XML): `r200.sabangnet.co.kr/RTL_API/guide/...` 라는 옛 가이드 주소가 검색에 나오고,
  SEND_COMPAYNY_ID · SEND_AUTH_KEY · SEND_DATE(YYYYMMDD) 머리 항목, `xml_url` 로 XML 주소를 넘기는 방식이 보인다.
  2026-11-27 에 열어 보면 403 Forbidden — 지금 쓰는지 **확인 안 됨**.
- 외부 서비스(CJ대한통운·스마트십·채널톡·품고 등) 안내문은 **마이페이지 > 서비스 관리 > 연동키 관리** 에서 연동키를 받는다고 쓴다.
  옛 XML 방식 연동키로 보이며, 새 개발자센터(Client ID/Secret)와의 관계는 **확인 안 됨**.

## 이용약관 핵심 (개발자센터 이용약관 v1.0, https://developer.sabangnet.co.kr/terms)

- 서비스 = 회사가 주는 **토큰**으로 연동. 앱 = 고객사 자체 시스템과 단독 연동, 솔루션 = 파트너사 ERP/WMS 를 여러 사방넷 고객에 제공.
- 이용요금 **선불**. 선납 전에는 유료 서비스 시작 불가 (5조). 고객사 요금은 사방넷 홈페이지 게재 금액 (17조).
- 기간·범위·기능·요금은 **별도 서비스 약정서**로 정함 (14조).
- 회사는 **API 호출 트래픽 제어(Rate Limit 등)** 를 할 수 있음 (16조). 숫자는 약관에 없음.
- 이용 제한 사유: 대량 트래픽 발생, 앱 권한을 외부 유출·영리 솔루션으로 악용, 재판매·제3자 임대 (12·16조).
- 회사는 정보를 「호출에 따라 송신할 뿐」 → **중복 호출 등 오류는 회사 책임 없음** (12조). 중복 처리는 우리 쪽이 막아야 함.
- 세부 정책은 개발자센터 화면에 게시, 회원이 지켜야 함 (12조).
- 사방넷 이용계약이 끝나면 API 계약도 해지 (19조). 환불·장애 보상은 사방넷 이용약관 20조·27조 준용.
- 보관기간: 웹훅 발송 이력 30일(→ **웹훅 있음**), 통계·활동 이력 24개월, 접속 로그 90일, 초대 메일 180일, 코드/시크릿 키는 앱 삭제 때 파기 (21조).
- 12개월 미사용 → 휴면 처리 가능 (16조).

  「개발자센터 초대」는 메일을 보내므로 누르지 않았다.

  왼쪽 **서비스관리** 하위 = 사방넷공지사항, 온라인문의, 사방넷업무연락, 사방넷접속현황, 사용계약관리, 유료부가서비스신청.
  외부 안내문의 「서비스 관리 > 연동키 관리」 메뉴는 **이 계정 화면에 없음** (API 미가입이라 안 보이는지는 확인 안 됨).
  화면 안 글에 「연동」이 들어간 메뉴는 「사방넷택배사연동관리」뿐.
- 개발자센터(developer.sabangnet.co.kr)는 사방넷 로그인과 별개 — 사방넷에 로그인해도 개발자센터는 로그인 화면이 나온다.

## 판매링크(쇼핑몰 판매주소) 찾는 길 — 찾음 (2026-11-27)

**주문관리 > 품번코드매핑관리** (`sbadmin07.sabangnet.co.kr/#/order/product-code-mapping`)
- 사방넷 품번코드 ↔ 쇼핑몰 상품코드 연결표. 열:
  No. | 쇼핑몰 | 쇼핑몰ID | 부가정보코드 | 카테고리코드 | 품번코드 | 쇼핑몰[상품코드 / 미리보기 / 매핑수정] | 상품명 | 판매가 | 매핑등록일 | 생성구분 | 등록자
- 「미리보기」 칸의 **MALL** 링크 = 그 쇼핑몰의 실제 판매 페이지. 본 예:
  - 오늘의집(쇼핑몰ID ingfceo@naver.com): 품번 103027 → 상품코드 4203062 → `ohou.se/productions/4203062`
  - 카페24(쇼핑몰ID inggagu): 품번 103024 → 상품코드 6622 → `inggagu.cafe24.com/product/detail.html` (상품번호는 뒤 조건값)
  - 스마트스토어(쇼핑몰ID faith227): 품번 103045 → 상품코드 13739736662 → `smartstore.naver.com/inggagu/products/13739736662`
    (쇼핑몰 선택 = 스마트스토어, 3개월 조회 53건. MALL 은 href 없이 눌러야 새 창으로 열림)
  → 판매링크 = 쇼핑몰별 주소 틀 + 「상품코드」. 상품코드만 있으면 주소를 만들 수 있다.
- 조회 조건: 생성일자(매핑등록일, 단추 오늘·1주일·당월·1개월·3개월), 쇼핑몰 선택, 쇼핑몰 ID, 매입처, 카테고리,
  생성구분(전체·연동생성·주문생성·임의생성), 검색항목. 3개월(2026-08-27~11-27) 조회 = **532건**.

## 확인 안 됨

- API 레퍼런스 세부 (엔드포인트 목록, 요청·응답 항목, 재고 API 유무) — 개발자센터 초대·가입 필요
- 호출 제한(분당/일당 횟수), 토큰 유효시간
- 이용약관 중 API 이용 조건 세부
- 「연동키 관리」 메뉴가 API 가입 뒤에 생기는지
- 옛 XML(RTL_API) 방식이 아직 쓰이는지
